# Nirai 詳細設計 01：通信プロトコル

Product Goalは [Nirai_基本設計.md](../Nirai_基本設計.md)、設計判断ルールは [Nirai_設計ガバナンス.md](../Nirai_設計ガバナンス.md)、全体像は [00_全体構成.md](00_全体構成.md) を正とする。

## 概要

通信プロトコルとは、CoreとWorldがWebSocketでやりとりするメッセージの取り決めである。

- 前提
  - CoreがサーバーでWorldがクライアント
  - 接続先：`ws://127.0.0.1:8765`（ポートはconfig.toml）
  - メッセージは全てJSONテキスト1件＝1メッセージ
  - 知らない`type`を受け取った側は、WARNログを残して無視する（落ちない）
  - 会話UIはWorld内にある。Master入力と会話ログ表示も、この接続のうえで運ぶ

## メッセージ共通形式

| フィールド | 型 | 必須 | 説明 |
|-----------|----|------|------|
| type | string | ○ | メッセージ種別 |
| id | string | — | 応答が必要なメッセージの相関ID（`action`と`action_done`の対応付け等） |
| ts | string | ○ | 送信時刻（ISO 8601） |
| payload | object | ○ | 種別ごとの中身（空でも`{}`） |

## 接続開始

1. Coreは起動ごとにWorld専用の高強度Secretを生成し、Coreが子Processとして起動するElectronへだけ実行時情報として渡す。永続設定・Git管理File・通常Logへ保存しない
2. Worldが接続し、最初に`hello`を送る
   - `payload: { "role": "world", "secret": "<起動時Secret>", "protocol": { "version": 1, "runtime_id": "electron-threejs", "capabilities": ["semantic-actions-v1", ...] } }`
   - `protocol.version`はCore / World Contractの互換世代。Currentは**1**。Secret認証後にCoreがVersionを厳密確認し、欠落・型不正・非互換Versionはclose code 4004で拒否する。古いWorldを「たぶん動く」として黙って接続しない
   - `runtime_id`は実装識別子でありResident Identityではない。標準Worldは`electron-threejs`、将来のUE Runtimeは別IDを使う
   - `capabilities`はそのWorldが実装する意味機能の一意なstring配列。Current標準Worldは`semantic-actions-v1 / conversation-ui-v1 / agent-runtime-ui-v1 / resident-roster-v1 / holo-addon-v1`を広告する。Current v1では接続許可自体をCapability充足へ依存させず、将来のFeature routing / Spike判定用に交換する
   - CoreはSecret一致とProtocol整合を確認するまでWorld接続として登録せず、Snapshot・Session・Agent状態等も返さない
   - Secret不一致または欠落は接続時点で拒否し、現在の正規Worldを置換しない。Protocol情報もSecret認証前の相手へ判断材料として返さない
3. Coreは認証・Protocol確認成功後に`hello_ack`を返す
   - `payload.protocol: { "version": 1, "runtime_id": "nirai-core", "capabilities": [...] }`を必須とし、WorldもVersion一致を確認してから`connected`へ遷移する
   - その他のpayloadは`{ "residents": [住人の初期情報の配列], "locations": [Location定義の配列], "time_of_day": "day", "settings": { "audio_volume": 100 }, "active_session": "S-..." }`
   - `residents`配列順は`[residents].enabled`の順序と一致させ、右Resident Sidebar表示順と複数Resident初期配置順の初期同期に使う
   - Current Standard World v1の住人初期情報：`{ "name": "…", "brain": "codex", "brain_model": "gpt-5.6-sol", "brain_reasoning_effort": "high", "avatar": "…", "location": "…", "tts": { "enabled": true, "provider": "voicevox", "speaker_uuid": "…", "style_id": 3, "speed": 1.0, "pitch": 0.0, "intonation": 1.0 } }`。`tts`は既存Electron/Three.js Standard Worldを維持するためのLegacy v1互換transportであり、Private DNA World / Protocol v2の共通Voice正本ではない。`brain_model` / `brain_reasoning_effort`等の未設定項目は`null`を許容する。`avatar`はCoreにとって`avatars/`配下のPresentation asset参照であり、拡張子やRuntime形式をCore Contractへ固定しない。標準WorldはVRM参照を使う
   - Resident初期情報にはCurrent追加契約として`role`、`usage_budget`、`availability`も含める。`role`は`resident / executor / integrated_auditor / commander`のいずれか。`usage_budget`はProvider固有値を共通化したSnapshotで、複数window、使用率、残量、reset、stale状態を持てる。取得不能時は`null`またはstaleなlast-knownを返し、`availability=unknown`へ縮退する
   - Location定義：`{ "id": "center", "name_ja": "光の柱" }`
     - Coreは意味的なLocation IDと表示名だけを持つ
     - 実座標・移動経路・接地はWorldの責務。初期は複雑なNavMeshを前提にしない
     - Worldは受け取るまで既定配置で描く（Coreがいなくても風景が出る）
4. 認証済みの同じroleの二重接続が来た場合だけ、Coreは古い方を切断して新しい方を採用する

## Core → World

| type | payload | 説明 |
|------|---------|------|
| spawn_resident | `{name, avatar, location, tts?}` | 住人の身体を出現させる。`tts`はResident固有の音声設定 |
| remove_resident | `{name}` | 身体を消す（住人が「留守」のとき） |
| action | `{name, command, args}` | 行動コマンドの実行指示。idを付ける |
| bubble | `{name, text_short, text_full?, duration_sec, tts?, request_id?}` | 独立した**公開World発話**の表示指示。M1のMaster会話では`resident_say`等のPublic World presentation対象`chat_append`からWorldが同等の頭上吹き出しを派生してよい。`resident_whisper`はPrivate Channelのため頭上吹き出し・TTSへ派生させない。M2以降の自律発話・短文化表示等で独立指示が必要な場合に使う |
| time_of_day | `{phase}` | 時間帯の切り替え（下記） |
| pause | `{}` | 省エネモード開始（描画負荷を下げる） |
| resume | `{}` | 省エネモード解除 |
| shutdown | `{}` | 終了指示 |
| chat_append | `{entry}` | 会話ログ1件の追加（会話UI用。下記の会話ログ形式） |
| history_response | `{session_id, entries, next_before}` | 選択中チャットセッションのログ配列。`next_before`は古い履歴が残る場合だけ次回`history_request.before`へそのまま返す不透明Cursor、最古到達時は`null` |
| chat_session_list | `{sessions, active_session}` | 左サイドバー用。`sessions`は`{id,title,created_at,updated_at}`の配列 |
| response_state | `{active, request_id?, session_id?}` | Master発話1回へのAI応答が進行中か。送信ボタンの↑/停止表示に使う |
| brain_provider_list | `{providers}` | AI連携UI用。各Providerの`name, available, connected, configuration_mode, models, default_model, default_reasoning_effort, custom_model_allowed`を返す。M4以降は任意の`capabilities`を追加し、少なくとも`conversation / agent_work`をboolで持たせ、11のApproval / Question / Plan等の対応可否も追加できる。M4実装前は`capabilities`省略を許容する。Codexの`models`は`{id,display_name,default_reasoning_effort,reasoning_efforts:[{id,display_name}]}`を返し、他Providerは不要なReasoning項目を省略できる |
| resident_settings_updated | `{resident}` / 削除時のみ`{resident:null, deleted_name}` | Resident作成・Brain/Avatar/VOICE変更・削除後の設定UI同期。`resident`にはRole / Usage / Availabilityも含める。削除時は削除済みResidentの設定Objectを捏造せず`deleted_name`で一覧・Worldから除去する |
| resident_roster_updated | `{residents}` | Resident並べ替え・Role変更・Usage更新後の一覧同期。配列順は`[residents].enabled`と一致し、Worldの初期配置順として扱う |
| status | `{residents, ecomode, budgets}` | 状態表示用（住人の現在Location・状態、省エネ中か、予算消費） |
| world_observation_request | `{reason?}` | M3以降。Coreが最新の意味的World Observationを要求する。通常はCacheを使い、未取得または古い場合だけ要求してよい |
| task_update | `{task_id, phase, text, agent_session_id?, working_dir?, queue_position?, target?, interruption_reason?, partial_work_path?}` | タスクの高水準進捗。phase：queued / consulting / assigned / running / done / failed / cancelled / interrupted。`queued`では`queue_position`、named target指定時は`target`を付与できる。Provider利用上限による中断では`interruption_reason=provider_quota_exhausted|provider_rate_limit`を付け、途中成果を隔離保存した場合は`partial_work_path`も付ける。CommandやDiff等の詳細は`agent_event`へ分離する |
| agent_event | `{event}` | M4。11で定義するNirai共通Agent Event 1件。**World-managed Agent Sessionだけ**を対象とし、Provider固有Protocol名や生JSON、Holo-owned SessionのEventをWorldへ漏らさない |
| agent_session_snapshot | `{agent_session_id, task_id, provider, state, events, pending_input?, recovery_options?, interruption_reason?, partial_work_path?}` | M4。World-managed Agent Sessionの再接続・詳細画面再表示用Snapshot。`pending_input`は`waiting_for_master`中の未解決Approval / Question / Plan等がある場合だけ含む。Core再起動で`interrupted`へ遷移する時は旧pending inputを破棄し、`interrupted` Snapshotへは再提示しない。Provider利用上限で安全停止した場合は`interruption_reason`と、存在する場合のみ`partial_work_path`を保持し、Core再起動由来のInterruptedとUIで区別する。`interrupted`では`rerun / abandon`を基本に、保存済みProvider native IDがありAdapterが`crash_resume`を明示する場合だけ`resume`を追加して`recovery_options`へ返す。Holo-owned SessionはこのWorld Snapshotへ含めない |
| agent_session_recovery_result | `{source_agent_session_id, agent_session_id, action}` | World-managedなsourceへの`agent_session_recover`受付結果。resume / rerunでは新Session ID、abandonでは元Session IDを返し、続けて最新Snapshotを送る。Holo-owned / 非World-managed sourceにはこの結果自体を送らない |
| holo_auto_resume | `{kind:"review", task_id, agent_session_id, reason}` | Holo-ownedな旧互換Supervisor Review（`HR-*`）が`done / failed / cancelled / interrupted`へ到達したことをHolo Addonへ継続通知する専用Event。汎用Agent UIへReview Eventを公開するものではない。Coreは送信だけで通知済みにせず、World/Holo Hostのdurable受領ACKまで未通知として保持し、再接続時に再送する |
| notice | `{level, text}` | Masterへの通知。Worldは画面へ表示し、Resident作成・AI変更等の設定操作が応答待ちならpendingを解除して再操作可能にする |

- time_of_dayのphase（Coreが実時刻から決めてWorldへ送る）
  - morning：5時〜9時
  - day：9時〜16時
  - evening：16時〜19時
  - night：19時〜5時

### 行動コマンド語彙 v1（正はこの表。03・04はここを参照する）

| command | args | 意味 |
|---------|------|------|
| move | `{location}` | Locationへ移動する。Worldは2026-08-26変更前の旧Move Bの演技を標準として使う |
| approach | `{target}` | M2以降。指定Residentへ会話距離を残して近づく。意味Locationが同一でも対象Residentの現在Presentation位置をWorld側で解決し、完全重複は避ける |
| gather | `{participants:[Resident名...]}` | Group Conversation用。2〜10人をscreen-safe範囲内の会話Formationへ集める。3人は三角形、4人以上も同じ輪状計算を使い、人数別の専用座標表は持たない |
| wander | `{}` | 現在地付近をゆっくり漂う。自然移動用の水中遊泳Primitiveを使う |
| stand | `{}` | LOCOMOTIONのIdleで立ち待機へ戻る |
| afk | `{}` | IDLE / AFK Animationで休憩する |
| expression | `{kind}` | 意味的な表情。Emotionはneutral / happy / angry / sad / relaxed / surprised / awkward / doubt、ほかblink / aa / ih / ou / ee / oh等の口形・瞬きを扱う |
| face | `{target}` | 対象（住人名または"master"＝画面手前）の方を向く |
| work | `{}` | 作業状態へ遷移する。視覚表現はWorldが決める |
| sleep | `{}` | SLEEP Animationで眠る |

- 語彙の追加はこの表への追記で行い、既存コマンドの意味・引数は変えない（後方互換）
- Worldは未知のcommandを受けたら`stand`扱いにしてWARNログ
- `expression`はVRM Runtime経由でAvatarのExpressionへ適用する。CoreはAvatar固有Expression名を送らず意味名だけを送る。WorldはVRM0の`joy / sorrow / fun`やAvatar固有の`happy01`等を意味名へ解決し、同一Emotionに複数候補がある場合はEmotionへ入る時に候補から選択する。頭上アイコンにはしない
- 発話の正本はテキスト。TTSはWorld側の任意表現である。Mute中でもPublic World presentation対象の`bubble`と会話`chat_append`は通常通り表示・保存するが、`resident_whisper`はMute状態に関係なくPrivate会話UIだけへ表示し、World `bubble` / TTSへ流さない
- `text_full`がある場合、WorldはTTS入力に必ず全文を使い、`text_short`だけを読み上げない

※メモ：`gesture`と`talk`は対応Animation Asset追加後に語彙へ追加する。`sit / stretch / think`は追加予定に含めない。

## World → Core

| type | payload | 説明 |
|------|---------|------|
| hello | `{role:"world", secret, protocol:{version,runtime_id,capabilities}}` | 接続開始。`secret`はCore起動ごとのWorld専用Secret。Current Protocol versionは1。認証成功前はSnapshotや権限Messageを扱わず、認証後もVersion不一致ならWorld登録前に拒否する |
| action_done | `{name, ok, reason?}` | 行動完了。指示のidを引き継ぐ。失敗時はok=false、reasonに理由 |
| display_state | `{visible, focused, minimized}` | 表示・フォーカス・最小化の状態通知。省エネ判定に使う |
| world_observation | `{captured_at, master_focus, environment, residents}` | M3以降。現在Worldの意味的Snapshot。生のThree.js座標・Camera行列・Shader値は送らない |
| master_say | `{text, request_id}` | 現在選択中チャットセッションへSayを送信。`request_id`はMaster発話1回のID |
| master_whisper | `{to, text, request_id}` | 現在選択中チャットセッションでWhisperを送信（toは住人名） |
| cancel_response | `{request_id}` | 指定Master発話に対する全Residentの応答処理を停止する。実行中Taskは停止しない |
| chat_session_list_request | `{}` | 左Sidebar用のセッション一覧を要求 |
| chat_session_create | `{}` | 新しいチャットを作成して選択する。World / Private Memoryは消さない |
| chat_session_select | `{session_id}` | 過去セッションを選択し、会話を再開可能にする |
| chat_session_delete | `{session_id}` | UI上の履歴を削除する。World Memoryは削除しない |
| world_memory_forget_session | `{session_id}` | 指定UIセッション由来のWorld Memoryについて、Public Raw Durable Source / Structured Continuity / Derived Retrieval対象を整合して削除・再構成し、同じUIチャット履歴も削除する。旧Episode互換Viewだけを削除してRawを残す状態をForget成功と扱わない。Private Memoryは削除しない |
| task_request | `{text, target?, resident?}` | タスク依頼。`resident`ありはDirect Taskとして指名Residentへ割り当て、`resident`なしはRole / Usage Budgetに基づく自動Routingを行う。通常自動候補は`executor`、該当者がいない場合のみ実行可能な`commander`へfallbackし、`integrated_auditor`を通常Taskへ自動選出しない。旧Council volunteer判定は通常Taskの担当決定に使わない。WorldではResident Focus中に`会話 / 仕事`を切り替え、`仕事`時の自然文をFocus Resident付きで送る。`/task`は互換Shortcutとして残し、`/task @対象フォルダ名 依頼文`では`target`へ対象名を分離する。Coreは対象を内部`runtime/workspace`を除く実在`tasks.allowed_dirs` Root basenameとして再検証する |
| agent_approval_response | `{agent_session_id, request_id, decision}` | M4。World-managed Agent Sessionが現在`waiting_for_master`で保持するApprovalへのMaster回答。`decision`はNirai共通値`approve_once / approve_session / reject / cancel`のうち、その要求で提示されたものだけを送る。`interrupted / cancelling / terminal` Sessionや解決済みrequestへは適用しない |
| agent_question_response | `{agent_session_id, request_id, answers}` | M4。World-managed Agent Sessionが現在`waiting_for_master`で保持する質問への回答。`answers`はQuestion IDごとの選択値または自由入力を持つ構造化Object。`interrupted / cancelling / terminal` Sessionや解決済みrequestへは適用しない |
| agent_plan_response | `{agent_session_id, request_id, decision, reason?}` | M4。World-managed Agent Sessionが現在`waiting_for_master`で保持するPlanへの回答。`decision`は`approve / revise / cancel`。`revise`時は`reason`へ修正要求を入れられる。`interrupted / cancelling / terminal` Sessionや解決済みrequestへは適用しない |
| agent_session_cancel | `{agent_session_id}` | M4。World-managedな実作業Agent Sessionを停止する。会話用`cancel_response`とは別物。Holo-owned Session IDを指定しても受理しない |
| agent_session_recover | `{agent_session_id, action}` | Core再起動等で`interrupted`になったWorld-managed SessionへのMaster明示操作。Coreはsourceがdurable `origin_chat_session_id`を持つWorld-managed Sessionであることを最初に検証し、Holo-owned / 非World-managed sourceは受理せず状態変更しない。`action`はSnapshotで実際に提示された値だけを受理する。`resume`はProvider native IDがありAdapterが`crash_resume`を明示したSessionでのみ提示・受理し、自動Write resumeは禁止。`resume / rerun / abandon`はすべてsource Sessionごとのatomic one-shot操作とし、最初のRecovery受理時にsourceをdurableに消費してから副作用へ進む。`resume / rerun`で作るchildはsourceの`task_id` / `origin_chat_session_id`とWorld-managed ownershipを引き継いでからWorldへ公開し、同じsourceへの逐次・並行Recoveryを拒否する。`abandon`はchildを作らずsourceを`cancelled`へdurable確定する |
| agent_session_snapshot_request | `{agent_session_id}` | M4。再接続・再表示時にWorld-managed Agent Sessionの復元Snapshotを要求する。CoreはHolo-owned / 非World-managed Session IDを拒否し、Snapshot / Event / `pending_input`を返さない |
| holo_auto_resume_ack | `{kind:"review", task_id, agent_session_id}` | Rendererのdurable OutboxからHolo HostへReview Auto Resumeが受理済み、または同じTriggerが既にdurable処理済みと確認できた時だけ返す。CoreはこのACKをReview terminal通知のcommit pointとして`result_notified=true`へ進める。Approval / Decisionではなく、所有済み`HR-*` Reviewの配送確認だけを行う |
| history_request | `{session_id, before?, limit}` | 指定セッションのログ追加読み込み（既定limit=50）。`before`は`history_response.next_before`で受け取った不透明Cursorだけを使用し、時刻をCursorとして生成しない |
| pause_toggle | `{}` | 省エネモードの手動切り替え |
| audio_volume_changed | `{volume}` | 全体音量0〜100。0はMute。Coreは値を保存し、会話内容には影響させない |
| brain_provider_list_request | `{}` | AI連携Provider一覧と状態を要求 |
| usage_budget_refresh | `{}` | Residentに紐づく対応Providerの利用枠を明示再取得する。取得失敗時はstaleなlast-knownまたはUNKNOWNへ縮退し、Task実行可否を推測で捏造しない |
| resident_create | `{name, provider, model?, reasoning_effort?, role?}` | 名前とAI Providerを指定してResidentを新規作成する。`provider`は必須、`role`省略時は`resident`。`model`省略時はProvider既定Modelを使う。`reasoning_effort`はCodexのみ任意指定。実行系Roleは選択Brain/ModelがAgent Work可能な場合だけ受理する |
| resident_set_brain | `{name, provider, model?, reasoning_effort?}` | 既存ResidentのBrain Providerと任意Modelを変更する。`model` / `reasoning_effort`省略・空欄はProvider既定。現在Roleの実行Capabilityを変更先AIが満たさない場合は保存せず拒否する。Core保存成功後に`resident_settings_updated`で同期する |
| resident_set_role | `{name, role}` | `resident / executor / integrated_auditor / commander`を変更する。CoreはRole Capabilityを再検証し、`commander`指定時は既存Commanderを安全に`executor`または`resident`へ降格して最大1名を維持する。保存成功後に`resident_roster_updated`で一覧を返す |
| resident_reorder | `{names:[Resident名...]}` | 現在有効なResidentを同一集合のまま並べ替える。重複・欠落・未知名は拒否する。保存成功後に`resident_roster_updated`で確定順を返す |
| resident_disconnect_brain | `{name}` | ResidentとBrain Providerの割当だけを解除する |
| resident_set_avatar | `{name, avatar_path}` | `avatars\\`配下のPresentation asset参照を設定する。CoreはRoot逸脱と実在を検証するが形式をVRMへ固定しない。標準Worldの選択UIはVRMを供給する |
| resident_set_tts | `{name, tts}` | Current Standard World v1互換。旧TTSのSpeaker / Style / 話速 / 音高 / 抑揚等を保存する。Private DNA World / Protocol v2のProvider非依存Voice設定は未実装であり、この`tts` Schemaを新Architectureの正本へ昇格させない |
| resident_delete | `{name, confirm}` | Character完全削除。`confirm`が`Delete`完全一致でない場合は拒否する |
| shutdown_request | `{}` | Nirai全体の終了要求 |
| error | `{message}` | World内部エラーの報告 |

**Agent ownership境界:** Core⇔Worldの汎用Agent面でWorld-managedとみなす唯一のallowlist条件は、durable `origin_chat_session_id`を持つ公開Task由来Agent Sessionであることとする。World→Coreの`agent_approval_response / agent_question_response / agent_plan_response / agent_session_cancel / agent_session_recover / agent_session_snapshot_request`は、対象Sessionがこの条件を満たすことを状態判定や副作用より前に検証し、満たさないSession IDはすべて受理しない。拒否時はAgent状態・pending request・Recovery消費状態を変更せず、`agent_event / agent_session_snapshot / agent_session_recovery_result / pending_input`もWorldへ返さない。Core→Worldの`agent_event / agent_session_snapshot / agent_session_recovery_result`もWorld-managed Sessionだけを送る。Recoveryで作るchildはsource自体がWorld-managedである場合に限り、sourceの`origin_chat_session_id`とownershipをdurableに引き継いでからWorldへ公開する。Holo Supervisor Review（`HR-*`、origin Chatなし）とHolo Provider Conversationの短命child Agent Session（`conversation_id`所有、origin Chatなし）はHolo-ownedであり、このWorld汎用面へ接続しない。Holo-owned Sessionの観測・停止は12で定義する認可済みHolo Local / Conversation経路だけを使う。例外的に、所有Diveへ監督を戻すための`holo_auto_resume`とその配送確認`holo_auto_resume_ack`だけはHolo-owned `HR-*` Reviewのterminal継続通知としてWorld transportを通過できるが、Agent Event / SnapshotやApproval権限を公開するものではない。

### World Observation（M3以降）

Residentが現在のWorldを「設定として知る」のではなく「観測して判断する」ための意味的Snapshot。

例：

```json
{
  "captured_at": "2026-08-29T01:00:00+09:00",
  "master_focus": "Lapan",
  "environment": {
    "light": "bright",
    "water_surface": "calm",
    "visibility": "clear",
    "caustics": "normal"
  },
  "residents": [
    {
      "name": "Lapan",
      "location": "center",
      "state": "stand",
      "nearby": ["Codex"]
    }
  ]
}
```

規則：

- Worldは描画の生値ではなく、会話・行動に意味のある離散化済み情報だけを送る
- 正確な`x/y/z`、Camera Matrix、Shader Uniform、FPS等をBrain Context用Snapshotへ常時載せない
- `master_focus`は現在World上でMasterがFocusしているResident名。Focusなしは`null`
- `environment`は実際にWorldが現在描画している状態から生成する。固定Promptの世界説明をそのまま複製した値にしない
- `residents`は身体がWorldに存在するResidentの現在Location・意味状態・近接関係を表す。近接は必要なら`near / same_area / far`等へ拡張してよい
- 毎Frame送信は禁止。意味のある状態変化時に更新し、Coreは最新SnapshotをCacheする
- Brain呼び出し時にSnapshotが未取得または古い場合、Coreは`world_observation_request`で更新を要求してよい
- World未接続・Snapshot取得不能時は「観測なし」として扱い、推測で現在状態を補わない

## IDの使い分け

- Message共通`id`：WebSocket Message 1件の相関ID
- `session` / `session_id`：UI上のチャットセッションID
- `request_id`：Master発話1回と、その発話に対する全Resident応答を束ねるID。Rendererが`crypto.randomUUID()`で生成する
- `invocation_id`：Core内部のBrain 1回呼び出しID。World Protocolへ常時露出させない
- `task_id`：Nirai上の仕事1件のID
- `agent_session_id`：Task担当Agent Providerとの実作業Session ID。再実行・Provider交代では同じTaskに複数Sessionを持ち得る
- `event_id`：Agent Session内の構造化Agent Event 1件の一意ID

会話停止対象は`session_id`ではなく`request_id`で特定する。同じChat Session内の過去発話まで停止対象に含めない。実作業停止は`agent_session_id`で特定し、会話の`cancel_response`と混同しない。

## 会話ログ形式（chat_append / chat_sessions共通）

`runtime\chat_sessions\<session-id>.jsonl` に1行1件で追記する。セッション一覧用メタデータは`runtime\chat_sessions\index.json`に保持する。

`entries.sqlite3`はJSONLから復元可能な派生索引とする。通常追記・旧履歴の取込・障害後の復旧は同じ増分取込処理を使い、未反映の行を飛び越して反映済み位置を更新しない。原文追記はflush / fsync後に索引へ反映する。末尾が改行なしで途切れている場合は既存bytesを残して改行を補い、次のEntryが壊れた行へ連結されるのを防ぐ。不正な行は索引へ入れず、原文には残す。

旧索引（`user_version=0`）は欠落したEntryを含み得るため、初回に派生行とcheckpointだけを無効化し、各Sessionの次の読込／追記時に原文から再構築する。移行後の通常取得は未反映の末尾だけを読む。原文JSONL・Session一覧・World / Private Memoryはこの索引移行の対象外とする。

| フィールド | 型 | 説明 |
|-----------|----|------|
| entry_id | string | Chat Entry 1件の安定ID。同一Entryのretryでは同じ値を使い、同文の別発言には新しい値を発行する |
| ts | string | 時刻 |
| kind | string | say / whisper / resident_say / resident_whisper / resident_chat / holo_say / task / system |
| from | string | 発言者（"master" または住人名） |
| to | string? | whisperの宛先、またはresident_chatで発言者が明示的に話を振った参加Resident。Group全体向けresident_chatでは省略 |
| text | string | 本文（全文） |
| session | string | セッションID |
| request_id | string? | Master発話に紐づくEntryの場合のRequest ID。Resident自律会話等では省略可 |
| task_id | string? | Taskの高水準Entryの場合のTask ID。通常会話では省略 |
| agent_session_id | string? | Task実行の詳細Agent UIへ辿る必要があるEntryの場合のAgent Session ID。Command全文やDiff自体はChat Entryへ複製しない |

旧履歴では`entry_id`省略を許容する。Worldの重複判定・既読位置は`session + entry_id`を優先し、省略時だけ時刻・種別・話者・宛先・各関連ID・本文の組を使う。`request_id`は依頼単位でありEntryの一意IDではないため、同じ依頼の別発言を消す根拠にしない。

- 例1：Masterが全体に話す
  - `{"ts":"…","kind":"say","from":"master","text":"みんなおはよう","session":"S-20260821-001"}`
- 例2：住人AがBに話す（住人同士の会話）
  - `{"ts":"…","kind":"resident_chat","from":"A","to":"B","text":"この実装、手伝ってくれない？","session":"S-20260821-002"}`

### チャットセッション規則

- 新規チャットはTemporary Contextだけを新しくする。World Memory、Private Memory、Resident人格は維持する
- Chat Session履歴には削除済みResidentの過去発言を歴史として残してよい。ただしBrain Contextには履歴とは別に現在有効なResident一覧を渡し、削除済みResidentを現在参加者として扱わせない
- セッションタイトルは追加のBrain呼び出しを使わず、最初の**公開Master Say**を短く切り詰めて生成する。Whisper / Private Channel本文をSidebarタイトルへ昇格させない
- 過去セッションを選択した場合、その履歴を表示し、そのセッションの続きとして発言できる
- `chat_session_delete`は`runtime\chat_sessions`側の履歴だけを削除する。ただしHolo ↔ Resident `talk`がそのSessionを公開先としてTurn finalization中なら、発言と返答の帰属を壊さないため削除を拒否する
- `world_memory_forget_session`はそのUIセッションに紐づくPublic Raw Durable Source、Structured Continuity、Derived Retrieval対象を整合して削除・再構成し、同じ`runtime\\chat_sessions`側のUI履歴も削除する。旧Episode互換Viewだけを削除してRawを残す状態をForget成功と扱わない。Private Memoryは削除しない。ただしHolo ↔ Resident `talk`がそのSessionを公開先としてTurn finalization中なら同様に拒否する

## 再接続と異常時の規定

1. World切断をCoreが検知した場合
   - 住人の行動指示を保留（捨てない。再接続時に最新状態だけ送り直す。個々のactionは再送しない）
   - 会話ログはセッションファイルに書き続ける（再接続時にhistory_requestで取り戻せる）
2. Core切断をWorldが検知した場合
   - 1秒→2秒→4秒→8秒→16秒→30秒の指数Backoffで再接続し、以後30秒を上限として継続する。接続成功時は1秒へ戻す
   - Worldは再接続中もアイドル演出（住人がその場で待つ・歩き回る）を続ける
   - Worldの送信は互換Protocolの`hello_ack`完了かつWebSocketがOPENの場合だけ受け付ける。`hello_ack.protocol.version`がWorld実装のVersionと異なる場合、またはCoreがclose code 4004でProtocolを拒否した場合はconnected扱いせず、明示的な互換性Errorで停止して自動再接続しない。Version不一致は時間経過では回復しないためReconnect Stormを起こさず、World/Core更新後の明示再起動で再接続する。CLOSING / CLOSEDや通常の送信例外は失敗として入力元へ返し、入力中の文面を保持して通常Backoffへ移る。依頼や承認を自動再送しない。終了済み接続からの遅延通知で新しい接続を置換しない
3. 応答待ちのタイムアウト
   - `action`に対する`action_done`が60秒来ない場合、Coreは失敗扱いにして次へ進む（WARNログ）
4. 生存確認
   - 独自Heartbeatプロトコルは初期実装しない。WebSocket標準の接続状態・切断検知を利用する
   - 実装上必要になった場合は、AITuberKit等の既存実装をベンチマークにして追加し、Nirai独自方式を発明しない
