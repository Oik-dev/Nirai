## プロセス構成

NiraiはCoreと交換可能なWorldを基本構成とする。配布可能なStandard WorldはElectron + Three.js、Master個人用Private DNA WorldはUE4.27をMain UX Surfaceとする。Private DNA Trackの現行正本は`../Nirai_DNA_UE427_Architecture_2026-09-08.md` v0.5。

1. **Core**（Python常駐サービス）
   - Brain、会話、記憶、自律行動、Task、Agent Runtime、拡張
   - WebSocketサーバー（127.0.0.1:8765）を持つ。World lifecycleは`WorldRuntimeLauncher` Contract（launch / stop）だけへ依存し、標準Electron固有の実行Pathは`world/launcher.py`の`StandardWorldLauncher` Adapterへ隔離する
2. **World**（交換可能なPresentation / Embodiment層）
   - 配布可能なStandard WorldはElectron + Three.js。VRM Runtimeは`@pixiv/three-vrm`を中心に構成する
   - Master個人用Private DNA WorldはUE4.27を唯一の通常利用Main UX Surfaceとし、DNA Scene／Body／UI／Animation／Interactionを可能な限りReuseする
   - 3D World、Resident身体、Animation、表情、視線、LipSync、UI、演出を担当する。Voiceは特定EngineをWorld Contractへ固定しない
   - AIの判断・記憶は一切持たない
   - Electron / Three.js / UE4.27 / DNAのいずれもCoreの永久Invariantにせず、共通の意味Contractへ接続する

- 生存関係
  - 現行標準WorldではCoreが親。Worldが落ちたらCoreが再起動を試みる（30秒間隔）。短時間に連続5回失敗した場合はWorldだけを見捨ててCoreを残さず、Nirai全体を終了する。60秒以上安定稼働した後のCrashは過去のfailure streakを引き継がず、新しい1回目として数える
  - Coreは起動ごとにWorld専用Secretを生成し、現行標準Worldでは子Electronへ渡す。交換Worldでも同等以上の`hello`認証境界を維持し、認証成功前は接続登録・Snapshot送信・権限Message処理を行わない。未認証Processが正規Worldを置換できないことを安全Invariantとする
  - Coreが落ちたらWorldは切断を検知し、1→2→4→8→16→30秒（以後30秒）の指数Backoffで再接続を試みながら待つ（Worldはアイドル演出を続ける）

会話UIは表示中WorldのUX Surfaceへ統合する。Standard WorldではElectron Renderer UI、Private DNA WorldではUE内Private UIを使う。Private常用時にElectron別Windowとの往復を要求しない。

```
D:\Products\Nirai\

  Docs\
    Nirai_基本設計.md     # 正本

  core\                  # Python: Core本体

  residents\
    <住人名>\             # 人格・Private Memory（06参照）
  skills\                 # Nirai共通Skill Registry。Skill本体は<name>\SKILL.md（03参照）

      SKILL.md
  world_memory\           # Say・公開会話・World Eventの共有記憶（06参照）

    events\                # 旧/補助World Event移行元。Current Raw正本はSQLite
    episodes\              # 旧M1互換Episode View。派生 / Legacy fallback
    index\                 # 旧Episode Retriever派生Index。再生成可能
  extensions\
    <拡張名>\             # 拡張機能（07参照）
  runtime\               # 実行時データ（Git管理外）
    logs\                # ログ
    chat_sessions\       # UI上のチャット履歴。セッション単位で保存
      index.json          # セッション一覧用メタデータ

      entries.sqlite3     # JSONLから増分生成する検索・pagination用派生Index
    state.json           # 世界の状態（Location・予算消費など）
    workspace\           # タスク実行の作業場
    agent_sessions\      # Agent Runtimeの構造化実行履歴。Taskごとの詳細UI復元用
```

Named Locationの実座標はThree.js Worldが持つ。Coreは意味的なLocation IDだけを扱う。

Worldの依存VersionとLockfileは`world/package.json` / `world/package-lock.json`を正本とする。CoreのPython PackageはRoot `.venv`へ隔離し、`requirements.txt`の固定Versionを使う。ルートでは`npm test`（World）、`npm run test:core`（Core）、`npm run typecheck`、`npm run build`を実行できる。初回またはPC復元後は`Setup Nirai Runtime.cmd`で`.venv`を再構成し、World依存準備は`npm --prefix world ci`を使う。ルート側へ別VersionのElectron / React / Three.jsを導入しない。

M0安定版までの実装範囲は `world\` と `avatars\` と Docs。M1-01以降で `core\` と `config.toml` を導入する。`residents\` と `world_memory\` は後続Taskで必要になった段階で追加し、未使用Moduleを先回り実装しない。

## 技術選定

| 部品 | 技術 |
|------|------|
| Current standard World | Electron + electron-vite + React + TypeScript + Three.js |
| World UI State | Zustand |
| VRM Runtime | `@pixiv/three-vrm` + `@pixiv/three-vrm-animation` |
| Core | Python 3.12.x + Project-local `.venv` |
| Core⇔World | ローカルWebSocket（`websockets`ライブラリ） |
| Voice | Current Standard World v1はVOICEVOX互換`tts.*`を現役transportとして利用する。Private DNA / Protocol v2ではProvider非依存Voiceへ移行するが、v1互換確認前に現行経路を削除しない |
| 設定 | TOML |
| データ交換 | JSON |

- Worldはデスクトップ専用のためNext.jsを採用しない。Main / Preload / RendererのBuildは`electron-vite`へ任せ、RendererはReact + TypeScript、UI状態はZustand、3D RuntimeはReactの外側に置く
- npmをPackage Managerとし、依存版はM0 bootstrap時に互換確認した組み合わせを`package-lock.json`で固定する。実装途中で無断更新しない
- `three` / `@pixiv/three-vrm`はAITuberKitで実運用されている組み合わせを出発点として評価し、VRMAは公式`@pixiv/three-vrm-animation`を直接利用する。AITuberKit内の独自VRMAnimation実装はコピーしない
- AITuberKitを主要ベンチマークとする。AITuberKitが既に解いているVRM表示、Animation、Expression、LookAt、LipSync、TTS、WebSocket外部連携、Electron化等は、設計・責務分割・採用OSSを積極的に参考にし、同じ問題を独自方式で再発明しない
- AITuberKit自体はForkしない。AITuberKit固有コードをコピー・改変して利用せず、採用OSSの公開APIからNirai向けに独自実装する
- 新規ライブラリ追加は「既存OSSで解けるか」を先に確認し、Nirai固有要件に必要なものだけ導入する

## 共通規約

- ファイル
  - テキストファイルは全てUTF-8（BOMなし）
  - ただしWindowsのbat等ネイティブツールが読むファイルを作る場合は、文字コード事故に注意する（ASCIIのみで書くのが安全）
- 時刻
  - ローカルタイム。記録はISO 8601形式
    - 例：`2026-08-21T14:30:00+09:00`
- ログ
  - `runtime\logs\core-YYYYMMDD.log`（WorldのログもCoreが集約する）
  - 形式：`[時刻] [レベル] [部品] メッセージ`
  - レベル：DEBUG / INFO / WARN / ERROR。`config.toml`の`core.log_level`を適用する
  - Core常駐中に日付を跨いだ場合は、次の日の`core-YYYYMMDD.log`へ自動で切り替える
  - 障害追跡用に、Core/Worldの起動停止・接続切断・Protocol種別・`request_id`・`invocation_id`・Brain/CLIの開始/終了/所要時間・Cancel・Timeout・Parse失敗・例外を記録する
  - 会話本文、Brain Prompt、正常なBrain stdoutはCoreログへ重複保存しない。会話本文の正本は`runtime\chat_sessions\S-*.jsonl`とする
  - CLI異常出力を記録する場合は改行をエスケープし、最大500文字までの診断用抜粋に制限する
- ID規則
  - セッション：`S-YYYYMMDD-連番3桁`　例：`S-20260821-001`
  - タスク：`T-YYYYMMDD-連番3桁`　例：`T-20260821-001`
- 安全（全部品共通・違反禁止）
  - 通信は127.0.0.1のみにバインドする。外部公開しない
  - localhostであってもWorld接続をrole自己申告だけでは信頼しない。Core起動ごとのWorld Secretで認証し、認証成功前はWorld専用状態・Approval / Plan / Agent Cancel等を受け付けない
  - Git操作・外部への送信・システム設定変更・秘密情報の読み書きは、Masterの明示承認なしに行わない
  - `world_memory\`、`residents\*\private\`、`runtime\`は個人会話・実行時データを含むためGit管理外を既定とする
  - Brainのタスク実行が触れるのは許可された作業ディレクトリのみ（07参照）

## config.toml（全体設定）

| キー | 型 | 既定値 | 説明 |
|------|----|--------|------|
| core.port | int | 8765 | WebSocketポート |
| core.log_level | string | "INFO" | ログレベル |
| world.fps | int | 30 | 通常時の描画FPS上限 |
| world.audio_volume | int | 100 | 全体音量0〜100。0はMute。値は永続保存する |
| world.voicevox_url | string | Current v1 compatibility | Standard World v1のVOICEVOX互換TTSで現役利用する。Provider非依存v2へのmigration完了とStandard World互換確認後に廃止を検討する |
| ecomode.resume_delay_sec | int | 10 | 非表示解除後、復帰までの待ち |
| residents.enabled | array | ["..."] | 有効な住人名の順序付きリスト（residents\配下のフォルダ名）。配列順は右Resident Sidebarの表示順であり、複数Residentの初期配置順にも使う |
| tasks.allowed_dirs | array | ["runtime\\workspace"] | タスクが作業できる許可ディレクトリのリスト。Masterが追記して広げる（07参照） |

- 住人ごとの設定（頭脳・ティック間隔・予算・Avatar・TTS Speaker/Style/音声調整）は `residents\<住人名>\config.toml` に置く（06参照）
- `residents.enabled`の順序変更はResidentのIdentity・Memory・設定を変更しない。表示順と初期Presentation配置順だけを変更し、削除・再作成の代替にしない
- Electron Rendererからファイル選択、既定アプリ起動、プロセス操作等を直接行わない。Renderer → Preload IPC → Main Processの境界を通す
- Current World MemoryのRaw正本は`world_memory\world_memory.sqlite3`とする。`world_memory\episodes\` / `world_memory\index\`は旧M1互換・Legacy Retriever向けの派生物であり、正本ではなく削除・再生成可能とする
- Nirai共通Skillの正本は`skills\<name>\SKILL.md`とする。Provider固有のGlobal Skill Directoryへ複製しない。Coreは`name / description`だけの軽量索引を共通入口とし、通常会話へSkill本文を常時注入しない。Task相談では索引だけを渡し、実Agent Work開始時にTaskとの関連度から必要なSkillだけを選んで本文を遅延読込する。Holo Local Clientの`skills`も索引だけを返し、本文を無条件配布しない。Skillが0件なら追加Contextを発生させない。詳細は03と12を正とする

## 起動と停止

1. 起動（通常は`Nirai.lnk`、開発時は`Start Nirai.cmd`）
   - Rootの`nirai_bootstrap.py`がCore importより前にstdlib-only Preflightを行う。`.venv`、Python 3.12.x、`websockets` / `sqlite-vec`、config、Electron Runtime、Production Buildまたは開発Toolingを確認し、必須要件欠損時はCoreへ入らず明示エラーと`runtime/logs/startup-preflight.log`を残す
   - Cursor / Codex / Claude / Gemini等のProvider状態はPreflightで診断してもoptional扱いとし、未導入・未認証・利用不能をCore起動失敗へ昇格させない。Provider Adapterも実利用時まで遅延初期化する
   - Coreが設定を読み、WebSocketサーバーを立てる
   - CoreがWorld専用Secretを生成し、選択された`WorldRuntimeLauncher`でRuntimeを起動する
   - 現行標準LauncherはElectronアプリを子プロセスで起動する。交換RuntimeはLauncherだけを差し替え、CoreServer / Memory / TaskをForkしない
   - WorldがSecretとProtocol descriptor付き`hello`を送り、認証とProtocol Version確認が成功したら稼働開始する。Protocol不一致は接続時に明示拒否し、古いWorldを黙って接続しない
   - Private World Addon等でも認証・Protocol Version / capability handshake・Core生存性のInvariantは維持する
2. 停止
   - 会話UIの終了操作 → CoreがWorldに終了通知 → 全プロセス終了
   - Coreは終了前に`state.json`を保存する
3. Windowsスタートアップへの自動登録はM3で行う（それまでは手動起動）

M0ではCoreを完成条件としない。World単体で起動し、存在感を確認する。

## 用語集

| 用語 | 意味 |
|------|------|
| Master | 画面のこちら側にいる利用者（このPCの持ち主） |
| Resident（住人） | 世界に暮らすAI。人格・記憶・頭脳・体の4層 |
| Brain（頭脳） | 住人の会話・生活判断を担う差し替え可能な部品。人格・記憶・World Contextを受け、発言と意味的行動を返す |
| Agent Runtime | M4以降の実作業を担うProvider統合層。Command、File変更、Approval、Question、Plan、Todo等を構造化Agent Eventへ正規化する |
| World | Residentの身体・3D空間・UI・演出を担う交換可能なPresentation / Embodiment層。現行標準実装はElectron + Three.js |
| Core | 裏で動く調停役（Python） |
| Avatar | Residentの身体となるVRMモデルと、その補正・表現設定 |
| VRM Runtime | VRMの読込・Humanoid・Expression・LookAt・SpringBone等をWorldから扱う層 |
| World Memory | Say・公開Resident会話・世界イベントを全Residentで共有する長期記憶の正本 |
| Private Memory | Masterと特定ResidentのWhisperだけを保持する個別記憶 |
| Location | Coreが扱う意味的な場所。実座標はWorldが持つ |
| Say | 場に話す。全住人に届く発言 |
| Whisper | 個別に話す。宛先の住人だけに届く発言 |
| セッション | ひとまとまりの会話（参加者・履歴を持つ） |
| ティック | 住人が「今なにをするか」を考える定期タイミング |
