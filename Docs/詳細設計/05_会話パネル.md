# Nirai 詳細設計 05：会話UI

正本は [Nirai_基本設計.md](../Nirai_基本設計.md)。通信メッセージは [01_通信プロトコル.md](01_通信プロトコル.md)。TTS / LipSyncは [04_World.md](04_World.md)、Resident設定は [06_Residentと記憶.md](06_Residentと記憶.md) を正とする。

## 概要

会話UIはElectron Renderer内のWeb UIとしてThree.js Sceneへ重ねる。

画面の役割は4か所へ分離する。

- 左上：チャットセッション管理
- 右上：Resident設定
- 中央下：会話入力と過去ログ
- 右下：全体音量

Worldを眺めることを主とし、通常時は必要最小限のUIだけを表示する。

## 中央下：チャット入力

### 通常状態

中央下部に半透明のチャットテキストボックスバーを常駐させる。

- 非アクティブ時はWorldを邪魔しない透過度にする
- バー押下で入力をアクティブにする
- アクティブになると、バー上部へ現在セッションの過去ログWindowを表示する
- 入力欄は複数行を許容する
- マイク入力は後回しとし、実装するまでマイクボタン自体を配置しない

### 入力操作

- `Enter`：送信
- `Shift + Enter`：改行
- 右端の`↑`ボタン：送信
- 空文字・空白のみは送信しない
- `@名前 テキスト`：対象ResidentへのWhisper
- 素のテキスト：Say
- 日本語IME変換確定中のEnterで誤送信しない。`KeyboardEvent.isComposing`またはcomposition状態を必ず確認する
- 送信1回ごとにRendererで`request_id = crypto.randomUUID()`を生成し、`master_say` / `master_whisper`へ付ける

## 過去ログWindow

- チャット入力がアクティブな間、入力バーの上部に表示する
- 初期表示は半透明とし、Worldが背後に見える
- 過去ログWindow自体をクリックすると背景透過を解除し、文字を読みやすくする
- World側または入力バー以外へフォーカスを移した場合は半透明状態へ戻してよい
- 縦スクロール可能
- 上端へ到達した場合は`history_request`でさらに古い履歴を取得する
- 表示中の履歴は現在選択中のチャットセッションだけとする

| kind | 表示 |
|---|---|
| say（Master） | `あなた: テキスト` |
| whisper（Master発） | `あなた → 名前: テキスト` |
| resident_say | `名前: テキスト` |
| resident_whisper | `名前 → あなた: テキスト` |
| resident_chat | `名前 → 名前: テキスト` |
| task | `[タスク] 進捗テキスト` |
| system | `[お知らせ] テキスト` |

WhisperはMasterのUI履歴には表示するが、他ResidentのContextやWorld Memoryへ混ぜない。

## AI応答中と停止ボタン

Master発話へのAI応答処理が始まったら、送信ボタンの`↑`を停止ボタンへ切り替える。

停止ボタン押下時は、現在の`connectionStore.activeRequestId`を使って`cancel_response {request_id}`をCoreへ送る。Chat Session IDだけで停止してはならない。

停止対象：

- 現在のMaster発話に応答中のResident Brain呼び出し
- 同じ発話に対してまだ開始していないResident応答キュー
- その発話に対応する再生中TTS

停止対象外：

- 実行中Task
- Worldの描画・生活状態
- 過去セッション
- 別契機で動いている処理

Coreから`response_state.active=false`を受けたら送信ボタンを`↑`へ戻す。

## 左上：チャットセッションSidebar

左上のサイド展開ボタンを押すと、左側Sidebarを開く。

Sidebar内でチャットセッションに関する操作を完結させる。

```text
[＋ 新しいチャット]

今日
  NiraiのUIについて
  VRMについて

昨日
  海中Worldについて
```

### 新しいチャット

- 新規チャット作成時に新しいSession IDを発行する
- Temporary Contextだけを新しくする
- World Memory、Private Memory、Resident人格は維持する
- セッションタイトルは最初のMaster発話を短く切り詰めて生成し、タイトル生成専用のBrain呼び出しは行わない

### 過去チャット

- 一覧は更新日時の新しい順
- 選択するとそのセッションの履歴を中央ログWindowへ表示する
- 過去セッションを選択して、その続きとして会話できる

### 削除と記憶

「チャット履歴を削除」と「World Memoryから忘れさせる」は別操作とする。

- **履歴を削除**：UI用チャットセッションを削除する。World Memoryは残る
- **世界の記憶から忘れさせる**：対応するWorld Memory Episodeを削除・除外する。UI履歴は残る

両方を行いたい場合は、それぞれ明示的に操作する。

## 右上：Resident設定Sidebar

右上の設定ボタンを押すと右側Sidebarを開く。

上部に`新規作成`、その下に存在するResident一覧を並べる。

### Resident新規作成

新規作成時にMasterへ要求する入力は**名前だけ**とする。

名前は空文字、既存Residentとの重複、Windowsフォルダ名として不正な文字を含む場合は作成せず、その場で理由を表示する。

作成時：

- Residentフォルダを作成
- 名前だけ入った`persona.md`の雛形を作る
- 未設定状態の`config.toml`を作る
- Brain / VRM / VOICEは後から個別に設定する

Brain未設定のResidentはAI応答しない。VRM未設定のResidentはWorldへ身体を出さない。設定Sidebarには存在し続ける。

## Resident項目

Resident名を押すと、その直下へ次の項目を展開する。

1. AI連携
2. VRM読込 / VRM変更
3. VOICE読込 / VOICE変更
4. プロンプト
5. キャラクター削除

### 1. AI連携

初期Provider一覧：

- Codex
- Claude
- Cursor
- Gemini
- Local LLM

Provider Adapterが返す方式に応じてUIを切り替える。

- 連携方式なら`連携`
- API設定方式なら`API設定`
- ローカルRuntime方式なら必要なローカル接続設定

連携済みの場合は、現在のAI名と`連携解除`を表示する。

連携解除はそのResidentとBrain Providerの割当を解除する操作であり、外部CLIのアンインストールやPC全体のログアウトを勝手に行わない。

### 2. VRM読込 / VRM変更

未設定時は`VRM読込`、設定済みなら`VRM変更`と表示する。

押下時はElectron Main Process経由でWindows標準File Pickerを開く。

- 初期表示フォルダ：`D:\Products\Nirai\avatars\`
- 選択可能拡張子：`.vrm`
- 選択したVRMへの参照をResident設定へ保存する
- Nirai外部から自動コピーするImporterは作らない
- キャラクター削除時も`.vrm`本体は削除しない

### 3. VOICE読込 / VOICE変更

未設定時は`VOICE読込`、設定済みなら`VOICE変更`と表示する。

初期ProviderはVOICEVOXとする。

Nirai内の設定UIで次を選択・調整できるようにする。

- Provider
- Speaker
- Style
- 話速
- 音高
- 抑揚
- 試聴
- 保存

Speaker / Style一覧はVOICEVOX Engineから取得する。

VOICEVOX本体の画面を設定UIとして利用する前提にはしない。VOICEVOXへ接続できない場合はその旨を表示し、テキスト会話には影響させない。

### 4. プロンプト

押下すると対象Residentの`persona.md`をWindows既定のテキストエディタで開く。

Nirai独自のMarkdown Editorは作らない。

Rendererから直接OS操作せず、Preload IPC → Electron Main Process経由で既定アプリへ渡す。

### 5. キャラクター削除

強い削除操作とする。

押下時に確認Dialogを開き、テキストボックスへ完全一致で`Delete`と入力した場合だけOKを有効にする。

削除対象：

- persona.md
- config.toml
- Private Memory
- Whisper履歴
- Brain割当
- VRMとの紐付け
- VOICE設定
- Resident状態
- Residentフォルダ内のその他Resident固有データ

削除しないもの：

- `avatars\`配下の`.vrm`本体
- World Memoryに残っている共有世界の過去
- VOICEVOX本体
- Claude / Codex / Cursor / Gemini等の外部CLI・Runtime

削除後、そのResidentはWorldと設定一覧から除去する。

## 右下：全体音量

画面右下に音声ボタンを置く。

押下すると、ボタンの上方向へ**縦型**音量Sliderを展開する。

```text
      │
      │
      ●
      │
      │
     🔊
```

仕様：

- 値は0〜100
- Dragで調整
- 音量領域にマウスカーソルが乗っている状態でMouse Wheelを使うと**5刻み**で増減する
- 上方向Wheel：+5
- 下方向Wheel：-5
- 0でMute扱い
- 0のときIconをMute表示へ切り替えてよい
- 値は保存し、次回起動時に復元する
- 音量0でもテキスト発話・吹き出し・会話ログは継続する
- 音量0の間に発生した発話を、音量復帰後に遡って再生しない

音量操作は右下へ集約し、チャットバー付近に別のMuteボタンは置かない。

## Core切断時

- チャット入力を無効化し`接続待ち…`を表示する
- Three.js SceneとResidentのアイドル演出は継続する
- 設定のうちCoreを必要とする操作は一時的に無効化する
- Core再接続後、現在のセッション一覧・選択セッション・音量状態を同期する

## 実装方針

- UIはReact + TypeScriptで実装し、UI StateはZustandへ分割する。3D Runtime ObjectはZustandへ入れない
- Storeは`connectionStore` / `sessionStore` / `residentStore` / `audioStore` / `uiStore`へ分割し、巨大Store 1個にしない
- UIはWeb標準のDOM / CSS / Eventで成立する部分を優先し、不必要な独自UI基盤を作らない
- Three.js SceneとDOM UIを分離する
- OS操作はRendererへ直接公開せずPreload IPC経由にする
- AITuberKit等の既存UIやAIクライアントの一般的な操作感をベンチマークにしてよいが、固有コードはコピーしない
- 音声入力は後回し。実装するまではマイクボタンも配置しない
- Component名、Store責務、Chat Scroll処理、VOICE設定Flow等の実装粒度は10を正とする
