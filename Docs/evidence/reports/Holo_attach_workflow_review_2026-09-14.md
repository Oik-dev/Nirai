## Remaining findings

1. **[P2] Require workflow identity for completion, including delayed retries.** `tools/holo-local-client.mjs:245` permits completion without a workflow ID; `.tools/local-mcp-guard/register-tools.mjs:351` makes both identifiers optional. A Dive identifies a Conversation, not one unit of work. Reproduction with the actual CLI in a disposable fixture: start workflow A in Dive D, complete A, start workflow B in the same Dive, then retry `workflow-complete D` from A. The call returns `ok: true` and marks B completed. This disables B's watchdog although B is unfinished. The same failure is possible after a lost response or delayed continuation. Require the expected workflow ID for completion and carry it through the semantic Tool schema and bootstrap/auto-resume instructions. The UUID parsing correction below makes workflowId-only calls work but does not make identity mandatory.

2. **[P2] Serialize lease updates across every writer and validate the expected revision.** `tools/holo-local-client.mjs:187` reads the lease before asynchronous work; lines 266–269 await the build guard and then unconditionally write that earlier lease. `world/src/main/holo/HoloWebHost.ts:442` is a separate cancellation writer. Reproduction: pause a fixture copy of the actual CLI at the asynchronous build guard, replace active lease A with active lease B (the state after World cancels A and another Dive starts B), then release A's completion. The final file contains completed A; active B disappears. This reproduces even with both A's Dive ID and workflow ID supplied. Atomic rename prevents torn JSON, not lost updates. All CLI mutations and the World cancellation writer need a shared transaction/lock and expected workflow/revision validation; a post-await read alone still leaves a cross-process race.

3. **[P2] Bind the build stamp to the inputs actually consumed by a successful build.** `world/package.json:9` invokes the stamp only in `postbuild`; `tools/world-build-state.mjs:96` fingerprints whichever inputs exist then. Reproduction with the actual stamp and completion functions: start with source version 1, let a successful fake builder consume version 2 into output, edit the source to version 3 before postbuild, record the stamp, and run the completion guard. It succeeds with `required: true`, although the source is version 3 and the output is version 2. Content hashing fixes metadata collisions but not this build/input race. Build orchestration must capture and validate the input snapshot over the successful build, reject intervening edits and conflicting builds, and only then publish a stamp for that build. Production build execution was unavailable in this isolated copy, so no unverified build-pipeline replacement was introduced.

These remaining changes span the workflow caller contract, multiple process writers, and the build lifecycle. The review applied bounded fixes; it does not certify those broader contracts as safe.

## Applied fixes

- `tools/world-build-state.mjs`: replace size plus truncated mtime fingerprints with streaming SHA-256 of input contents. A same-size edit with a preserved timestamp previously retained the old fingerprint and bypassed the build requirement. The regression failed before this fix and passes afterward. Resolve project containment and refuse symbolic links/junctions before reading contents; cyclic links and a World ancestor link escaping the project are covered. Existing metadata-based stamps conservatively cease to match and require a fresh build. This does not resolve finding 3.
- `tools/holo-local-client.mjs`: distinguish the generated UUID workflow ID from the optional UUID Dive ID. A semantic Tool call supplying only `workflowId` previously failed with “belongs to a different Dive”. Calls omitting both identities now validate the current Dive and Conversation before mutating the lease; they can no longer silently complete an unrelated current Dive's lease. Explicit owner routing remains available for background work. Compare Conversation IDs across query/hash and `WEB:` URL aliases. Findings 1 and 2 remain.
- `tools/holo-local-client.test.mjs`: add real subprocess CLI regressions for UUID-only calls, implicit cross-Dive mutation, mismatched identifiers, Conversation alias handling, same-Dive navigation, and build rejection preserving an active lease and its original baseline.
- `core/tests/test_holo.py`: add attach-window persistence-failure coverage for write/replace failures, restart with an old binding and a current window, duplicate pending delivery without deadline extension, and removal of a stale window belonging to another Dive. Make the existing injected startup-failure test independent of installed provider availability; the original test stopped at provider discovery before reaching its intended failure injection in a clean staging home.
