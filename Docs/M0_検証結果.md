## 概要

Nirai M0検証とは、海中3D WorldとHumanoid Resident 1体がWindows上で継続動作し、「Residentがそこにいる」と感じられる最低限の体験を満たすか確認する受入検証である。

- 実施日
  - 2026-08-23
- 対象
  - `D:\Products\Nirai\world`
- 結果
  - M0受入条件を満たした
  - VRM 1.0とVRM 0.xの両方でAvatar読込・交換を確認した
  - M0基礎実装の30分連続表示に加え、高品質化後にも17分間の追加負荷確認を実施した
  - 継続的なメモリ増加・描画崩れ・Animation停止・Effect停止は確認されなかった
- 2026-08-23時点の制約（履歴）
  - 当時はShiro（VRM 0.x）のAvatar固有表情を意味表情へ解決しておらず、happy / angry / sadを未収録扱いとしてno-opにしていた
  - 2026-08-26の最終ブラッシュアップでAvatar固有Expressionの意味解決を追加し、この制約は解消した。Expressionの現行参照は、末尾 2026-08-26 節のうち Expression 項目に限る。Cameraの正本は `Docs/詳細設計/04_World.md` である。

## 詳細仕様

### 海中Environment

- 構成
  - 上方光・水中減衰
    - 水面Meshは置かず、上方の白〜シアンの明るさと深度方向の青い減衰を軽量Shaderで描画する
  - Caustics
    - 外部画像を使わないVoronoi系Shaderで、海底上の光模様を時間変化させる
  - 光条
    - 生成したソフトマスクを使う半透明Spriteを低速で揺らす
  - Fog
    - `THREE.FogExp2`で遠景を青へ溶かす
  - Resident連動気泡
    - Idle / AFK中は約2.8秒に1個を頭部付近から生成する
    - Locomotion中は速度に応じて少し増やし、身体の後方・下方から生成する
    - 固定長Poolを再利用し、停止後は残った気泡が上昇して自然消滅する
  - 浮遊粒子
    - 通常粒子と発光粒子を別系統の`THREE.Points`で低速に漂わせる
  - 海底
    - （2026-08-23当時）`material/aerial_beach_01_4k`を比較選定し、color / normal / roughness / AO / displacementを使うPBR砂地にした。現行は `GroundSand005` 4K。
  - 仕上げ
    - ACES tone mappingと弱いBloomで上方光、光条、発光粒子を馴染ませる
- 設定
  - seabed / fog / lighting / overheadGlow / caustics / suspendedParticles / luminousParticles / bubbles / lightShaftsを個別にON / OFFできる
  - 品質はlow / medium / highの3段階で、気泡・粒子・光条の数を変更できる
  - Residentとは別の`EnvironmentController`が生成・更新・破棄を担当する
- 実機結果
  - 全Effectが有効なことを実行中diagnosticsで確認した
  - 段階画像で砂地・Caustics、上方光・光条、浮遊粒子の追加を確認した
  - Idle / AFKの控えめな気泡と、Locomotion中に増える気泡を確認した
  - 高品質化後の17分追加負荷でも、描画崩れと実行時エラーはなかった

## 2026-08-23 海中光学再構築

### 結果

- 画面全体へ水色を加算する旧Post Effectを廃止し、Scene深度から水中距離を復元する方式へ置換した
- 距離別のBeer-Lambert吸収により、近景のResidentは明瞭、遠景は赤から先に減衰して深い青へ沈む構成とした
- 太陽方向を1つに固定し、直射光、光条、海底Caustics、中央照明、粒子の明るさを同じ方向へ統一した
- 同一の海面波関数を、水面境界の揺らぎ、屈折光条、Causticsへ共有した
- 光条は深度を使う12 / 18 / 22 stepの品質別Ray Marchを主処理とし、低濃度の円錐Volumeを補助層にした
- Resident中央域にはSpotLight、Caustics密度、光条、発光粒子を集め、周辺を抑えた自然光のStageを形成した
- 砂地は既存のAerial Beach 5-map PBR素材を継続使用し、青白い自己発光を抑えて光が当たった結果として明るくした
- 気泡はResident連動の固定Poolを維持しつつ、中央群・孤立群・速度差・サイズ差を持つ環境気泡を追加した
- 近景 / 中景 / 遠景粒子に層属性と光親和度を追加し、均一な星空状配置を解消した
- Resident表示とEnvironment Effectの管理責務は分離したままで、既存のEffect個別ON / OFFも維持した

## 2026-08-23 参考画像寄せ・光柱/Caustics最終調整

### 結果

- Cameraを引いて上方の太陽域、Resident、海底の光Stageが同時に入る画角へ変更した
- Causticsは海底へ投影される屈折光に限定し、海面へCaustics模様を貼る誤った表現を撤去した
- 海面側は波面法線、Fresnel、太陽反射だけで明暗を作る構成へ修正した
- Caustics、光柱、太陽反射だけをHDR/Bloom対象とし、水色、Resident、浮遊粒子、気泡はBloom閾値未満へ分離した
- 旧円錐Volumeは面の輪郭が見えていたため撤去し、放射状の「高輝度の芯 + 幅広い低輝度散乱」を持つ光柱へ置換した
- 光柱に等間隔で見えていた丸い点列は、粒子やLens Flareではなく、狭い光束を22点で積分したRay Marchのサンプル痕と隔離試験で特定した
- 狭い光束はRay Marchから外し、Ray Marchは連続的な水中散乱だけ、明瞭な光柱はRadiance Planeが担当する構造へ分離した
- 丸い点列の消失後も、浮遊粒子と気泡の上昇・流れは別Effectとして維持した
- 新しいEngine、Runtime依存、外部Assetは追加していない

- 15分の常用負荷は直前の海中光学再構築版で合格済み。今回の最終修正はRay March計算量を削減する変更であり、追加の短時間確認でも増加傾向はなかった

### Movement（現在も有効）

2026-08-25までの本書には、海底歩行と中層遊泳を別の製品挙動として扱った記録が含まれる。これらは当時の検証履歴として保持する。2026-08-26のDecisionでは「既に成立していたMove B自体を作り直さず、Move Aも同じ挙動へ統一する」方針へ更新した。Movementについて現在も有効な項目は以下である。

- Move A / Move Bの明示移動は、2026-08-26変更前の旧Move Bそのものを使用する
- A/Bで異なるのは目的地だけであり、経路、速度、姿勢、Animation、水中Overlayを分岐させない
- 両方とも`medium='seabed'`、移動開始時のY維持、`speed * 0.58`、低いPitch/Bankを使う
- 旧Move B内部の`walk.vrma`基礎Clip、`seabed`水中骨格Overlay、Move B追加脚振りをそのまま保持する
- 「歩行を廃止する」は海底歩行という別の製品モードを廃止する意味であり、旧Move B内部の`walk.vrma`を削除・置換する意味ではない
- 自然移動用の`swimNear` / `swim` Primitiveは別用途として残す
- `stand / afk / sleep`の明示指示は進行中の通常移動を停止し、新しい指示を優先する
- 白砂へ降りるAFKは、接地後の水流Overlayを浮遊AFKより弱くした
- Sleepは現在位置から画面安全領域内の白砂位置へ約3秒でXYZ移動・降下しながらSleep Animationへ馴染み、到着時に二度目のAnimation切替を行わない
- Sleepの安全位置はUnit Testで画面端相当の開始位置から内側へ補正されることを固定した

Quaternionによる水中骨格補正は、旧Move Bと自然移動`swim`の見た目を構成する既存要素として維持する。今回のレビューではProfilerによる負荷実測を行っていないため、回転計算の多さだけを根拠に最適化Task化せず、将来実測でCPU負荷が問題になった場合に対応する。

### Animation読込と操作結果（現在も有効）

- `stand`表示後、`walk / sleep`とAFKを独立してBackground Loadし、AFKは3本ずつ読み込む
- 明示移動が`walk`読込前に要求された場合は、旧Move Bの演技を変えず、`walk`読込完了後に同じ移動を開始する
- `sleep / afk`など、まだ利用可能になっていないAnimationは成功扱いにせず`false`を返す
- AFKのランダム選択対象は、実際に読込済みかつ退役していないClipだけに限定した
- 旧Move Bを壊さない範囲で、Animation未準備時の誤操作経路を縮小した

### Expression最終整理（現在も有効）

Core / AIはAvatar固有のExpression名を知らず、`happy`等の意味Emotionだけを指定する。World側が現在Avatarで利用可能な表情へ解決する。

- 意味Emotion: `neutral / happy / angry / sad / relaxed / surprised / awkward / doubt`
- VRM0互換Alias: `joy -> happy`、`sorrow -> sad`、`fun -> relaxed`
- Avatar固有差分: `happy01`等の同義候補、`startled -> surprised`、`awkward*`、`doubt`を意味名へ解決する
- 同じEmotionに複数候補がある場合、Emotionへ入った時に候補から1つ選び、そのEmotionが継続する間は同じ表情を維持する
