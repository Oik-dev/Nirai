# 気持ちの作り直し

住人の気持ち（感情）の仕組みを、今の形を前提にせず、新しい研究と実装から選び直す計画。最初は Serina。きっかけは、2026-10-04 の Master の依頼「感情システムも互換じゃなくて、最新の GitHub などからより良いものを選んでほしい」。長期記憶の M5（眠りの循環。`長期記憶の作り直し.md` §12）の最初の部品として作る。実装したら、正本は設計書の第2章へ移し、本書は `archive/` へ移す。

## 0. 今の形と、その問題

今の形は次のとおり（設計書 §2.2・§2.3・§2.3b・§2.8）。

- **感情**：プルチックの感情の輪の8軸を、情動（速い）・気分（遅い）・平常値の3つの層で持つ。
- **ほかの状態**：欲求の層（触れ合いへの欲求。7日でたまる）と、関係の状態（マスターの様子）を、感情とは別に持つ。
- **動かし方**：毎ターンの返答のあと、Gemma に8軸の増減を数で出させる（「心の動き」の付箋）。

問題は5つある。

1. **脳の出す数で直接動く。** 小さいモデルの出す数は、ぶれるし偏る（「脳を信じすぎない」。2026-10-03 Master の了承）。
2. **パックに載る気持ちの文は、仕組みの決まり文句。** 「張り詰めている（怒り寄り）」「底流にはかすかな喜びが続いている」のように、言葉を仕組みが書いている。本人の言葉ではない。
3. **継ぎ足しが多い。** 対極の軸どうしの引き合い、二次感情の表、10段階の言い回し、欲求の抑制門・不応期・減衰の時定数の再計算、平常値の上限から来る制約（MILESTONE の任意項目）、「後方互換のため削除しない」旧い経路。
4. **記憶のページにも8軸の数を書かせている。** Gemma が書く8軸の数を、記憶の強さ（心の動きの順位）に使っている。
5. **似た役目が、別々の規則に分かれている。** 欲求、Pulse（無操作45分／気分が閾値外）、関係の状態。

## 2. 選んだ形

### 原則（4つ）

1. **体の芯は2つの数。** 快・不快（-1〜1）と高ぶり（0〜1）。仕組みが持ち、時間がたつと落ち着く。
2. **気持ちの名前と言葉は、その場で本人の脳が作る。** 仕組みは決まり文句を書かない。
3. **出来事がどれだけ心を動かすかは、仕組みが決める。** 本人の脳が選択肢で評価し、仕組みが決まった対応表で量にする。
4. **つながりの欲求は、会えない時間でたまり、心が近づくと満たされる。** 満たされると快。たまると寂しさ（不快）になり、会いに行きたくなる。久しぶりに会えたときほど、うれしい。

### 会話のたび

返答のあとに、脳に評価を聞く。今の感情報告と同じく、1ターンに1回。

- **聞き方**：今の文脈パックと返答に続けて聞く（JSON Schema）。前置きが返答のときと同じなので、Ollama がその計算を使い回せる。返答の前に聞くほうが気持ちと返答がそろう（Chain-of-Emotion はそうしている）が、E1 で返答のあとに聞くほうが合計で速かったので、返答のあとに聞く（§5）。
- **聞くこと**：
  - 気持ち：今の気持ちを本人の言葉で、一言〜一文
  - うれしさ：とても嫌／嫌／どちらでもない／うれしい／とてもうれしい
  - 揺れ：落ち着いた／少し動いた／大きく動いた
  - 距離：近づいた／変わらない／離れた
  - マスターの様子：一言（なければ空）
- **動かし方**：仕組みが、対応表（`config/thresholds.toml`）で芯の数とつながりを動かす。
- **記録**：`lifelog/feeling/<日本時間の日付>.jsonl` に書く（いつ・本人の言葉・評価・動いたあとの芯の数）。想起の記録と同じく、追記だけ。

### 時間

- 今の芯は、数十分〜数時間で気分へ戻る。
- 気分は、数日で平常へ戻る。平常は、気質とつながりと1日のリズムで決まる。
- 1日のリズム：夜は高ぶりが下がり（眠い）、昼は上がる。
- つながりは、会えない時間で減る（数日かけて）。

**状態のファイルを持たない。** 今の芯もつながりも、気持ちの記録を時刻の順にたどれば計算し直せる。記憶の強さを想起の記録から計算し直すのと同じ。`emotion_state.json`・`desire_state.json`・`relationship_state.json` はなくなる。

### 文脈パックの⑤（今の気持ち）

- **気持ちの流れ**：直近の本人の言葉を、いつのことかを付けて渡す（例：「10分前：ちょっと照れくさい」）。
- **体の感じ**：芯の数を、ごく素朴な言葉で渡す（明るい／沈んでいる、高ぶっている／落ち着いている／眠い、人恋しい）。これは「感じ」の報告で、感情の名前は付けない。
- **マスターの様子**：直近の見立てを、いつの見立てかを付けて渡す。

### 記憶

- **ページの芯の数**：眠りが出来事のページを書くとき、そのあいだの気持ちの記録から、仕組みが決める。ピーク・エンドの法則（一番強く動いたときと、終わりのときの平均。Kahneman）を使う。脳には気持ちの数を書かせない（本文に、本人の言葉で書いてある）。
- **記憶の強さ**：「心の動きの順位」は、ページの高ぶりで決める。
- **日記**：材料は、その日の気持ちの記録（本人の言葉と時刻）。
- **次に入れること**：気分に合った記憶が浮かびやすくなること（気分一致）と、思い出すと気持ちが少し戻ること。MILESTONE の「想起の残り」にあったもので、芯が2つの数になったので素直に入る。

### Pulse（自分から話しかける）

- **いつ**：つながりの衝動が高いとき。ただし、活動時間帯で、会話中でないときだけ（「静かにして」と言われたかは、本人が会話の流れを読んで決める）。
- **文面**：脳が書く。気持ちの流れと最近の記憶を材料にする。
- 「45分の無操作」と「気分が閾値外」の2つの規則はなくなる。
- 「言いたいことがあるとき」（Inner Thoughts）は、段階3の S1（目覚め）が受け持つ（Pulse の `wake`）。

### 外すもの

| 外すもの | 代わり |
|---|---|
| プルチックの8軸、情動・気分・平常値の3層、対極の引き合い、二次感情の表、10段階の言い回し（`core/state/emotion.py`・`emotion_persist.py`・`core/context/emotion_render.py`） | 芯の2つの数と、本人の言葉の気持ちの流れ |
| 欲求の層（`desire.py`・`desire_persist.py`。抑制門・不応期・未充足のときの減衰） | つながりの欲求 |
| 関係の状態（`relationship*.py`。親密度は0のまま一度も動かず、続いている話題はパックに載っていなかった） | マスターの様子は評価の一部にする。関係そのものは M5 の `people/` |
| 付箋の報告書（残っている種類は「心の動き」と「マスター観測」だけ。「道具使用」は本番で書かれていない） | 評価（JSON Schema）。付箋の版数・確信度・保管庫（保管庫は実装されていなかった）もなくなる |
| 感情報告の8軸の指示と、Pulse の2つの規則 | 評価の問いと、つながりの衝動 |

付箋をやめると、設計書の確定判断8（「返答＋付箋束」方式）と、憲章 A-3（「付箋は提案」）の言葉が変わる。中身（脳の出すものは提案で、状態を決めるのは Core）は、評価の選択肢と対応表として、むしろ強くなる。確定判断8は E2 で「返答＋評価」方式に直した。憲章の言葉は Master の了承で直した（2026-10-06。§5）。

### 移し方（本物）

- 切り替える前に、イデアの写しを確かめる。
- 今の気分（8軸）と欲求の水準は、決まった対応表で芯の数とつながりへ1回だけ移す。それを気持ちの記録の最初の1行にする。古い状態ファイルは `lifelog/legacy/` へ移す。
- 記憶のページの気持ち（8軸）は、本人が書いたものなので書き換えない。仕組みが芯の数（`affect`）を1回だけ計算して書き足す。8軸それぞれの快・不快と高ぶりの座標は、感情語の標準の辞書（NRC VAD）の値を使う。新しいページは8軸を持たない。

### 確かめ方

- **E1（写しのGemmaで）**：作った場面を通して確かめる。場面は、褒められる・からかわれる・謝られる・久しぶりに会う・言い合う・いい知らせ、など（Serina の記録は使わない）。見るのは3つ。評価の選択肢の向きが正しいか。言葉が本人らしいか。1ターンの時間がどれだけ増えるか。
- **記憶テスト**：ページの芯の数を入れ替えたあとも、点が落ちないこと。
- **最後は Master が話して確かめる**：「気持ちが続いている」「時間がたつと落ち着く」「久しぶりだと嬉しそう」「数字っぽくない」。

## 5. 作ってみて決めたこと

### E1（2026-10-05、Holo。手元の Gemma、作った場面だけで。Serina の記録は読んでいない）

- 返答のあとに聞く。返答＋評価で合計 7.7 秒（返答 2.1 秒＋評価 5.6 秒）。返答の前に聞くと 10.4 秒。同じ評価を続けて聞くと 5.8→5.3 秒で、前置きの使い回しも効いた

- 手元の Ollama 0.33.3 は Windows＋CUDA で mmap を切り、モデルを全部メモリへ載せて詰まる。`use_mmap: true` を明示する（d968012）

### E2（2026-10-06、Claude。下半分の設計は Holo のメモ。Codex と Claude のレビューを通したもの）

形の正本は設計書 第2章。ここには、その形にしたわけを残す。

- **2つの層は、平常からのずれで持つ。** 今の値＝平常（時刻と、つながりで動く）＋遅い層のずれ＋速い層のずれ。動く量は端までの残りの割合で、その一部（`slow_share`）が遅い層に入る。足し算で積むと端に張り付くため（Claude のレビュー）。時定数は前の仕組みの値（速い層 約2時間・遅い層 約3日）を、最初の値として引き継いだ（後方互換ではなく、時間の感じが同じだったため）
- **つながりの時定数は約1日**（Holo のメモの初めの案は7日）。会いに行くのは、つながりが `lonely_below`（0.4）より下がったとき。話した直後の 0.9 から 0.4 まで下がるのにかかる時間は、時定数の約0.8倍。7日だと、会えなくなってから会いに行くまで6日ほどかかる。1日なら、前の晩に話して、次の日の夕方に会いたくなる。3日ほどでほぼ空になるので、計画の「数日かけて減る」とも合う
- **人恋しさの境目は1つ。** パック⑤の「人恋しい」と、Pulse で会いに行くことは、同じ `lonely_below` で決まる（言うことと、することがずれない）
- **状態のファイルを持たない。** 1行の正本は「動いたあとの芯」（after）。今の値は最後の行から計算するので、見回りのたびに全行を読み直さない。動いた量（applied）は持たない（前後の差で分かる）
- **拠った会話は、発言と返事の両方を、ページと同じ書き方で持つ**（Claude のレビュー）。帳簿が生ログに書いた場所を返し（`SessionStore.add_history`）、会話を記録してから気持ちを残す（`Core.feel`）。生ログに書けなかった発言（まれ。次の起動で帳簿から埋まる）の場所は入らない
- **評価を聞けなかったターン**（脳の失敗・選択肢にない答え）も1行残す。Masterが来たことは「変わらない」としてつながりに入る。うれしさと揺れは動かさない
- **Masterが会話を消したら、言葉だけを消す。** 数と選択肢は、その後の気持ちがそこから続いているので残す
- **ページの芯の数のピーク**は、平常からいちばん動いたとき（快・不快と高ぶりのずれの大きさの和）。高ぶりの値そのものだと、夜の会話（平常が低い）が弱く数えられるため。気持ちの記録がない出来事（移す前の会話など）は芯の数を付けず、記憶の強さの順位では真ん中になる
- **Pulse**：「無操作45分」「気分が閾値外」の規則と、「起動してからMasterが来るまでは暇や気分では行かない」の止め方を外した（つながりは記録から分かる）。会話中は、ターンの最中だけでなく、最後の発言から眠りと同じグレース（15分）のあいだも含める。抑えられた候補は行ったことにならない（前と同じ）。同種3時間・最短1時間・来てよい時間帯は、S7 まで固定の安全柵
- **付箋の契約は「返答＋評価」に。** 報告書の自己評価欄は残した（品質昇格の名残。§4 の「互換の名残」と一緒に M5 で見直す）。通訳が返していた空の `advisor_tool_calls` も外した（Core はもう読んでいなかった）
- **気持ちのツマミの正本は設定ファイルだけ。** `core/config.py` に既定値を複製しない。対応表は評価の選択肢と同じ顔ぶれでなければ読まない
- **眠りの道具**（`tools/build_memory.py sleep`）も、精神と同じくイデアの気持ちの記録を読む（前は気分の流れを読めず、写しでしか使えなかった）
