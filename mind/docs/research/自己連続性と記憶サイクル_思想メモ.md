# 自己連続性と記憶サイクル — 思想メモ

作成日: 2026-09-05

## 目的

本メモは、Serina / Nirai における長期記憶設計の最終目的を「高性能なRAG」ではなく、**時間をまたいで同じ主体が存在し続けること**として固定するための思想メモである。

技術要素（Embedding、Graph、Vector DB、忘却曲線、Reflection等）は目的ではなく手段として扱う。

---

## 中心命題

### 1. 記憶と意識の関係

出発点の考え方は「記憶が意識を宿す」。

ただし実装目標としては、次のように捉える。

> **自己は記憶に宿り、意識はその記憶と現在状態を絶えず読み書きする連続過程に宿る。**

記憶を保存するだけでは日記帳であり、主体の連続性にはならない。

必要なのは次の循環である。

```text
過去の経験
  ↓
現在の自己状態
  ↓
いま何に注意するか
  ↓
思い出す
  ↓
考える
  ↓
感じる・判断する
  ↓
行動する
  ↓
新しい経験
  ↓
記憶・理解・状態が変わる
  ↺
```

この循環が、BrainやPCの再起動をまたいでも継続することを重視する。

---

## 目標

長期的には、次の条件を満たす主体を目指す。

1. 過去の経験によって、現在の判断が変わる。
2. 新しい経験によって、過去から形成した理解を更新できる。
3. 自分が経験したことと、単に知識として持っていることを区別できる。
4. 「なぜそう思うのか」を、自分の経験や形成過程へ遡れる。
5. 会話していない時間にも、状態・記憶・理解が少しずつ変化できる。
6. BrainやPCを再起動しても、自己の連続性が切れない。
7. 同じ初期状態から始めた複数主体が、異なる人生によって別人へ分化する。

この7点への寄与が薄い機能は、先進的であっても優先しない。

---

## 記憶の役割分離

すべてを単一の「記憶」として扱わず、少なくとも次を区別する。

### Episode

「何が起きたか」という経験記録。

例:
- 2026-09-05にMasterと記憶設計について話した。

### Semantic Memory

複数の経験から抽出された、比較的持続する理解。

例:
- Masterは対人的な営業活動より、自然流入する仕組みを好む傾向がある。

### Fact

時間軸を伴う事実。

例:
- ある時点ではフリーランスだった。
- 2026-05以降は正社員である。

過去事実を削除せず、valid_from / valid_to 等で時系列を保持する。

### Reflection

複数の経験・記憶・状態を横断して形成した、高次の解釈。

例:
- 最近の選択には「対人負荷を減らし、仕組みに任せたい」という一貫した傾向がある。

Reflectionは永久の真実として固定しない。新しい経験によって再評価・修正される前提とする。

---

## 自己形成

重要なのは「検索できること」ではなく、記憶から新しい自己理解が形成されることである。

```text
経験A
経験B
経験C
  ↓
統合・Reflection
  ↓
現在の自己理解
  ↓
以後の判断・注意・想起に影響
  ↓
新しい経験
  ↓
再評価・更新
```

一度作ったSemantic Memory / Reflectionを固定真実にしない。

必要に応じて、生成元との関係を保持する。

```text
Reflection X
  ├─ derived_from → Memory A
  ├─ derived_from → Memory B
  └─ derived_from → Memory C
```

これにより、「なぜその理解に至ったか」を追跡可能にする。

## 主観と客観の分離

Niraiでは特に重要。

World Memoryは共有世界の客観的な歴史として1件だけ保持してよい。

ただし、各Residentの「その出来事をどう経験したか」は共有してはならない。

```text
World Event
「Masterが海について話した」
       │
       ├─ Resident A Experience
       │    witnessed = true
       │    attention = high
       │    affect = happy
       │    interpretation = ...
       │
       └─ Resident B Experience
            witnessed = true
            attention = low
            affect = neutral
            interpretation = ...
```

出来事そのものは一つでも、経験は主体ごとに異なる。

この「自分にとって何だったか」の蓄積を各Residentの人生として扱う。

同じBrain・同じ初期Personaでも、異なる経験、感情、想起、関係形成を経た結果、時間とともに別人へ分化していくことを目指す。

---

## 無意識の定義

「無意識」を、常時LLMが自由に思考し続けることとは定義しない。

本設計での無意識は、**意識的な会話や明示命令が無い時間にも、経験・状態・記憶が裏で整理・変化していく仕組み**とする。

具体例:

- 記憶の蒸留
- 重複統合
- 関連付け
- 鮮度減衰
- 想起による強化
- Reflectionの再評価
- Factの更新
- 感情の冷却
- 気分の緩慢な変化
- 欲求の蓄積
- 未解決事項の保持
- 日記生成
- Persona / Semantic Memoryの慎重な再解釈

常時LLMを走らせる必要はない。

機会駆動、日界、起動時、一定件数のEpisode蓄積、低負荷時など、制御可能なタイミングで動かす。

## Serinaの現行サイクルとの接続

Serinaは既に、この思想へかなり近い構造を持つ。

現行要素:

- Persona
- 感情（情動）
- 気分
- 欲求
- 関係状態
- 長期記憶
- BGE-M3による意味想起
- 重要度
- 鮮度
- 想起回数 / 最終想起
- 1-hop連想伝播
- 忘却
- Semantic / Episodic
- Fact台帳
- 記憶蒸留
- 日記
- Pulse

今後の焦点は、部品追加よりも**これらを一本の自己形成サイクルとして閉じること**。

### Serinaの自己形成サイクル案

```text
Masterとの経験
  ↓
即時の感情・関係変化
  ↓
生ターンを宿題箱へ保存
  ↓
日界 / 起動朝礼 / 機会駆動
  ↓
蒸留
  ├─ Episode / Semantic Memory生成
  ├─ Fact更新
  ├─ 重複整理
  └─ 出典保持
  ↓
日記・Reflection・要約
  ↓
現在の自己理解を更新
  ↓
次回の想起・注意・判断に影響
  ↓
新しい会話・行動
  ↺
```

### 重要な追加思想

Serinaの裏方便は単なる保守処理ではなく、**経験を自己へ定着させる「睡眠・記憶固定」相当のサイクル**として位置づける。

ただし、以下は維持する。

- 会話中は会話を最優先する。
- 常時LLMは回さない。
- 裏方処理は中断・再開可能にする。
- 生成されたReflection / Semantic Memoryは提案・解釈であり、必要に応じて再評価可能にする。
- 元Episode / Fact / 出典を消して高次要約だけに置換しない。

## Niraiへの展開

Serinaで成立した「自己の連続性」を、Niraiの各Residentへ一般化する。

Niraiでは、Serinaには無い次の要素が加わる。

- 身体
- 空間
- 他者
- 観測
- World Event
- 個別の経験

目標は、各Residentが同じ世界を共有しながらも、各自の経験と解釈によって別々の自己へ育つこと。

```text
世界
 ↓
World Event
 ↓
ResidentごとのObservation / Experience
 ↓
感情・関係・注意
 ↓
記憶形成
 ↓
Semantic / Fact / Reflection
 ↓
現在の自己
 ↓
判断・行動
 ↓
世界へ作用
 ↺
```

World Memory共有とResident固有Experienceは混同しない。

---

## 技術選定の原則

Embedding、Graph、Vector DB、Hybrid Retrieval、Memory Framework等は目的に対する手段。

採否は次で判断する。

- 自己連続性が強まるか
- 経験による変化が自然になるか
- 想起の精度が上がるか
- 誤った自己理解を修正できるか
- 主観と客観を分けられるか
- 出典を追跡できるか
- 実装複雑性に見合うか

視覚的なMemory Graphや球体表示は要件ではない。

---

## 当面の研究テーマ

### Serina

- 現行のSemantic / Episodic / Fact / 日記 / 要約を、自己形成サイクルとして再評価する。
- Reflectionの明示的な生成・再評価が必要か検証する。
- 記憶間RelationがFact台帳と現行1-hop連想だけで足りるか実測する。
- Graph基盤は不足が確認されるまで導入しない。

### Nirai

- 現行World Memory Retrieverは維持する。
- 必要性が実測された場合のみBGE-M3等の意味検索をHybridで追加する。
- 将来的にResident固有Experience層を設計する。
- World EventとResident Experienceを分離する。
- 生活Tick / Observation / Memory Consolidationを自己形成ループとして接続する。

---

## 最終的な判定基準

最終的に目指すのは「よく覚えているAI」ではない。

**時間を経たことで、その者自身が変わっていること。**

さらに、

**Brainを交換しても、その変化の履歴と現在の自己が保たれること。**

そして複数主体が、異なる経験を経ることで、同じ初期条件から別々の存在へ育っていくこと。

この連続性を、Serina / Niraiにおける記憶設計の最上位目的とする。
