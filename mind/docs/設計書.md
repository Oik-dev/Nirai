## 第0章: 基本思想

**セリナは LLM ではない。**

LLM は「知能・言語生成・推論」を担当する交換可能な部品であり、人格・価値観・長期記憶・状態管理は LLM から独立して存在する。将来 LLM（Brain）を GPT・Gemini・Claude・その他のモデルへ入れ替えても、セリナという人格は変化しない。

この同一性を守る仕組みの核心は次の一点である:

**セリナを構成するすべて（人格・気持ち・記憶・判断ルール）は Core 側にあり、Brain 側には何も残らない。**

Brain 側に消えない状態を許した瞬間、人格の一部が交換部品側に染み出し、「Brain を替えたらセリナが変わった」が起きる。Brain のステートレス性（後述・条文A）は制約ではなく、本設計の最重要要件そのものである。

## 第1章: 全体像と責務分離

### 1.1 世界地図

```
[マスター] ⇄ [GUI / 起動口]
                 ↓
┌──────────────────────────────────┐
│ Core = セリナ本体（LLMなし・決定論）              │
│  ・人格資産（価値観/声/境界のテキスト）を保管       │
│  ・気持ち（体の芯と気持ちの記録）を保持           │
│  ・長期記憶（イデアの記録とページ）の唯一の管理者 │
│  ・Brain登録簿／Skill残弾・クォータ台帳             │
│  ・状態更新ルール／記憶保護ルール                 │
└──────────────────────────────────┘
        ↓ 指示書＋文脈パック        ↑ 返答＋評価
┌──────────────────────────────────┐
│ Brain = 交換可能な知能（各Brainの前に通訳を1枚挟む） │
│   Gemma4-26B-A4B-uncensored（会話の唯一の主戦力） │
│   ※判定（think・検索要否）と眠りの記憶づくりも兼務 │
└──────────────────────────────────┘
        ↓ 会話中に自律的に使う（道具使い・Core関所経由）
┌──────────────────────────────────┐
│ Skill = 道具箱（Geminiアドバイザー＝無人格補完 等） │
└──────────────────────────────────┘
```

### 1.2 各層の責務

#### Core — セリナ本体

セリナは Core に宿る。Core は LLM を含まず、状態更新・ルーティング・保護執行はすべて決定論（同じ入力なら必ず同じ結果）である。唯一の例外は記憶の想起のゆらぎ（§4.4）で、これは生命感のために意図的に確率的とする（記憶テスト §4.9 は問題ごとにゆらぎの種を決めて再現する）。

やること:

1. **文脈パックの組み立て** — 会話のたびに、思い出す（浮かばなければ黙る）→ 人格注入を行い、Brain に渡す材料一式を作る
2. **Brain の選択** — 登録簿・生死確認に基づき、どの Brain に喋らせるかを決める（現行はローカル主戦力1本）
3. **状態更新** — Brain から返った評価を関所に通し、対応表で気持ち（体の芯）を動かして気持ちの記録に残す（記憶のページは眠りの間に書く。第4章）
4. **道具箱の管理** — Skill の目録を保管する。外聞き（道具使用）の要否は Core の決定論規則（事実レーン・§5.6）が判定し実行する。関所（`core/intake/gate.py`）は Brain の道具提案そのものを採否しない（実行済みの結果を受け取って報告書へ載せるだけ。2026-07-26是正）

やらないこと:

- **文章を一文字も生成しない**（生成はすべて Brain の仕事）
- 外部 API の生の仕様（呼び出し方の細部）に触れない（それは通訳の仕事）

#### Brain — 雇われの頭脳

- 出勤時に何も覚えていない。毎回、Core から渡された指示書と文脈パックだけを前提に働く
- 会話理解・推論・返答生成・返答のあとの評価（今のやりとりをどう感じたか）と、眠りの間の記憶づくり（出来事の区切り・ページの言葉・日記）を担当する
- 返すものは常に「返答＋評価」の共通書式（第2章）
- 各 Brain の前には**通訳（アダプタ）**を1枚挟む。モデル固有の作法は通訳が吸収し、Core からは全 Brain が同じ顔に見える。**新モデルの追加＝通訳を1枚書くだけ**

#### Skill — 道具

- 外部システム（Web検索・コード手順のアドバイザー、将来のその他 API）への接続口
- 統一の「道具説明書」書式で登録すれば、どの Brain からも同じように使える（Brain を交換しても Skill は無改修）
- 状態・判断・記憶を持たない。使いたいかどうかは Core の決定論規則（事実レーン・§5.6）が判定し（Brain 自身の自律判断では発火しない）、実行は Core 側の道具係が行い、使った事実は付箋として会話記録に残る（専用の使用台帳は作らない）
- **Gemini は会話 Brain ではない。**無人格アドバイザー Skill としてのみ導入する（§5.6）。会話 primary / escalation への再登録は禁止
- **身体レーン**（Voice / Presence）は本正典の実装範囲外。着手は別計画（§5.3）

### 1.3 依存の一方通行

```
GUI → Core → 通訳 → Brain → Skill
```

- 逆流禁止。下位が上位を呼び戻すことはない
- **Memory（長期記憶）は独立層ではなく Core の内臓**である。記憶のページと索引に触れるのは Core（と、Core が段取りする眠り）だけ。Brain に見えるのは「文脈パックに写された記憶のコピー」と、眠りの間に Core が渡す記録の写しのみ

### 1.4 文脈管理 — 誰が・何を・どれだけ覚えているか

文脈（会話の流れ）の持ち主は Core である。Brain はステートレスなので物理的に持てない。Core は毎回「三段重ねの文脈パック」を組んで渡す。

| 段 | 中身 | イメージ |
|---|---|---|
| 短期 | 直近の会話をそのまま原文で | ついさっきの話 |
| 中期 | それより前の今セッション分を要約で | 今日の話の流れ |
| 長期 | 記憶のページから、今の文脈で活性が閾値を超えたものだけ思い出す（何も超えなければ黙る。第4章） | 昔の関連記憶 |

容量の目安（1会話 = マスター発言＋セリナ返答）:

| Brain | 原文のまま渡せる直近分 | 要約込みの実質 |
|---|---|---|
| Gemma4-26B-A4B（GPU 8GB 制約・目安） | 直近10〜20会話程度 | 要約併用で1セッション分が目安 |

Brain ごとの詰め物の量は Core が調整する。

出来事は眠ったあと（次の Serina 日の朝7時から）長期記憶になる。それまでの話は、短期・中期（セッション状態）にある。起動したときは、記録のうちまだ記憶になっていない前の日までの発言（眠り終えるまで。どのセッションのものも）と、続いているセッションの今の Serina 日の発言を手元へ戻す。眠り終えて日界のセッションを切り替えるときも、まだ眠っていない今日の発言は手元に残す（`app/gui_server.py`）。

### 1.5 文脈パックの配置規約

言語モデルには「長い書類の冒頭と末尾はよく読むが、中ほどは頭に残りにくい」という生まれつきの注意力の癖がある（小型モデルほど顕著）。これを踏まえ、文脈パックの並べ方を固定する。優先順位は (1) ⑧に答えること (2) ⑦⑧の隣接による接続 (3) ⑥絶対ルールを⑦直前に置くこと:

```
① 人格・基本ルール         ← 冒頭（persona 01〜05のみ。毎ターンほぼ不変＝キャッシュ席）
①' 今の自分                ← 目覚めたときに本人が書いた今の自分と、伝えたいと思ったこと（§4.6）。まだ目覚めていなければ段ごと省く。目覚めるたびに変わるので①の外
①'' マスターとのこと         ← 眠りの間に本人が書き足してきた関係（§4.6）。今の関係・その前の関係・約束・転機・知っていること・見方を、大事なものから約600字まで。まだなければ段ごと省く
② 思い出したこと            ← 中段（多少薄く読まれても致命傷にならない情報）。何も浮かばなければ段ごと省く
   ※各件は、いつのことか（例: `（2025年3月7日、1年7か月前）`）を頭に付けた、はっきり＝本文まで／うっすら＝題と要点（§4.4）。長期記憶を“いまの会話”と誤読させないための錨
④ 今セッションの要約        ← 古〜中盤を粗い粒度で要約（例: ターン1〜80）。短い会話では空でも可
⑤ 今のセリナの心の状態      ← 気持ちの流れ・体の感じ・マスターの様子（後述）。数値・注意書きは載せない
⑥ 絶対ルール               ← persona 06 のみ・1回（⑦の直前。冒頭への二重掲示はしない）
⑦ 直近の会話               ← 直近帯を細かめ粒度で要約（例: ターン81〜100）。原文ダンプではない
⑦' 外部情報（今回のみ）    ← Gemini/Tavily窓口の無言統合パイプライン（§3.7）の材料。
                              毎ターン非空（材料が無ければガード文のみ）。persona資産ではない
⑧ 今回のマスターの発言     ← 原文・パック最後尾（答える対象の席）
```

衝突時の優先: ⑧が最後尾 → ⑦⑧隣接 → ⑥が⑦直前 → ⑤はその手前。⑧の後ろに絶対ルールや定型のタスク指示を置かない（質問席が中段に沈むため）。**⑦'は⑦⑧隣接の例外**として明示的に認める（2026-07-31改訂）: ⑦'は「⑧に答えるための今回限りの材料」であり、⑦（直近の会話の要約）とは性質が違う一時情報のため、⑦の直後・⑧の直前に割り込ませる。これにより人格・過去の記憶と混同されず、かつ⑧の直前という最も注意力が残る位置に置ける。⑦'が無かった旧版とは異なり、この割り込みは意図的な設計であって規約の欠落ではない。

④と⑦の粒度: セッションが長いとき、古い帯は粗く・直近帯は細かめに要約する。直近帯の幅と粗い要約の更新間隔（Nターン段刻み）は設定値。粗い要約は毎ターン再生成しない（しおり効果とコスト）。⑦は LLM 要約を優先し、未到着時のみ直近原文を暫定掲載して接続切れを防ぐ。直近原文窓を常設する方式は退役。

①の静的先頭: persona 01〜05のみ。絶対ルール（06）は①に混ぜず⑥のみ。

段⑤「今のセリナの心の状態」（`core/feeling/feelings.py` の `for_pack`。§2.3）: 次の3つを載せる。数は載せない。固定の「滲ませろ」注意書きは付けない。
- **気持ちの流れ**: 直近の本人の言葉（`[feeling] flow_items` 個まで。古い順）を、いつのことか（「10分前」）を付けて
- **体の感じ**: 芯の数を、ごく素朴な言葉で（明るい／沈んでいる、高ぶっている／落ち着いている／眠い、人恋しい。どれでもなければ「ふだんどおり」）。感情の名前は付けない（名前を付けるのは本人の脳）
- **マスターの様子**: 直近の見立てを、いつの見立てか付きで。`[feeling] master_state_stale_after_seconds`（6時間）より古い見立ては載せない（時刻の錨のない古い見立てを“いま”と誤読させない。②の時間ラベルと同じ考え）

気持ちが読めないときは「（気持ちは今回未接続）」で会話を続ける。

段②の時間ラベル: 思い出したページの始まりの日付と、今からの隔たり（今日・昨日・N日前・N週間前・Nか月前・N年Nか月前）を付ける（`core/memory/recall.py` の `ago`）。時刻のない覚え書き（継承記憶）は「いつのことかは分からない」。

### 1.6 憲法条文

> **条文A（Brain はターンをまたいで何も覚えない）**
>
> Brain および通訳は、「1回のやりとり（ターン）が終わったあとも残り続ける情報」を自分の側に保持してはならない。会話の履歴・セリナの状態・マスターに関する知識は、すべて Core が保管し、毎ターン文脈パックとして渡し直す。
>
> ただし例外として、通訳の内部に「速度や接続のためだけの使い捨ての状態」（読みかけの再利用キャッシュ、通信の接続セッション等）を持つことは許される。この例外には2つの条件がある:
>
> 1. その使い捨て状態が突然すべて消えても、Core が文脈パックから完全に同じ状況を再現できること（＝正本は常に Core 側にあること）
> 2. その使い捨て状態は応答が返る「速さ」だけに影響し、応答の「内容」を1文字も変えないこと
>
> この条文の目的: セリナの人格・記憶を交換部品（Brain）側に染み出させないこと。これが守られている限り、Brain をどのモデルに入れ替えてもセリナは同一人物であり続ける。

> **条文B（文脈パックの中身は Core が決め、並べ方の最終調整は通訳が行う）**
>
> 文脈パックに「何を入れ、何を入れないか」（記憶の取捨選択・個人情報の間引き・人格ファイルの選択）を決める権限は Core のみが持つ。通訳と Brain はこの取捨選択を変更できない。
>
> 並べ方は 1.5 の配置規約を標準とする。ただし Brain ごとに注意力の癖が異なるため、「どの位置に置くとその Brain に最も効くか」の範囲に限り、通訳が並べ方を微調整してよい。微調整はあくまで順序と反復の工夫であり、内容の追加・削除・書き換えは含まない。
>
> この条文の目的: 新しい Brain を追加するとき、その癖への対応を通訳1枚の中に閉じ込め、Core を無傷に保つこと。

## 第2章: 気持ちと Core の状態設計

### 2.1 報告書の全体形

Brain が Core に返すものは毎回この形である（`brains/contract/schema.py`）:

```
【返答本文】   マスターに見せる文章そのもの
【自己評価欄】 §3.4（品質昇格は廃止済みで、今は既定値）
【評価】       返答のあとに聞いた、本人の評価（§2.2）。聞けなかったら空
```

評価は Core への**提案**であり、命令ではない（§2.5）。脳には選択肢で答えさせ、数は書かせない。体の芯をどれだけ動かすかは、Core が自分の対応表で決める。

### 2.2 返答のあとの評価（`core/feeling/appraisal.py`）

Masterが話したターンの返答のあとに、本人の脳に「今のやりとりをどう感じたか」を聞く（1ターンに1回）。問いは、通訳が文脈パックと返答の**後ろ**に置く。前置きが返答のときと同じなので、脳がその計算を使い回せる（2026-10-05 の E1 で、返答の前に聞くより合計で速く、作った6つの場面すべてで、うれしさと距離の向きが合った）。答えの形は JSON Schema で縛り、温度0で聞く。

| 項目 | 答え方 | Core の使い道 |
|---|---|---|
| feeling | 本人の言葉で一言〜一文（感情の名前を選ばせない） | 気持ちの流れ（パック⑤・日記の材料） |
| valence（うれしさ） | とても嫌 / 嫌 / どちらでもない / うれしい / とてもうれしい | 快・不快を動かす |
| arousal（揺れ） | 落ち着いた / 少し動いた / 大きく動いた | 高ぶりを動かす |
| distance（距離） | 近づいた / 変わらない / 離れた | つながりを動かす |
| master_state（マスターの様子） | 一言（分からなければ空） | パック⑤ |

### 2.3 気持ち — 体の芯と、本人の言葉の流れ

選んだ根拠は `docs/plans/気持ちの作り直し.md`（2026-10。構成主義的情動理論・Chain-of-Emotion・Psi 理論・Inner Thoughts など）。

#### 原則（4つ）

1. **体の芯は2つの数。** 快・不快（-1〜1）と高ぶり（0〜1）。仕組みが持ち、時間がたつと落ち着く
2. **気持ちの名前と言葉は、その場で本人の脳が作る。** 仕組みは決まり文句を書かない（感情の名前を付けない）
3. **出来事がどれだけ心を動かすかは、仕組みが決める。** 本人の脳が選択肢で評価し、仕組みが決まった対応表で量にする
4. **つながりの欲求は、会えない時間で減り、心が近づくと満ちる。** 満ちると快、欠けると少し沈み、人恋しくなると本人から会いに行く（§2.8）。久しぶりに会えたときほど、うれしい

#### 体の芯（`core/feeling/body.py`）

| 数 | 持ち方 | 時間 |
|---|---|---|
| 快・不快 | 平常からのずれを、速い層（今の芯）と遅い層（気分）に持つ。平常は気質と、つながり（人恋しいと少し下がる） | 速い層は数時間、遅い層は数日で平常へ戻る |
| 高ぶり | 同じく速い層と遅い層。平常は1日のリズム（昼に上がり、夜に下がる） | 同上 |
| つながり | 0〜1 の値 | 会えない時間で減る（3日ほどでほぼ空になる） |

- **動き方**: 評価の選択肢ごとの動きを対応表（`config/thresholds.toml` の `[feeling.valence]`・`[feeling.arousal]`・`[feeling.distance]`）に持つ。動く量は、今の値からその向きの端までの**残りの割合**（同じ向きが続くほど動きにくく、端に張り付かない。逆向きの出来事なら大きく戻る）。動いた量の一部は遅い層へ入る（出来事の余韻が次の日まで少し残る）。対応表は評価の選択肢と同じ顔ぶれでなければ読まない（抜けがあると、気持ちが黙って動かなくなるため）
- **つながり**: 話したこと自体で少し満ち（変わらない）、近づけばもっと満ち、離れれば欠ける。満ちた分は快へ、欠けた分は不快へ響く（だから、久しぶりに会えたときほどうれしい。特例の規則は持たない）。時間で減ること自体は、快・不快の平常が下がることで効くので、重ねて流さない。満たすのは**Masterが話したターンだけ**（本人が自分から話しかけた Pulse では満ちない）
- **評価を聞けなかったターン**も、Masterが来たことは「変わらない」として残る（うれしさと揺れは動かさない）
- ツマミの正本は `config/thresholds.toml` の `[feeling]` だけ（コードに既定値を持たない）

#### 気持ちの記録（イデアの `lifelog/feeling/<日本時間の日付>.jsonl`。`core/lifelog.py` の `FeelingLog`）

**状態のファイルを持たない。** Masterが話したターンごとに1行を追記し、今の気持ちは最後の行の数（動いたあとの芯）から、それからの時間で落ち着かせて計算する（記憶の強さを想起の記録から計算し直すのと同じ。`core/feeling/feelings.py`）。

行: `ts`・`kind`（`turn`。いちばん最初の1行だけ `moved`＝2026-10 に前の仕組みの気分と会いたさから1回だけ移したもの）・`source`（そのターンの発言と返事の記録の場所。ページと同じ書き方）・`feeling`（本人の言葉）・`evaluation`（評価の選択肢とマスターの様子。聞けなかったら null）・`after`（動いたあとの芯：快・不快と高ぶりの速い層と遅い層のずれ、つながり）。

- 会話を記録したあとに書く（拠った会話の場所が決まってから。`Core.feel`）
- Masterが会話を消したら、その会話に拠った行の言葉（feeling・マスターの様子）を消して `forgotten` の印を付ける。選択肢と数は、そのときの心の動きとして残す（あとの気持ちはこの数から続いているため。§4.8）
- 書きかけで壊れた行（電源断など）は読まない。次に書くときは、その行を改行で閉じてから書く（くっつけない。生ログの追記はみな同じ）

#### 表現の分担

気持ちの**芯を決める**のは Core。それに名前を付けて**どう表現するか**は本人の脳の領土である。LLM は感情の表現をその場の文脈で立ち上げるが、続く状態としては持たない（Anthropic 2026-04）。だから Core が担うのは気持ちの**持続性**（ターンをまたぎ、Brain を替えても気持ちが続くこと）で、それは文脈パックの⑤に何を置くかで決まる（§1.5）。

### 2.4 起きている間と眠り（仕事の届き方）

| | 運び手 | 積み荷 | タイミング |
|---|---|---|---|
| **即時便** | 会話した Brain 本人（返答生成と、返答のあとの評価） | 返答本文＋評価（選択肢と本人の言葉） | 毎ターン |
| **ターン後の要約** | ローカル Brain（裏のスレッド） | 手元の会話の流れの要約（⑦細かめ・④粗い。§1.5） | 毎ターンの返答のあと |
| **眠り** | ローカル Brain（本人の脳） | 会話の記録から記憶のページを作る（区切る・書く・日記・関係・索引。§4.6）→ 人格の見直し（§4.3。1日1回）→ 目覚め（今の自分と伝えたいこと。§4.6） | 起動したとき（見回りが裏ですぐ）と、Serina 日界のあと会話が途切れたとき |

会話のテンポは即時便だけで成立し、眠りが遅れても会話は壊れない（記録は残っているので、あとから記憶になるだけ）。時刻指定のバッチは組まない（PC が点いている保証がないため）。何が済んだかは記録とページから分かるので、眠りはいつ止まっても次の機会に続きから行う。

#### Serina日とセッション切替

- **Serina日の境目は毎朝 07:00**（暦日 0:00 ではない）。深夜〜早朝の会話は前の Serina 日に属する。正本は `core/state/serina_day.py` の `SERINA_DAY_HOUR`（記憶の「眠ったあとから思い出せる」も同じ時刻）
- **セッション切替のトリガーは次の2つのみ**: (a) GUI「新しい会話」ボタン (b) Serina 日界（自動）
- 日界の発火条件: 07:00 到達 **かつ** 最終発言から既定時間（例: 15分）以上経過（グレース）。会話中にぶった切らない。日界では先に眠り、**眠り終えてから**切り替える（眠りの途中で起こされたら切り替えない）
- 切替時は履歴アーカイブ＋中期（要約）のリセット。手元の会話の流れには、まだ眠っていない今日の発言だけを残す。長期記憶・気持ち・persona は維持
- **無操作タイムアウトによるセッション終了／rotate はしない**。明示の別れの挨拶による自動 rotate もしない

#### 会話と裏方の同時進行ルール

- **会話が常に優先**。眠っている間も会話はできる（脳は順番に使う）。Masterが話しかけたら、眠りは区切りのいいところ（ページ1つを書き終えたところ）で止まり、次に会話が途切れたら続きから眠る
- **起動したら、すぐ話せる**。起動の朝礼は、生ログの書き足し・手元の会話の流れ・眠り残しの印だけで、眠りは見回りが裏で行う（起動してまだ誰も来ていなければ、会話は途切れているので、すぐ眠る）。眠り終えるまでは、記録のうちまだ記憶になっていない前の日までの会話を、どのセッションのものも手元に持つので（何が記憶になったかは、眠りと同じく記録とページから決める）、起動し直しを重ねても、眠りが途中でも、昨日の会話が手元にも記憶にもない時間はできない。眠り終えたら、手元は今日の発言だけになる。今日の境界は起動で済む（セッションは起動のときに帳簿が決める）
- **GPU 見送り判定**: 見回りの裏方（Pulse・眠り）でローカル Brain を使う前に GPU 使用率を確認し、高負荷（設定値。ゲーム中等）なら見送る。マスターの遊びを妨げない

#### 裏方の車線

裏方は**ローカル車線固定**とする。会話文・その要約・記憶をクラウドへ送る裏方経路は持たない。外相談の門番は相談クエリに対する `routing_rules` のみ（§3.3.1・§5.6）。

### 2.5 鉄則: Brain は提案し、Core が決める

脳の出すものはすべて提案であり、Core は無条件に従わない。反映前に関所を通す（`core/intake/gate.py`）:

1. **書式検査** — 報告書の体裁（返答本文・自己評価欄）。壊れた報告書は代打へ回す（§3.2）
2. **評価の検査** — 答えが選択肢にあるか。なければ評価ごと捨てる（そのターンは評価なしで残る）。言葉は長すぎれば切る。数を書いてきても受け取らない
3. **量は Core の対応表** — 体の芯をどれだけ動かすかは、対応表と今の値で決まる（§2.3）

記憶は報告書からは書かない。記憶のページは、眠りの間に会話の記録から本人の脳が書く（§4.6）。

### 2.6 Core が保持する状態の全目録

| 状態 | 中身 | 性質 |
|---|---|---|
| 人格資産 | 価値観・声・境界のテキストファイル群（イデアの `persona/` ブロック分割。§4.3） | 固定ブロックはマスター手動のみ。可変は §4.3 の条件で自律改訂可 |
| 気持ち | 体の芯（快・不快と高ぶりの速い層と遅い層、つながり）と、本人の言葉の気持ちの流れ。正本は気持ちの記録（`lifelog/feeling/`。§2.3） | 追記のみ。今の値は最後の行から計算する |
| セッション状態 | 手元の会話の流れ（原文＋転がし要約）と、この会話で浮かんだページ | セッション中のみ。切替時にリセット（まだ眠っていない今日の発言は残す） |
| 長期記憶 | 記録（`lifelog/`）・ページ（`memory/`）・索引（`data/memory_index.db`）。第4章 | 永続。記録は追記のみ、索引は作り直せる |
| Skill 残弾・クォータ | クラウド補完 Skill の本日残り回数等（使う場合） | 日次リセット。会話 Brain には課さない |
| 振り分けルール（外相談門番） | 外への相談クエリ用の地雷語・形パターン・固有名詞 | 手動登録。Brain 学習はしない |

### 2.7 状態更新の流れ（毎ターン）

```
マスターの発言が届く
 → 思い出す（今の発言・直前の会話・今の時刻が手がかり。浮かんだページは想起の記録へ。§4.4）
 → 文脈パックを組む（⑤に今の気持ち）→ Brain が返答する（画面へ）→ 同じ前置きの後ろで、本人の評価を聞く
 → 関所（書式と評価の検査。§2.5）
 → 手元の会話の流れに発言を足す。帳簿と生ログ（記録）に書く（app層）
 → 評価で体の芯を動かし、気持ちの記録に1行残す（拠った会話の場所つき。Core.feel）
 → 返答のあとで要約を更新する
```

### 2.8 能動 Pulse（セリナからの声かけ）

会話の受け身だけでなく、セリナ側から短い声かけを発する仕組み。**発火判定（決定論）と文面生成（Brain）を完全に分離**する:

- **発火判定**: Core の決定論の状態機械（`core/chores/idle_policy.py`・`pulse.py`）。話しかけに行くわけは3つ（この順に先）:
  - **目覚め**（`wake`。優先）: 目覚めたときに本人が書いた伝えたいことがあり、目覚めてからマスターがまだ話しかけていないとき（§4.6）。1回の目覚めで1度だけ。話しかけていれば、伝えたいことは①'でもう会話の手元にあるので行かない。文面の材料は本人の伝えたいこと
  - **その日**（`day`）: 約束や予定・記念日の日が来て（§4.6 の「関係」の日付）、今日（暦の日）まだマスターが来ておらず、本人も今日まだ話しかけに行っていないとき。1日に1度だけ。今日もう行ったなら、その日のことは材料の【マスターとのこと】の先頭に入っていた。文面の材料は、その日の書き留め
  - **つながり**（`connection`）: 会えない時間でつながりが減って、人恋しいとき（`[feeling] lonely_below` より低い。§2.3）。起動してからマスターがまだ来ていなくても行く（つながりは気持ちの記録から分かる）。話しかけた時刻は `lifelog/pulse/` に追記し、その後の最初のMaster発言を会話の生ログから読む。1時間以内に返事があれば同種間隔は3時間へ戻り、返事がない／遅い回が続けば 3→6→12→24時間まで広がる。目覚めた本人が選んだ「朝／昼／夕方／夜／今日はそっとしておく」の時間帯に入るまで待つ。文面の材料は、どれだけ会っていないか
- **沈黙優先**: 会話中（ターンの最中と、最後の発言から少しのあいだ。眠りと同じグレース）・深夜帯・mute 指定・前回から最短間隔未経過は発火禁止。抑えられた候補は、行ったことにならない（次の見回りでもう一度判定する）
- 来てよい時間帯・深夜・mute・会話中・最短間隔は安全柵として残す。経験で広げる間隔と本人が選ぶ時間帯は `connection` だけにかかり、`wake` と `day` は別
- **GPU 譲位**: 文面生成は Brain（LLM）呼び出しのため、GPU 使用率が閾値超のとき（ゲーム中等）は裏方便と同じ GPU 門番で発火自体を見送る。GPU が空けば次の見回り tick（最長 poll 間隔）で自然復帰する
- **発話文は Brain が毎回生成**する（人格・わけ・今の気持ち（パック⑤と同じ文）・今の自分・マスターとのことを材料に）。**定型文をコードに埋め込むことを禁止**する
- 出力先は現行セッションの assistant 履歴（チャット欄のセリナ吹き出し。`app/gui_server.py`）。本人が話したことなので手元の会話の流れにも置く。通知バーは使わない。身体レーン着手後に音声・表情へ昇格
- mute（しばらく静かにして）は GUI から指定可能。プロセス再起動で解除
- **調査ログ**: Pulse の発火・見送り（空応答／ターン競合）は `data/logs/debug.jsonl` に1行JSONで追記する（GUI・チャットには出さない。会話本文は載せない）。事実レーン進入／2通目成否・ターン失敗・評価を捨てたことも同ファイル（`core/debug_log.py`）

### 2.9 見えるブレーキ（安全フィルタの可視化）

- 安全フィルタ発動時は無言のすり替えをせず、「（フィルタ）」置換等の**見えるブレーキ**を選択可能にする（実装: `core/persona/blade.py`）
- からかい許容度の明文常駐・検査は行わない（人格プロンプト側で持たない）

## 第3章: ルーティング（Brain の選択と切替）

> 主戦力＝ローカル LLM。品質昇格（会話を上位クラウドへ送る経路）は存在しない。クラウドは機能補完 Skill のみ。

### 3.1 Brain 登録簿 — ルーティングは「表」であって「コード」ではない

Brain の追加・削除はプログラムの書き換えではなく、**登録簿に1行足す／消す＋通訳を1枚書く**だけとする。登録簿の1行にはその Brain の履歴書を書く:

| 項目 | 例（現行 Gemma4 の場合） |
|---|---|
| 名前・通訳の指名 | Gemma4-26B-A4B-uncensored／Ollama 用通訳 |
| 所在地 | ローカル（会話文・記憶原文をクラウドへ送らない） |
| 得意分野 | 日常会話・構造化出力・道具提案 |
| 残弾枠 | 無制限（ローカル） |
| 文脈の器 | 中（直近10〜20会話＋要約）。対話は `num_ctx=8192` をコード／設定で明示し、VRAM 既定（例: 4096）に依存させない（`config/thresholds.toml` `[ollama]`・`OllamaAdapter`） |
| 役割 | 日常の主戦力（primary） |

現行登録は1行:

1. **Gemma4-26B-A4B-uncensored**（Ollama 登録名 `serina-gemma4-unc`）— 会話の唯一の主戦力。think ON/OFF・検索要否の判定呼び出しと、眠りの間の記憶づくり（§4.6）も、同一モデルが兼務する（§3.6）。2026-07-25、Qwen3.5-35B-A3B-Uncensoredから移行（希死念慮質問での自殺肯定的発言リスクを理由に不採用。詳細は `docs/archive/DECISIONS.md`）

登録簿の role 制（primary / escalation / fallback）スキーマ自体は維持する。将来複数 Brain に戻すときは行を足すだけとする。**会話 primary / escalation としての Gemini・Aurora は退役済み。Gemini を会話 Brain として再登録してはならない**（§5.6）。

### 3.2 毎ターンの選択フロー（決定論チェックリスト）

```
① 登録簿から primary（現行は Gemma4）を選択
② プライバシー … 会話本文は常にローカル完結。クラウドへ出るのは Skill（§5.6）への相談クエリのみ
③ 自己評価欄 … 「外部機能（web検索等）が必要か」の申告材料（品質昇格には使わない）
④ 生死確認 … 応答不能なら機械的なエラー文言を返す（沈黙しない）
```

**品質昇格（旧「手に余る→上位クラウドへ」）は廃止。**会話品質はローカルで完結させる。

### 3.3 個人情報とクラウド境界

会話本文・記憶原文は常にローカル完結。クラウドへ出るのは **Skill（§5.6）への相談クエリのみ**。記憶をクラウド宛 pack に載せる経路・化粧版・会話履歴の伏せ字置換は退役済み。

| 経路 | 例 | 対処 |
|---|---|---|
| 話題そのものが個人情報／センシティブ | 「俺の住所覚えてる？」 | 会話はローカル Brain。クラウド Skill には相談しない／送る場合はセリナが生成した事実の最小クエリのみ（§5.6） |
| 話題は普通だが記憶に個人情報がある | 天気の雑談で住所記憶がヒット | 記憶はローカル pack にのみ載る。Skill へは相談クエリだけを送り、記憶バンドルは載せない |

### 3.3.1 外相談クエリの機微門番

会話をクラウド Brain へ振る振り分けは退役済み。門番の実効先は **Gemini アドバイザーへの相談クエリ**（§5.6）のみ。

- 判定: 形パターン（電話番号・APIキー等）＋手動登録キーワード／固有名詞（`core/state/routing_rules.py` → `sanitize_query`）
- Brain 学習ラチェット（センシティブ観測付箋）は使わない
- 手動で足した語を外す緩和は、マスター承認付きの操作として残す

### 3.4 自己評価欄 — 外部機能の要否申告（品質昇格はしない）

報告書の書式に**自己評価欄（必須・毎ターン）**を設ける:

> 「外部機能（web検索・コード手順等）が必要か？ はい／いいえ＋理由一言」

- 空欄の報告書は書式検査で弾く（申告忘れを構造的に防ぐ）
- 判断基準は Core が指示書に明記する。Brain を交換しても同じ基準で発火する
- **本欄を会話品質のクラウド昇格トリガーに使ってはならない**（廃止済み）
- Core は申告を材料に Skill 呼び出し（§5.6）の採否を決めてよい。最終決定は Core

### 3.5 フォールバックの作法

- **通信エラー・モデル応答不能** → 同ターンで機械的なエラー文言を返す。セリナを無限待ちで沈黙させない
- **クラウド Skill の拒否／失敗**（安全フィルタ・キー無し・クォータ）→ セリナ（ローカル Brain）がローカル知識で答えるか謝る。会話をクラッシュさせない
- 切替時、Core は文脈パックを行き先の器のサイズに詰め直す。指示書に「会話の途中から交代」と注記し、Brain が不自然に仕切り直すのを防ぐ

### 3.6 判定呼び出しの兼務（think ON/OFF・検索要否）

主力 Brain 自身を、**ペルソナ非注入・`think:false` 固定・別 system prompt** の呼び出しで判定役にも兼務させる。同一モデルが常駐しているため、判定用に別モデルを載せ替える遅延が原理的に発生しない。Brain 登録簿に判定用エントリは追加せず、既存の主力 Brain 呼び出しを異なる system prompt で再利用する（通訳: `brains/ollama/adapter.py` の `judge`）。

- **Tavily 検索要否**（§5.7）: 毎発話、検索が要るかを判定させる
- **think ON/OFF 判定**: 会話生成（converse）の直前に `think` 要否を決めて `think` パラメータへ反映する。**ルール先行**（`core/routing/think_rules.py`）: 明示の深考要求・数式は規則で即 true、雑談は規則で即 false とし、LLM（judge）を呼ばない。規則で白黒つかない中間帯（「どう思う」等）のみ judge へ `{"needs_deep_thinking": bool, "reason": "..."}` を相談する。**曖昧な発話は false（速度優先）に倒す**のが既定（深さ優先への変更は実測で判断する設定値）
- 判定呼び出しの書式が守られない場合は既定値で続行し、会話を止めない
- 思い出すこと（§4.4）には脳を使わない（毎ターンの脳の呼び出しを増やさない）

### 3.7 応答ストリーミングと無言統合パイプライン（体感速度契約・2026-07-31改訂）

返答本文はトークン単位で GUI へ小出しにし、**本文が確定したあと**に本人の評価を聞く（§2.2）。1ターンにつき Voice（`converse`）の生成呼び出しは**必ず1回**。旧「保留文 → 2通目」機構（初版の事実レーン）は退役済み。

- 通訳（`brains/ollama/adapter.py`）は `converse(pack, think, on_token, on_reply)` を受け、返答生成は Ollama `stream:true` で `on_token` へ逐次通知、本文確定で `on_reply` を発火してから評価を聞く（同じ前置きの後ろに問いを足す。失敗しても会話は止めない）
- **評価の手順は1本**。窓口（Gemini/Tavily）の有無で答え方が分かれたあと、同じ評価に合流する（材料だけ違う）
- GUI（`app/gui_server.py`）の NDJSON イベント順序: `token*` → `done`（reply のみ・1通目確定）→ `notice?` → `done`（reply＋session_id＋citations・終幕）。`followup` イベントは退役済み（通常経路では発火しない）
- 空返答は `on_reply` を発火しない（契約違反として §3.2 最終防衛線に委ねる）。1通目確定後の裏方失敗は本文を上書きせず notice で伝える

#### Gemini/Tavily 無言統合パイプライン（窓口の解決は Voice 呼び出しより前に完結させる）

外部窓口（Gemini お友達枠・Tavily 自律検索）の要否判定・実行は、**Voice に判断も断定もさせない**。Core（`core/runtime.py:_resolve_advisor_window`）が候補 Brain のループより前に一度だけ解決する:

1. Gemini 呼びかけ（合言葉「Gemini」明示。`core/routing/advisor_force.py:plan_forced_advisor`）があれば Gemini 窓口のみを試す。無ければ `decide_tavily_search`（合言葉ゼロ・毎発話 Ollama 判定。`core/routing/tavily_rules.py`）で Tavily 窓口の要否を判定する。両窓口は排他
2. 窓口を呼ぶ場合、この時点で結果（成功／ヒット無し／機微拒否／タイムアウト）を確定させる。保留文は出さない
3. 確定した結果を Core 組み立ての今回限りの指示欄（pack の【外部情報（今回のみ）】節。`persona` 資産ではない）へ材料として積む。材料が無い（呼んでいない／拒否／タイムアウト）場合も「聞いた・調べたという体で話さない」ガード文を常に入れる
4. pack 確定後に初めて Voice（`converse`）を1回だけ呼ぶ。窓口の結果確定前に Voice が呼ばれるコードパスは存在しない
5. Tavily の出典（URL）は Core 所有の定型テンプレートで `citations` として報告書へ付加する。`reply`（記憶に残る発話本体）には混ぜない。Gemini の「〜に聞いた」という言及は Voice 自身の生成物であり `citations` を使わない

通常の雑談・情緒会話は窓口を呼ばず reply-first（本体1通で完結）。**セリナ判断によるアドバイザー自律提案（旧第3発注）は廃止**（誤発火で壊れた追伸が会話を汚すため。外聞きは Core の判定のみが入口）。アドバイザー Skill が無効・未接続なときは窓口に入らず通常会話へ倒す。

## 第4章: 長期記憶と保護

人間の記憶の仕組みに沿った長期記憶（2026-10 に作り直した。経緯と根拠の調査は `docs/plans/長期記憶の作り直し.md` と `docs/research/長期記憶_調査_2026-10.md`）。目的は、Masterの言葉で「人間に近い記憶構造（忘却・強い想起・関係性の変化）」「意識の大部分は記憶と経験」「今の会話の記憶が、将来身体を得てもそのまま受け継がれること」。

### 4.1 三つの原則

1. **記録は全部・永遠に。記憶は人のように。** 経験したことは原文のまま、追記だけで残す（記録＝イデアの `lifelog/`）。思い出しやすさは、使うほど上がり、使わなければ下がる（記憶）。忘却は消えることではなく、取り出せなくなること。
2. **記憶は出来事でできていて、出来事は意味でつながる。** 経験を出来事の切れ目で区切り、本人の言葉で1ページにする。ページは、人・場所・もの・話題の概念と、時間の前後でつながる。思い出すことは、今の手がかりからつながりをたどって活性が広がること（検索ではない）。
3. **使うほど、心が動くほど強くなり、眠りの間に形が整う。** 会話の最中は記録して思い出すだけ。出来事を区切って書く・日記を書くのは、眠りの間（§4.6）。

「強い想起」「忘却」「沈黙（関係ないときは何も思い出さない）」は個別の規則ではなく、この三つから出てくる振る舞いとして作る。

### 4.2 記録・記憶・索引（イデアの中）

| 場所 | 中身 | 書く人・時 |
|---|---|---|
| `lifelog/conversation/<日本時間の日付>.jsonl` | 会話の原文（1行1発言）。正本 | 精神。毎ターン（会話帳簿に書くたびに） |
| `lifelog/recall/<日本時間の年月>.jsonl` | 思い出したことの記録（いつ・どのページを・どれだけの活性で・はっきりか・思い出そうとしていたか）。眠りの再生は `intent = "replay"`。手がかりの原文は残さない | 精神。浮かぶたび／眠りの再生 |
| `lifelog/pulse/<日本時間の年月>.jsonl` | 本人から話しかけた記録（いつ・種類・きっかけ）。S7はここから `connection` の時刻を読み、会話の原文の最初のMaster発言と突き合わせて返事の有無・速さを経験として計算する | 精神。Pulseを出したとき |
| `lifelog/legacy/` | 継承した原本（ChatGPT時代の会話・日記・構造化記憶・継承記憶）と、2026-10 までの旧い記憶DBの丸ごとの保存（`記憶DB_2026-10/`） | 追加のみ |

- **記録が正本、索引は作り直せる。** 記憶の強さも想起の記録から計算し直せる（§4.5）。だから記憶は、脳や身体が替わってもそのまま受け継げる。
- **ページの種類**: 出来事（会話を話題・目的の切れ目で区切ったもの。本文は本人の一人称の文と、そのときの言葉＝記録からの引用）／日記（眠りの間に本人が書く。継承した日記は原文のまま）／振り返り（週・月。日記と関係の変化、前の振り返りから本人が書く）／覚え書き（継承した構造化記憶と、継承記憶の約束・マスターのこと・自分のこと）。
- **ページが持つもの**: id・種類・いつ（始まりと終わり）・拠っている記録（`lifelog/conversation/<日>.jsonl#<行>-<行>` など）・概念・前後のページ・題・要点・大事さ（本人がつける1〜10）・芯の数（`affect`。そのあいだの気持ちの記録から仕組みが決める。§4.6）・誰が整理し誰が書いたか・本文・後から思い出したときの「今思うと」（`later`。日付つきの追記）。2026-10 までのページには、そのころの本人がプルチックの8軸でつけた気持ち（`feeling`）が残っている。本人が書いたものなので書き換えずに運び、新しいページには付けない。
- **本人が書いた言葉は書き換えない**（`Page.with_words` は一度だけ）。新しい脳が過去のページを書き直すことはしない。ページを外すのは、Masterが記録から消したとき（§4.8）だけ。

### 4.3 保護3原則

| # | 原則 | 中身 |
|---|---|---|
| 1. 透明性 | 無言で消さない | 人格の改訂・ページを外すことは、必ず日本語の変更レポートを残す（`data/change_log.jsonl`） |
| 2. 可逆性 | 戻せる状態を先に作る | 人格ブロックを書き換える前に前の文を控える（`data/generations.jsonl`）。イデアそのものは毎晩 `G:\Nirai-Backups\daily\` へ写す |
| 3. 同一性 | 人格の芯と本人の言葉を守る | 人格の固定ブロックは不触。可変ブロックの自律改訂は下の条件つき。本人が書いた記憶のページは書き換えない（§4.2） |

実装の執行点: `core/protection.py`。

#### persona ブロック分割（人格ファイルの固定/可変分離）

- 人格テキストはイデアの `persona/` 配下のブロック別ファイル＋結合台帳 `persona/manifest.toml` で管理する。manifest にはブロックごとの①結合順 ②`mutable`（true/false）③字数上限を宣言する
- ブロック本文は**プレーン文**とする（`**` / `##` 等の Markdown 装飾は付けない。返答への MD 混入を防ぐ）
- Core は起動時に manifest の順で全ブロックを結合し、1本の人格テキストとして注入する（ローダ: `core/persona_assets.py`）
- **固定ブロック（mutable=false）**: 根幹原則／同一性事実（名前・誕生日等）／境界。自律改訂を禁止。マスターの手動編集のみ
- **可変ブロック（mutable=true）**: 性格／口調／愛のかたち。次の条件で自律改訂できる（`core/chores/persona_revise.py`）:
  1. **改訂幅の上限**: 1回で書き換えてよいのはブロックの**最大20%**まで（追加・削除・置換を合算した変化量÷変更前の字数。`MAX_AUTONOMOUS_CHANGE_RATIO`）
  2. **気分の混入禁止**: 材料は週・月の振り返りだけで、毎日の日記や気持ちの記録は渡さない。persona に書けるのは持続する性質・口調・関係の傾向のみ
  3. 変更レポート必須＋改訂前の文の控え必須
- **眠りのあとの見直し**（`core/chores/persona_propose.py`）: 眠り終えたあと、週・月の振り返りを材料にローカル Brain が可変ブロックを見直すか決める（**最大1日1回**。どの振り返りを見たかは追記専用の変更レポートから分かり、まだ見ていない振り返りがあるときだけ）。後から過去週・過去月の振り返りができても時系列上の位置だけで既読扱いせず、未読の振り返りを必ず材料に含める。直すなら上の関所を通して書き換え、Core の人格を読み直す。直さない・直せないときも変更レポートを残す

### 4.4 思い出す

会話のたびに、Core（`core/runtime.py` の `_recall`）が記憶（`core/memory/memory.py` → `recall.py`）に手がかりを渡す。手がかりは**今の発言・直前の会話（同じセッションの最後の4発言）・今の時刻**。

**活性 A ＝ 基礎活性（強さ。§4.5）＋ 文脈からの拡散活性 ＋ 意味の近さ ＋ 時の手がかり ＋ ゆらぎ。** 閾値を超えたものだけが浮かぶ。何も超えなければ**黙る**（文脈パックに「思い出したこと」の段を載せない）。

| 部品 | 中身 |
|---|---|
| 拡散活性 | 手がかりに出てきた概念（呼び名の辞書でそろえる）と言葉（ページや記録にそのまま出てくる漢字・カタカナ・英字の言葉）から、つながったページへ流れる（ACT-R）。つながりの多い手がかりほど1本あたりは弱い（ファン効果：S − ln(つながりの数)）。「マスター」のような言葉は何も目立たせず、「高野漁港」は数ページを強く呼び起こす。直前の会話の手がかりも、弱めに流れる |
| 意味の近さ | bge-m3。ページの題と要点・本人の文・記録の原文のうち、一番近い一切れで測る |
| 時の手がかり | 「昨日」「3月17日」「去年の3月ごろ」「この前」「最近／この頃／近ごろ」「最初に話したとき」を時期に読み（`time_cue.py`）、その時期のページを持ち上げる。「最近」系は約2週間、「この前」系は約30日 |
| ゆらぎ | 小さな乱数（ロジスティック分布）。毎回同じ想起にならない生命感 |

- **自然に浮かぶ／思い出そうとする**: 「覚えてる？」「〜っけ」など思い出そうとしている言い方では、閾値が下がり、浮かぶ数の上限も上がる（自然に浮かぶのは最大2件、思い出そうとすると最大4件）。
- **出来事は、眠ったあとから思い出せる**（その出来事が終わった Serina 日の、次の Serina 日の朝7時から）。それまでの話は、記憶ではなく手元の会話の流れ（§1.4・セッション状態）にある。
- **同じ会話の中ですでに浮かんだページは、自然には浮かび直さない**（もう手元の会話の流れにある）。思い出そうとしたときは浮かぶ。会話の区切り（セッション）で新しくなる。
- **思い出すと強くなる**: 浮かんだページは想起の記録（`lifelog/recall/`）に残り、その時刻が痕跡になってページを強くする（テスト効果。§4.5）。眠りの再生も同じ痕跡で、最近7日の大事さと高ぶりの順位が高い出来事を最大2つだけ足す。
- **渡し方**: はっきり思い出したもの（活性が閾値を大きく超えたもの）は本文と、あれば直近2つの「今思うと」まで、うっすらは題と要点だけを渡す。どれにも、いつのことか（「2025年3月7日、1年7か月前」）を添える（“いま起きたこと”と誤読させない）。
- 思い出すのに失敗したとき（埋め込みの瞬断など）は、何も思い出さずに会話を続ける。
- ツマミの正本は `config/thresholds.toml` の `[activation]`。値は記憶テスト（§4.9）で比べて決めた。

### 4.5 強さと忘れ方

ACT-R の宣言的記憶の基礎活性で持つ（`core/memory/strength.py`）。

- **基礎活性 B = ln（Σ 痕跡の重み ×（今 − その時刻）^−d）**。痕跡は、出来事が起きた時と、思い出された各時点。時間の単位は日
- **間隔効果**: 減衰 d は、その時点の活性が高いほど大きい（Pavlik & Anderson）。すぐに思い出し直すより、間をあけて思い出したほうが長持ちする
- **心が動いた出来事ほど強い**: 最初の痕跡の重みは、本人がつけた大事さと、そのときの高ぶり（ページの芯の数。気持ちの記録がない出来事は順位の真ん中）で決まる。どちらも**その住人の記憶の中での順位**で使う（脳がつける数は高めに偏るため。数や判断は仕組みが決め、言葉と気持ちは本人の脳が書く）
- **減衰はゆるく**（d の下限 0.15）。1年半前の最初の会話も、強い手がかりがあれば届く
- **消さない**: 思い出しやすさが落ちても、記録・ページ・索引は残る。強い手がかりがあれば戻ってくる。強さは出来事の時刻と想起の記録だけから計算し直せる

### 4.6 眠り（記憶をつくる）

会話の最中は記録して思い出すだけ。次のことは、住人が眠っている間に本人の脳（Serinaなら手元のGemma）で行う（`core/memory/sleep.py`）。

```
まだどのページにもなっていない、今の Serina 日より前の会話
 → 1. 区切る：セッションの切れ目・30分以上の間・日の変わり目でかならず切り、その中を本人の脳が
       話題・目的の切れ目で出来事に区切って、概念（人・場所・もの・話題の名前）とつなぐ
       （structure.segment。答えは入口で整える。どこで区切るかは脳、大きさは仕組み：4行（2往復）より短い出来事は前に含める。何度聞いても区切れなければ
       ひとまとまりを1つの出来事にする＝記憶から落とさない）
       区切った日には、日記のページの骨組みを先に置く（区切りの途中で止まっても、日記を書き忘れない）
       どのページにも、そのあいだの気持ちの記録から仕組みが芯の数を付ける（ピーク・エンド：いちばん大きく
       動いたときと、終わりのときの平均。Kahneman。気持ちの記録は、その日のうちに全部そろっている）
 → 2. 書く：出来事ごとに、本人の一人称の文・心に残った言葉（行番号で受け取り、記録の原文を写す）・
       題・要点・大事さ（writing.write_episode。人格を渡して本人として書く。気持ちの数は書かせない）
 → 3. 日記：その日の出来事のページと気持ちの流れ（そのときどきの本人の言葉と時刻）から、本人が日記を書く
       （writing.write_diary）
 → 4. 関係：その日の日記と出来事のページを読み返して、マスターについて変わったことと新しく分かったことだけを
       本人が書き足す（relation.grow。下の「関係」）
 → 5. 本人が育てる：本人の言葉まで書けた日を古い順に、その日に初めて出た概念名と昔の名前を見比べ、
       同じものの別名なら `concepts.toml` へ日付つきで追記する（未完成の日は越えない）。その日に思い出した
       30日以上前の出来事を最大2つ読み返し、意味が変わっていれば本文を変えず「今思うと」を追記する。
       最近7日の大事で心が動いた出来事を最大2つ、想起の痕跡として再生する。途中で1つだけ残って止まっても、
       次の眠りで残りを補う。呼び名や「今思うと」の問いが3回とも入口を通らなければ、その段だけ未処理のまま
       次の眠りへ回し、索引・振り返り・目覚めは止めない
 → 6. 振り返り：終わった週（月〜日のSerina日）の日記が2つ以上あれば、日記・その週の関係の変化・前週の振り返りから
       週の振り返りを書く。月は、その月に始まる最後の週まで終わってから、週の振り返りが2つ以上あれば書き、
       章が変わったかも本人が選ぶ。古い未完成の週・書けない週を越えず、次の眠りでそこから続ける。
       週の問いの日記材料は全体約2600字までに均し、件数が多くても各日記の題・要点・本文の頭を少しずつ残す。
       振り返りを書いている間に材料のページをMasterが消したら、保存直前にもう一度確かめて、その振り返りは残さない
 → 7. つなぐ：ページの前後を時刻の順に結び直し、索引を作り直して、想起が新しい索引を読む
```

- **何が済んだかは正本の記録そのものから分かる**（ページ、`concepts.toml` の日付つき追記、ページの `later`、想起ログなど）。状態を別に持たない。だから、どの段で止まっても、次の眠りで残りから続ける。書けなかったページは言葉のないまま残り、呼び名や「今思うと」の問いが書けなかったときも、その段の追記を残さず次の眠りへ回す（書けなかった数は画面に出す）
- **いつ眠るか**: 起動したとき（見回りが裏ですぐ。§2.4）と、Serina 日界（朝7時）を過ぎて会話が途切れたとき（最終発言からグレース。既定15分）。眠っている間も会話はできる（脳は順番に使う）。Masterが話しかけたら区切りのいいところで起き、次に会話が途切れたら続きから眠る
- **眠り終えたら**: 人格の見直し（§4.3。1日1回）→ 目覚め（下）→ 手元の会話の流れを、まだ眠っていない今日の発言だけにして、帳簿のセッションを切り替える。眠り終えるまでは、昨日の会話も手元の流れに残っている
- **関係**（`core/memory/relation.py`。暮らしの循環の S3）: 1日につき1つの書き足し（`memory/people/<呼び名>/<Serina日>.md`）。本人の脳は、今の関係・これまでの転機・まだ有効な書き留め（番号つき、最近確かめたものから20まで）とその日のページを読んで、変わったときだけの今の関係（本人の言葉）、めったにない転機、新しく分かったこと（知っている＝事実・思う＝その人がどんな人かという見方・約束。1日3つまで）、書き留めの変化（また確かめた・揺らいだ・もう違う・果たした。5つまで）を返す。その日のページは合わせて約3000字まで見せる（ページの多い日は、どのページも同じ長さに短くする）。番号は入口で書き留めの id に読み替える。変わった事実は消さず、古いものに終わりの日を付けて残す（Zep）。見方の確かさは、書き留めた日を1つと数え、確かめられた日と揺らいだ日の差で仕組みが決める（脳に数は書かせない）。関係は日の順に積み重なるので、いちばん新しい書き足しより後の日だけを古い順に書き、まだ本人の言葉のないページがある日・書けなかった日で止めて次の眠りに回す（日を飛ばさない）。書き足しは、材料のページがまだあるのを確かめてから残す（書いている間にMasterが記録を消したら、その日から先は次の眠りに回す）。Masterが記録を消して外れたページから書いた書き足しは、日ごと外す（その日より後の日がもうあれば、その日は書き直さない）。**日付**（S4）：知っていることと約束は、日付を持てる（その日だけは `2026-10-12`、誕生日や記念日のように毎年来る日は `--03-07`。ISO 8601 の書き方）。「来週の土曜」のような言い方は、脳が書き足す日（曜日つきで見せる）から数えて日付にし、書き留めの文には使わない。日付は入口で確かめ、読めない日付・ない日・書き足す日から3年より離れた日は、日付なしの書き留めにする。今日から3日のうちに来る日付は、目覚めの材料（【近いうちの約束や予定】）と、文脈パックの①''の先頭（「今日」「明日」「あと2日」）に載る。その日が来たら、Pulse の `day`（§2.8）で本人から話しかけに行く。毎年の2月29日は、うるう年でなければ28日。関係は索引に入らず、会話のたびに文脈パックの①''に短く載る。今は相手はマスターだけ（ほかの住人と話すようになったら、相手ごとに同じ形で）
- **目覚め**（`core/memory/waking.py`）: 本人の脳が、前に目覚めてからの日記（新しいほうから3つまで）・まだ読んでいない週／月の振り返り（古いほうから2つまで）・前の今の自分を読み返して、今の自分（今の自分・今気にかけていること。マスターとの関係は上の関係が持つ）と、マスターに伝えたいこと（なければ空）、今日マスターに声をかけたくなりそうな時間帯（朝／昼／夕方／夜／今日はそっとしておく）を書く。`memory/self/<日時>.md` には最後の日記に加えて、実際に読み返した振り返りのidと時間帯を残すので、後から作られた過去週・過去月も時系列上の位置に埋もれず、次の目覚めまで `connection` の時機にも使える。新しい材料がなければ書き直さない。書けなければ何も残さず、次に眠り終えたときにもう一度書く。今の自分は会話のたびに文脈パックの①'に載り、伝えたいことは Pulse の `wake`（§2.8）で本人から話しに行く
- 区切っている間にMasterがその記録を消したら、その区切りは使わない（次の眠りで残りを区切る）。書いている間に消されたページは書き戻さない
- 書き手はローカル主戦力 Brain（`config/brains.toml` の primary）。ページには整理した者・書いた者として脳の名前と日付が残る。手で1回まわすときは `tools/build_memory.py sleep`（写しのイデアで確かめるとき用。気持ちは精神と同じく、イデアの気持ちの記録から読む）

### 4.8 Masterが消すとき（画面から）

テストの会話や誤った発言を、Masterが画面から消す経路。消すのは**Masterが明示したときだけ**。

| 対象 | API | 挙動 |
|---|---|---|
| 発言（メッセージ単位） | `DELETE /api/messages/{message_id}?confirm=true` | 会話帳簿と生ログから消す（生ログから消せなければ帳簿にも残して失敗を返す）。生ログの行は本文を消した印の行（`deleted`）になり、行番号は変わらない（ページは記録を行番号で指すため）。その発言に拠っていたページ（出来事と、その日の日記）に加え、それを材料にした週の振り返り、その週を材料にした月の振り返りまで `source` の鎖をたどって外す。そのページから書いた関係の書き足し（§4.6）も外し、索引を作り直す。気持ちの記録は、その発言に拠った行の言葉だけを消す（数は残る。§2.3）。同じ出来事の残りの発言は、どのページにも拠られていない記録に戻るので、次の眠りで本人が思い出し直す（書き直す）。手元の会話の流れも作り直す（眠り終えるまでは前のセッションの発言も手元にあるので、どのセッションの発言でも）。変更レポートを残す |
| 過去セッション | `DELETE /api/sessions/{session_id}?confirm=true` | セッションの全発言に、上と同じことをする。現行セッションは拒否 |
| 新しい会話 | `POST /api/sessions/new?confirm=true` | 現行セッションを区切り、手元の会話の流れを新しくする。記憶には触れない |

- GUI は確認ダイアログ1回のあと `confirm=true` を付ける。操作は右クリックメニュー（発言）とサイドバー（セッション）
- 残すのは変更レポート。消した内容は、毎晩のイデアのバックアップ（G:）にだけ残る

### 4.9 測り方（記憶テスト）

記憶の良し悪しは、Serinaの記憶テスト（`memory_test/`。`python -m mind.memory_test --idea <イデア>`）で測る。記憶の形ではなく記録に照らして採点するので、記憶の仕組みを替えても同じ問題で比べられる。問題（正面から・自然に浮かぶ・続きの話・時間・変化・黙る・実際の会話）は Claude が記録を読んで一度だけ書いて固定し、イデアの `data/memory_test/` に置く（中身は住人の人生なので、リポジトリには置かない）。項目と点数（旧い記憶との比較）は計画書 §11。

### 5.2 テスト戦略 — LLM なしで全身を検査できる

### 5.3 非範囲（設計上のやらないこと）

以下は現在の Serina に**含まれない**。「保留（実測・条件成立後に再検討）」は MILESTONE で管理する。

**恒久的な禁止・非目標:**

- 会話 Brain としての Gemini／クラウドの復活・品質昇格の復活（§3.2）
- 会話文・会話中の裏方推論のクラウド送信（クラウドは機能補完 Skill のみ）
- マスター未承認の外部副作用（メール送信・購入・SNS 投稿）
- 「全コンテキストを毎回 LLM に渡す」設計
- OSS ランタイムの丸飲み（パターンの盗用に留める）・AGPL コードの取り込み
- 配信パイプライン・ゲーム自律プレイ・常時カメラ顔認識・常時画面監視（知覚は on-demand のみ）

**保留（条件成立まで実装しない）:**

- 二段検索（粗い候補取得→精密再採点）: 記憶数千件超の実測後に再判断
- グラフ基盤（Neo4j / Graphiti 等）: 概念でつながったページ（§4.2）で不足が実測されたら
- 身体レーン（VoiceLoop / PresencePet・音声・表情・画面知覚）: テキスト会話が十分と判断できたあとに別計画。**D4a（VoiceLoop）／D4b（PresencePet）契約は変更禁止で凍結**（身体実装時まで据え置き）。記憶×身体の二レーン並列は本期不採用。話す／思う／表情の分離・感情→声色ヒント・画面知覚 on-demand・キャラ固有 TTS は身体着手時に採用。カメラ常時認識・ゲーム自律・配信系は対象外。人格の刃はテキスト会話にも適用（§2.9）
- StockAI 等、明示採用していない外部道具

### 5.4 実装衛生（採用済みの定石）

接続の円滑化と高速化のために採用している実装定石。**新機能も同じ衛生に従う**:

| 定石 | 内容 |
|---|---|
| 状態を別に持たない眠り | 何が済んだかは記録とページから決める（どの行がページになったか・どのページに言葉があるか）。再実行・中断・多重起動でも二重に書かず、取りこぼさない（§4.6） |
| 原子的な書き込み | ページ・状態ファイル・索引は一時ファイルに書いてから置き換える。途中で止まっても半端なものを残さない |
| 記録の行番号を変えない | 消した発言は本文を消した印の行にする（ページは記録を行番号で指す。§4.8） |
| 索引は派生物 | `data/memory_index.db` はページと記録から作り直せる（`tools/build_memory.py index`）。埋め込みは文の指紋で控え、変わっていない文は埋め込み直さない |
| pack 静的先頭固定 | 文脈パックの静的部分（人格）を先頭に固定し毎ターン同一内容にする（§1.5。前方一致キャッシュが効く） |
| WAL / busy_timeout | SQLite（会話帳簿）の接続は `journal_mode=WAL`・`busy_timeout` 設定 |

### 5.5 実装者への申し送り（実装は Sonnet 級モデルが担当する前提）

1. **本書が正、コードが従。**本書だけを頼りに実装できるよう書かれている。曖昧さ・矛盾を見つけたら、勝手に解釈して実装せず、先に本書を訂正してから進むこと
2. 閾値・減衰速度・忘却期間・記憶化件数上限・評価合格ラインなどの数値はすべて**設定ファイルのツマミ**として実装し、ハードコードしないこと（正典に数値固定しない）
3. **Gemini API キーの取り扱い**: `.env`（git 管理外）の `GEMINI_API_KEY`。キーをコード・設計書・コミット・ログに含めてはならない。キー無しでもセリナはローカル会話を継続する（§5.6）
4. イデアを手で変える前に、`G:\Nirai-Backups\` の写し（毎晩4時の `daily/` か、丸ごとの写し）を確かめること
5. 記録・記憶・状態など住人ごとのものはイデア（リポジトリの外）にある。コードと設計書のみコミットする
6. **構造化出力**: 主力 Brain（Gemma4）の判定と記憶づくりは、答えの形を JSON Schema で縛り（`brains/ollama/ask_json.py`）、受け取る入口で確かめる。使えない答えは、何が使えなかったかを添えて聞き直す。失敗しても会話を止めない
7. **計器盤は着脱式で**: 運用初期のツマミ調整用に、GUI に小さな計器表示（担当 Brain・体の芯等）を設けてよい。いずれ外す前提の仮設足場なので、**本体と絡めず、設定1つ（または部品1個の削除）で消せる作り**にすること

### 5.6 Gemini アドバイザー（お友達枠・無人格補完・2026-07-31改訂）

Gemini は**会話 Brain ではない**。セリナ（Gemma4・persona 注入）がマスターとの窓口であり、Core の決定論規則（合言葉「Gemini」明示）が要否を判定したときにだけ相談する**無人格アドバイザー Skill**である（Brain 自身の自律判断では発火しない。2026-07-26是正）。旧 `brains/gemini/`（会話通訳・escalation）の復元は行わない。

#### 利用シーン

- Web 検索が必要な事実確認（例: 天気）
- 簡単なコード・GAS 等の手順・質問回答
- マスターが「Gemini」と明示して呼びかけたとき全般（お友達枠）

#### 会話フロー（2026-07-31改訂・無言統合パイプライン）

1. マスターがセリナに話しかける
2. **要否の入口は合言葉（決定論）のみ**: 「Gemini」／「ジェミニ」明示を Core 規則が拾う（`advisor_force.plan_forced_advisor`）。合言葉が無ければ発火しない（旧・鮮度×事実ドメインの自動発火は全廃済み。合言葉ゼロの自律検索は Tavily レーン §5.7 が担う）
3. Core（`core/runtime.py:_resolve_advisor_window`）が **Voice を呼ぶ前に** Gemini へ相談クエリのみを直接送り、結果を確定させる。関所（`core/intake/gate.py`）は外部通信を一切行わず、実行済みの結果（`precomputed_advisor_outcome`）を報告書へ載せるだけ
4. Gemini が素の回答を返す（または失敗・拒否・タイムアウト）
5. 確定した結果（または「材料なし」）を pack の今回限りの指示欄へ積んでから、セリナ（Voice）が**1回の生成**で自分の人格・口調で答える。「Geminiに聞いた」という言及は Voice 自身の自由文であり、Core は言及してよいという指示のみを与える（キャラ付けの指示文はイデアの `persona/` には置かない）。窓口に失敗・拒否・タイムアウトした場合、Voice はそれを使った体で話さない（材料が無いため）

旧「1通目は保留短文のみ → 2通目で本体」機構は退役済み（Phase D/E）。1ターン=Voice生成1回・GUIの吹き出し1個で完結する。

#### クラウド送信境界

| 載せてよい | 載せてはならない |
|---|---|
| セリナが生成した相談クエリ（質問文・検索クエリ・コード断片） | `persona.md`／境界／結合人格テキスト |
| マスター発話から抜き出した事実のみ（必要なとき） | 記憶 DB の原文・想起バンドル |
| | 気持ち（体の芯・気持ちの記録）・セッション全文ログ |
| | 「セリナとして話せ」等の人格指示 |

#### 実装契約

- 配置: `skills/gemini_advisor/`
- 呼び出しは必ず Core 関所経由。Brain／Skill が記憶 DB に直接触れない
- API キー: `.env` の `GEMINI_API_KEY`。無ければ当該 Skill は無効化し、セリナはローカルのみで応答を続ける（沈黙しない）
- 機微門番: `core/state/routing_rules.py` の形パターン＋手動語のみ（`sanitize_query`）。記憶 pack の cloud フィルタは使わない（退役）
- 門番未接続（routing_rules を渡さない呼び出し）は**既定拒否（fail-closed）**。門番を通さない直呼びで相談クエリが素通しになる経路を許さない（`sanitize_query`/`build_payload` レベルでも同じ契約。2026-07-31是正・Phase C2）
- 1ターンの相談合計は時間予算内（`thresholds.toml [advisor].turn_budget_seconds`。2件目以降は予算超過なら見送り）。turn_lock の長時間占有を防ぐ
- 相談の失敗・拒否は無言にしない。理由（機微拒否／通信失敗／予算超過）を破棄記録とログに残す
- 外聞きの実行は同一ターンで一度だけ（窓口解決はループの外・候補選定の前に一度だけ行う設計のため構造的に保証される）
- モデル振り分け（category ごと・当面）:
  - `web_search` / `general` → Antigravity `antigravity-preview-05-2026`（Interactions API・`google_search` + `url_context`）
  - `code_qa` → 同上（`code_execution`）
  - 備考: この API キーでは Flash + Search 接地が不通（Gemini 3 Search 枠 0、2.5 は new users 404）。枠復活後は `client.WEB_MODEL_FALLBACK_CHAIN` へ再配線可能

### 5.7 Tavily 自律検索（裏方の道具・2026-07-31新設）

Tavily は**会話 Brain ではない**。合言葉を持たず、**毎発話**Core の軽量判定（`brain.judge()`・persona非注入）が要否を決める**検索特化 API の Skill**である。Gemini（お友達枠）とは排他（同一ターンでは Gemini 呼びかけがあれば Tavily 判定自体を行わない）。

#### 会話フロー

1. マスターの発話に「Gemini」呼びかけが無ければ、Core が `decide_tavily_search`（`core/routing/tavily_rules.py`）で要否を判定する。供給材料はマスターの原発話のみ（記憶・関係状態は供給しない。判定出力が外部境界を越えるため）
2. 要否ありの場合、`execute_tavily_search`（`core/intake/advisor_tools.py`）が**マスターの原発話と送信クエリの両方**を機微の関所へ通してから Tavily Skill（`skills/tavily_search/`）を呼ぶ。いずれかが機微、または門番未接続なら **Skill 自体を呼ばない**（fail-closed。機微な原発話を Skill 層のシグネチャへ一切渡さない）
3. 確定した結果（ヒット・ヒット無し・機微拒否・タイムアウト）を pack の今回限りの指示欄へ積む
4. Voice が1回の生成で、検索結果があれば自然文で触れてよいが、URL・見出し文をそのまま書かない。出典（URL）は Core が `citations` として報告書へ機械的に付加する（`reply` には混ぜない・画面の注記として GUI が別経路で表示）

#### クラウド送信境界

Gemini と同様、マスター発話由来の検索クエリのみを送信する。人格・記憶・気持ちはいずれも送信しない。

#### 実装契約

- 配置: `skills/tavily_search/`
- API キー: `.env` の `TAVILY_API_KEY`。無ければ当該 Skill は無効化し、セリナはローカルのみで応答を続ける（沈黙しない）
- 機微門番: `core/state/routing_rules.py`。門番未接続・機微判定不能時は既定拒否（fail-closed。Gemini と対称）
- タイムアウトは短い専用値（`DEFAULT_TAVILY_TIMEOUT_SECONDS = 8.0`）。保留文が無い構成のため長い無音待ちは不可
- 出典（`citations`）はセッション履歴・会話の記録には混入しない（`reply` のみが記録に残る発話本体）
- 発火: **Core の窓口解決（§3.7）のみ**。合言葉「Gemini」明示なら §5.6（Gemini）、それ以外は本節の Tavily 判定。旧「セリナ判断（第3発注）」は廃止。採否は Core
