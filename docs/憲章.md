# Serina 憲章（Architecture Reviewer 測定器）

## 概要

憲章とは、`設計書.md` に固定された構造のうち、**Architecture Reviewer が変更（diff）の適合／逸脱を機械的に判定するための測定器**である。

- 位置づけ
  - 原典は `設計書.md`。本書はその判定基準だけを抜き出し、各原則に「違反の兆候」を付与したもの。
  - 本書は**判定に使う定規**であって、新しい設計思想を発明・追加する場ではない。
  - 責務配置・ルーティング・文脈パック等の詳細仕様は原典を正とし、本書では重複を避けて最小の逸脱検知に畳む。
- 前提・制約
  - Architecture Reviewer は本書の条文**のみ**を基準に判定する（教科書的な AI エージェント論の一般語彙は持ち込まない）。
  - 条文の追加・変更・削除の権限は**マスターのみ**。番人（Reviewer）は条文を増減できない。
  - 憲章を更新する場合は、先に `設計書.md` を改訂し、その差分を本書へ反映する（原典が正、本書が従）。

## 対象レイヤー定義（Serina の実体）

| 記号 | レイヤー | 一言責務 | 原典 |
|---|---|---|---|
| C | Core | セリナ本体。決定論。人格・状態・記憶・ルーティングの管理者 | §1.1〜1.2 |
| Br | Brain | 交換可能な知能。生成・推論・抽出 | §1.1〜1.2 |
| Ad | 通訳（アダプタ） | Brain 固有の作法を吸収し、Core から見た顔を揃える | §1.2 |
| S | Skill | 道具。外部システムへの接続口（会話 Brain ではない） | §1.1〜1.2・§5.6 |

- **Memory（記憶DB）は独立層ではない。** Core の内臓であり、層名として Memory を立てない（§1.3）。
- **人格資産は Core が保管するテキスト**であり、独立レイヤー名は使わない。
- 一般語彙および**旧6層名**は使用しない。

## 憲章条文（測定器本体）

各条文は「ID／規範／違反の兆候」の3点で構成する。

### A. 層境界（最小）

詳細な責務表は設計書 §1.2・§1.3・§1.6 を正とする。Reviewer は次だけを逸脱検知に使う。

| ID | 規範 | 違反の兆候 |
|---|---|---|
| A-1 | Core は文章生成も外部 API 生仕様の組み立てもしない（§1.2） | Core が返答本文を生成する／外部 API の引数・エンドポイントを直接組み立てる |
| A-2 | 人格・長期記憶・判断ルールの正本は Core。Brain／通訳に永続させない（第0章／§1.6） | 正本が Brain または通訳の永続状態に染み出す |
| A-3 | 付箋は提案。関所を迂回して状態・記憶へ直結させない（§2.5） | Brain／通訳出力が無検証で反映される経路がある |
| A-4 | 新 Brain 追加＝通訳1枚。Core 本体改修を必須にしない（§1.2） | 新 Brain のたびに Core 広範改修が必須になる |
| A-5 | Skill は状態・判断・記憶を持たない。採否・実行は Core（§1.2・§5.6） | Skill が「やる／やらない」を決め、記憶を持ち、Core を経由せず方針を決める |
| A-6 | Gemini 等のクラウド補完は Skill。会話 Brain（primary／escalation）として登録しない（§3.1・§5.6） | `brains.toml` 会話行への Gemini 復帰／会話文を品質昇格でクラウド送信 |

### B. 依存方向（最小）

正規の依存方向：**GUI → Core → 通訳 → Brain → Skill**（§1.3）。

| ID | 規範 | 違反の兆候 |
|---|---|---|
| B-1 | 依存は一方向のみ。逆流禁止（§1.3） | Brain／Skill／通訳が Core を呼び戻す、または下位が制御フローを握る |
| B-2 | 記憶DBに直接触れるのは Core だけ（§1.3） | Brain／通訳／Skill から記憶DBへ直接 read/write する |
| B-3 | Brain 差し替えは通訳に閉じ込め、Core を無傷に保つ（§1.6） | 1つの Brain 交換が Core や他 Brain の広範変更を強制する |

### C. 記憶原則（書き込み経路と保護）

| ID | 規範 | 違反の兆候 |
|---|---|---|
| C-1 | 記憶DBへの書き込みは審査ライン一本だけ。裏口は存在させない（§4.1） | 即時便や会話経路から関所を迂回して記憶DBへ書き込む |
| C-2 | 保護3原則（透明性・可逆性・同一性＝事後監査制）を維持する（§4.3） | 変更レポートなし／控えなしの破壊的変更。pinned 正典約束・persona 固定ブロックへの自律改訂・指示忘却。可変ブロックで4条件（改訂幅40%・気分混入禁止・レポート＋控え・固定不触）を満たさない自律改訂 |
| C-3 | 記憶候補の採否は Core の生理として完結させる。棄却は記録する（§2.5／§4.1） | 記憶の取捨に人為的な裁定入口を作る／棄却を無言で行う |
| C-4 | センシティブ・個人情報はクラウドに送らない。機微等級2はクラウド宛パック／Skill ペイロードに載せない。グレーは安全側（ローカル）。宛先未確定もクラウド扱いでフィルタ（§3.3／§4.2／§5.6） | 機微等級2やセンシティブ内容がクラウド行きに混入する／グレーをクラウド側に倒す |

## 判定の3観点（3本の定規）

1. 観点1：層境界 — 対応条文 A 群
2. 観点2：依存・結合 — 対応条文 B 群
3. 観点3：記憶保護・機微 — 対応条文 C 群

---

## レビュー発火条件（毎コミットでは回さない）

Architecture Reviewer は**構造に触れる変更のときだけ**発火する。

- 発火する（必須）
  - 新レイヤー／新モジュールの追加
  - 層をまたぐ依存の追加・変更（import 関係の変化）
  - Brain の追加・削除、通訳の追加・供給配線の変更、登録簿の構造変更
  - 人格資産の置き場所・Core からの供給配線の変更
  - 記憶のスキーマ・保存先・保護ロジック・書き込み経路の変更
  - Skill（道具箱）の契約・登録構造の変更
- 発火しない（任意）
  - 単一層の内部実装のみの変更（関数リファクタ・命名・バグ修正）
  - テスト・ドキュメントのみの変更
  - 閾値・残弾枠などツマミ値のみの変更（条文の規範を変えない範囲）

※ 構造変更時は **architecture-reviewer** を先に通し、PASS 後に実装。作業完了時は `completion-review` → `serina-code-reviewer`（Claude / Cursor 共通の唯一入口）。完了時レビューの「構造ゲート証跡」も本節の発火条件リストのみを用い、独自の構造定義を増やさない。

## 番人の禁則（Reviewer 自身のドリフト防止）

| 禁則 | 内容 |
|---|---|
| 禁則1 | 番人は憲章の「違反」を指摘してよいが、憲章の「内容」を批判してはならない |
| 禁則2 | 憲章条文の追加・変更・削除はマスターのみ。番人は定規を増やせない |
| 禁則3 | 「最新技術だから正しい」で判定してはならない。基準は本書の条文のみ |
| 禁則4 | 一般語彙および旧6層名で監査してはならない。層名は本書の Core／Brain／通訳／Skill に固定 |
| 禁則5 | コード・ライブラリ・実装手段を提案してはならない。改善案は「思想的にどの層へ置くべきか」までに留める |

## 出力形式（Reviewer の返却フォーマット）

```
総合評価: PASS / WARNING / FAIL
違反条文: （該当する条文ID。例: A-1, C-2）
発生層:   （どの層で起きたか。例: Brain → Core への責務越境）
観点:     （観点1〜3のどれか）
懸念点:   （思想レベルの説明。コード・ライブラリ名は書かない）
改善案:   （どの層へ置き直すべきか、という思想レベルの方向のみ）
```

- PASS：どの条文の違反兆候にも該当しない
- WARNING：違反の兆候はあるが、設計書または DECISIONS で明示済みの移行状態・暫定として許容余地がある
- FAIL：条文に明確に違反し、放置すると設計思想が崩れる
