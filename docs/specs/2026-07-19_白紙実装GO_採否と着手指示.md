### 3. C4 — Gemini アドバイザー（ゼロベース導入）

#### 3.1 立ち位置

- Gemini は**会話 Brain ではない**。セリナ（Qwen・persona 注入）がマスターとの窓口であり、必要に応じて**自律的に相談する無人格アドバイザー**である。
- 旧 `brains/gemini/`（会話通訳・escalation）の復元は行わない。新規に Skill／道具経路として実装する。

#### 3.2 利用シーン

- Web 検索が必要な事実確認（例: 天気）
- 簡単なコード・GAS 等の手順・質問回答

#### 3.3 会話フロー（必須挙動）

1. マスターがセリナに話しかける
2. セリナ（Qwen）が「アドバイザー相談が必要」と判断する
3. Core 関所経由で Gemini に**相談クエリのみ**を送る
4. Gemini が素の回答を返す
5. セリナが自分の人格・口調でマスターへ言い直す

例: マスター「明日の天気教えて」→（セリナが Gemini に相談）→ Gemini「晴れです」→ セリナ「明日は晴れだよ！」→ マスター「なるほど」

#### 3.4 クラウド送信境界

| 載せてよい | 載せてはならない |
|---|---|
| セリナが生成した相談クエリ（質問文・検索クエリ・コード断片） | `persona.md` / `boundary.md` / 結合人格テキスト |
| マスター発話から抜き出した事実のみ（必要なとき） | 記憶 DB の原文・想起バンドル |
| | 関係状態・感情状態・セッション全文ログ |
| | 「セリナとして話せ」等の人格指示 |

議題 2.5（会話文をクラウドへ送らない）との整合: マスター↔セリナの人格会話はローカル完結。クラウドに出るのはアドバイザーへの問い合わせだけとする。

#### 3.5 実装契約（パス・責務）

- 新規: `skills/` 配下にアドバイザー Skill（ディレクトリ名は実装時に Wave 内で確定。候補: `skills/gemini_advisor/`）
- 呼び出しは必ず `core/intake/gate.py`（または同等の Core 関所）経由。Brain / Skill が記憶 DB に直接触れない（憲章維持）
- API キーは既存 `.env` の `GEMINI_API_KEY`（無ければ当該 Skill は無効化し、セリナはローカルのみで応答を続ける。沈黙しない）
- 機微門番: 既存 `core/context/pack.py` の cloud 宛フィルタ思想を流用する。アドバイザー向けペイロードは等級 2 を載せない・等級 1 は化粧版または除外
- `brains.toml` の conversation Brain 行には Gemini を戻さない（Qwen 1 行維持）
- 残弾・クォータが必要なら設定値とし、置き場所は `config/thresholds.toml` または専用 toml（実装時に Wave で確定）

#### 3.6 発火条件（初期）

- 既定: **セリナ判断のみ**（マスターの明示コマンドは必須としない）
- 判断材料は Qwen の構造化出力（付箋「道具使用」または同等の tool 提案）。Core が採否する
- 失敗時: マスターへ謝る／ローカル知識で答える。会話をクラッシュさせない
