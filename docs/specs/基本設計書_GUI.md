# GUI 基本設計書（チャット画面・会話履歴・アルバム）

## 概要

Serina GUI とは、REPL（黒い画面）に代わる日常利用の入口となるローカル Web チャット UI のこと。

- 目的
  - ショートカット1発で起動し、Claude 風のチャット画面でセリナと話せるようにする
  - 会話履歴（過去セッション）とアルバム（蒸留された日記）を閲覧できるようにする
- 前提・制約
  - GUI は Core の**薄い皮**。判断ロジックは一切持たず、REPL と同じ `create_core()` / `SessionManager` / `DistillWorker` を使う
  - `127.0.0.1` バインドのみ（外部公開しない）。利用者は単一ユーザー前提
  - 基本形をまず出し、不満が出たらチューニングする方針（凝った装飾・設定画面は作らない）
  - アルバムの「鍵付き日記」（閲覧ロック演出）は将来のチューニング項目。v1 は閲覧のみ

## 技術構成

| 要素 | 採用 | 理由 |
|------|------|------|
| バックエンド | FastAPI + uvicorn（`app/gui_server.py`） | ストリーミング応答（StreamingResponse）が素直に書ける。画面が育っても保守しやすい |
| フロントエンド | 素の HTML/CSS/JS（`app/web/`、SPA 1枚） | ビルド工程なし。ブラウザで即動く |
| 通信 | POST + NDJSON ストリーム | 応答トークンを逐次描画（REPL のストリーミング表示と同じ体験） |
| 起動 | `Serina.bat`（リポジトリ直下） | サーバ起動＋既定ブラウザで自動オープン。Windows ショートカットの向き先にする |

- ポート: `8765`（固定。衝突したら起動エラーを表示して終了）
- 依存追加: `fastapi` / `uvicorn`（requirements.txt に追記）

## 画面構成

- 全体レイアウト（Claude 風・ダークテーマ）
  - 左サイドバー
    - 「今日の会話」（現在の active セッション）
    - 会話履歴リスト（過去セッション。日付＋冒頭一文）
      - クリックで右側に読み取り専用表示（過去セッションへの追記はできない）
    - アルバムボタン（📖）
  - 中央: チャット画面
    - メッセージリスト（ユーザー右・セリナ左）
    - セリナの応答は生成中トークンを逐次描画
    - 裏方の通知（蒸留レポート・独り言など）は小さなシステム行として表示
    - 入力欄＋送信ボタン（Enter 送信 / Shift+Enter 改行）
- アルバム（モーダル）
  - 蒸留された日記（`type="diary"` の記憶）を新しい順にカード表示
    - 各カード: 生活日の日付＋日記本文
  - v1 は閲覧のみ（編集・削除なし。正典保護原則のため書き込み経路を作らない）

## API 仕様

| メソッド | パス | 説明 |
|------|------|------|
| GET | `/` | SPA（index.html）を返す |
| GET | `/api/state` | 現在の session_id・pending 件数を返す |
| GET | `/api/history` | 現在セッションの全メッセージ |
| GET | `/api/sessions` | セッション一覧（新しい順。id / status / created_at / 冒頭一文） |
| GET | `/api/sessions/{id}/history` | 指定セッションのメッセージ（history → 無ければ archived_history） |
| GET | `/api/album` | 日記一覧（新しい順。created_at / content） |
| POST | `/api/chat` | 1ターン実行。NDJSON ストリームで返す |

### POST /api/chat の NDJSON イベント

| type | フィールド | 説明 |
|------|------|------|
| token | text | 生成中のチャンク（逐次描画する） |
| notice | text | 裏方の通知（蒸留レポート・独り言・セッション切替など） |
| done | reply, skill, session_id | ターン完了。session_id は蒸留でセッションが切り替わった場合に新IDになる |
| error | text | 失敗（セリナの人格の謝り文言。生スタックトレースは返さない） |

## 処理の流れ

1. 起動（`Serina.bat` → `python app/gui_server.py`）
   - `create_core()` で Core を組み立て（Ollama 未起動なら起動エラーページ相当のメッセージを表示して終了）
   - 孤児セッションの backfill → `SessionManager.resolve_active_session()`（REPL と同一手順）
   - uvicorn を起動し、既定ブラウザで `http://127.0.0.1:8765` を開く
2. 1ターン（POST /api/chat）
   - 直列化ロック（単一ユーザー前提。多重送信時は先行ターン完了まで待つ）
   - 蒸留ワーカー実行中なら中断要求（対話最優先。REPL と同じ）
   - `core.turn(session_id, text, on_token=...)` をワーカースレッドで実行し、チャンクを `token` イベントとして流す
   - `skill == "distill"` の場合（蒸留インテント）
     a. `notice` で「整理を始めた」旨を流す
     b. REPL の `_distill_now` と同じ同期蒸留を実行し、レポートを `notice` で逐次流す
     c. 新しい session_id を `done` に載せる
   - ターン完了後、pending か週次固結の期限があれば裏ワーカー起動（経路B。REPL と同一）
   - 裏ワーカーの完了レポートは、次のターンの `notice` として排出する
3. 例外時
   - `error` イベントで人格の謝り文言（「今つながりにくいみたい…」）を返す。部分応答は履歴に保存されない（Core の既存挙動どおり）

## データ構造（Store への読み取り専用の追加）

| メソッド | シグネチャ | 説明 |
|------|------|------|
| list_sessions | `list_sessions(limit=100) -> list[dict]` | sessions を last_activity 降順で返す |
| get_archived_history | `get_archived_history(session_id) -> list[dict]` | archived_history から時系列で返す（蒸留済みセッションの閲覧用） |

- どちらも SELECT のみ。書き込み経路は増やさない

## 例外処理

- Ollama 未起動: 起動時チェックで検知し、コンソールにエラーを出して終了（ブラウザは開かない）
- ポート 8765 使用中: エラーメッセージを出して終了（多重起動の可能性を案内）
- ターン中のブラウザ閉じ: サーバ側のターンは完走し履歴に保存される（次回開いたとき履歴に残っている）
