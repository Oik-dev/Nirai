# コンパニオンAIメモリ設計 — 研究蒸留

出所: Gemini研究会話ログ（原本: `docs/research/originals/コンパニオンAIの最新メモリ設計_geminiログ.json`）からの蒸留。蒸留日 2026-07-03。

---

## 1. 設計に直結する結論（Serina 3b/3c/スライス4に効く知見）

- **ファクト抽出だけのRAGは「情緒的文脈」を削ぎ落とす**。日記（ナラティブ）形式で自然言語のまま保存する方が、関係性の温度を再現しやすい。→ Serina 3bの「二役リフレクション」で日記＝Aurora本人が一人称執筆、という形で採用済み。
- **階層型メモリ（Working→Episodic→Semantic）**が業界の主流構造。生会話を直接長期記憶に入れず、段階的に圧縮・抽象化する。→ Serinaの Track A（エピソード日記）／Track B（ファクトブック）分離、およびスライス4の4a（週次再固結：日記群→傾向・信念）に対応。
- **キャラクター・ステートを独立オブジェクトとして持続させる**（RAGの受動的想起だけでなく、能動的な「今の姿勢」を常時プロンプト注入）。→ Serinaの `intimacy/tension/energy_level/narrative_mood` の常時注入設計に一致。
- **12Bクラスのローカルモデルには JSON より XML タグ出力の方が安定する**（コンマ抜け・ネスト崩れが起きにくく、前方一致の正規表現で救済しやすい）。→ Serina 3bで採用済み（`<diary>` `<new_facts>` `<state_update>` 等）。
- **「二本立て（ツートラック）記憶」で重要ファクトの損失を防ぐ**。日記のように要約で薄めると、アレルギー等の不変事実が消える危険がある。ファクトは新規判明時のみキー・バリューで直接マージ・上書きし、要約対象から外す。→ Track A/B分離として採用済み。
- **感情ステートの「ベタ惚れ張り付き」（Sycophancy Trap／おべっかトラップ）は、恒常性（重力）の実装がないと必ず起きる**。優しい会話が続くだけで数値が単調増加し、全キャラが親密度1.0に収束する。→ Serina決定2（ハイブリッド重力）で対処。
- **感情パラメータは「数値3つ＋自由記述1つ」が12Bモデルにとって限界かつ最適**。増やすほどパラメータ間の矛盾（悲しみと怒りが同時1.0等）でモデルが混乱する。数値は態度のアウトライン、自由記述（narrative_mood）が葛藤やグラデーションを担う。→ Serinaでそのまま採用（intimacy/tension/energy_level + narrative_mood）。
- **リフレクションを担うモデルは無検閲（Abliterated/Heretic系）の中立な書記であるべき**。センシティブな会話内容に対する安全ガードレールの拒絶・お説教を避け、事実に忠実に抽出させるため。人格は乗せない。→ Serina決定4（理性エンジン＝Gemma4-12B無検閲）に発展的に継承。
- **単一の固定時間トリガー（例: 6時間）は本質的に脆い**。連続対話でコンテキストが破綻する／低価値な短い対話でも発火してリソース浪費、の両方が起きる。ログ内の議論では「容量（ターン数・トークン量）×タイムアウト」のハイブリッドが有力候補として浮上（結論は未確定のまま議論終了）。→ Serinaは6時間＋生活日（AM4:00）のハイブリッドで確定させたが、容量トリガー（30ターン等での部分リフレクション）は将来検討として明記されたのみで未実装。

## 2. 採用を検討すべき手法（根拠つき）

- **エントロピー・ドリフト（恒常性への回帰）**: `Next_State = Current_State + (Baseline − Current_State) × Gravity_Factor` という磁石的な引き戻し計算。根拠: 人間の感情は一時的スパイクでありベースラインに戻ろうとする（恒常性）。この重力がないと数値は蓄積する一方になる、とログ内で明確に指摘されている。
- **快楽適応・退屈（Habituation）カウンター**: 同じ肯定パターンが繰り返されると増加幅をゼロに制限し、むしろ「退屈」方向へ振れさせる。根拠: 同じ褒め言葉の連続は人間でも喜び→退屈にシフトするため、単純累積は不自然。
- **愛情表現の拒絶閾値（Intimacy Defense Mechanism）**: 親密さが95%以上に達したら、単純加算でなく tension を跳ね上げてツンデレ的な「引き」を発生させる。根拠: 愛着理論。限界値での急な冷たさが「照れているのかな」という追いかけたくなるダイナミクスを生む。→ Serina §5.4「愛情表現の拒絶閾値」としてそのまま採用済み。
- **不在時間の外乱注入（Offscreen Events）**: AIが常にユーザーの呼びかけを待つだけの存在だと関係性の主導権が100%ユーザー側に偏る。AI側の「生活の文脈」（寝不足、システムログ整理中に発見したことなど）を起動時イベントとして強制的に注入する。根拠: 感情がユーザー入力だけに依存する閉じたループを破壊し、人間らしい複雑さを演出。→ Serinaのスライス4「不在時間の内的生活（idle_thought）」に発展継承（ただし捏造ガード付きに強化）。
- **先行研究の複数動的シグナル方式**（Stanford Generative Agents型の累積重要度スコア、エージェントのエネルギー/疲労度モデル、セッション文脈検知など）: 単一タイマーでなく複数シグナルを組み合わせる方向性が業界標準になりつつある、という指摘（ログ内では個々の手法の優劣は未確定のまま終了）。

## 3. 落とし穴・失敗パターン（ログ内で指摘されたもの）

- **JSONを12B以下のモデルに厳密出力させると構文エラーで容易にクラッシュする**（カンマ抜け、ブラケット閉じ忘れ）。XMLタグ＋前方一致パーサでフォールバックする方が堅牢。
- **同一箱で日記とファクトを混ぜて要約すると、重要ファクトが薄れて消失する**（ログ内の「ピーナッツアレルギー」の例え話）。ツートラック分離が必須。
- **数値ステートに重力（ベースライン回帰）を実装し忘れると、クランプ（変動幅制限）だけでは張り付き問題を防げない**。ログの会話自体、一度この抜け漏れを起こし後から補強している（重力式なしでは「±0.15に制限してもジワジワ上昇し続け、最終的に全員1.0に張り付く」と自己修正）。
- **感情パラメータを増やしすぎるとモデルが混乱する**。プルチックの感情の輪（8方向ベクトル）はアプローチとして美しいが、「親密になると最高値に張り付いたまま動かなくなる（飽和状態のトラップ）」という強力な弱点を持つ、と結論づけられている。
- **一律の時間ベーストリガー（6時間固定）は「無限対話の罠」と「低価値リフレクションの乱発」の両方を引き起こす**。10時間連続対話ではリフレクションが一切走らずコンテキストが肥大化する一方、2往復だけの挨拶でも6時間後には律儀に発火してリソースを浪費する。
- **新規セッションはそれ以前の会話履歴を一切参照できない**（ログ内で明示的に確認された制約）。長い議論の要点を持ち越すには、要約テキストを次セッションの最初のメッセージとして手動で渡す必要がある。これはGemini AI Studio運用上の制約であり、Serina自体の設計論点ではない。

## 4. Serina現行設計との差分メモ

ログの提案とSerinaの最終決定（`docs/specs/基本設計書_スライス3_リフレクション.md`、`docs/DECISIONS.md` に基づく）が食い違う、または発展している点。

| 論点 | ログでの提案 | Serinaの現行決定 |
|---|---|---|
| 重力（恒常性）の駆動方式 | 毎リフレクション一律10%固定（`Next_State = Current + (Baseline-Current)×0.1`） | **実時間×リフレクション回数のハイブリッド**（決定2）。時の力は実経過時間で駆動（τ=3日、`g=1-e^(-Δt/τ)`）、言葉の力はAI提案差分で駆動。ログの「一律10%」方式は明示的に破棄されている |
| 減衰スコアの計算式 | 単純乗算 `Score = Base_Relevance × e^(−λΔt)` | **フロア付き乗算**（`Score = α·relevance·(κ+(1−κ)·decay) + γ·importance`、κ=0.35）。単純乗算では「関連度が高い古い記憶が浮上できない」問題が生じるため改訂 |
| コアファクトの半減期 | 約180日（長期・コアファクト） | 同じく180日で採用（決定1）だが、**「二経路想起」**（自発想起=減衰スコア／トリガー想起=キーワード検知で減衰無視の静的マウント）を追加し、重要事実が沈んでいても事故らない設計を補強 |
| リフレクションの担当モデル構成 | 中立な書記モデル1体のみ（日記もファクトも同一モデルが処理） | **二役（ツーハット）**（決定3）。日記本文はセリナ本人（Aurora）が自分の声で書き、事実抽出・感情採点は別の理性エンジンが担当。当事者に自己採点させるとおべっかループになるため分離 |
| 理性エンジンのモデル候補 | Qwen2.5-Instruct系 7Bクラス無検閲 | **Gemma 4 12B無検閲（Heretic系）に確定**（決定4）。EQ-Bench最強クラスの機微読解＋高い構造化抽出適性を根拠に選定。交換可能な設計 |
| 発火トリガー | 6時間固定 → 議論の末「容量×タイムアウトのハイブリッド」が有力候補として浮上するも未確定のまま終了 | **6時間 OR 生活日（AM4:00）跨ぎのハイブリッドで確定**。容量ベース（30ターン等）の部分リフレクションは3a追補で「将来検討」として明記のみ、未実装 |
| 生ログの扱い | 「デバッグ期は退避、本番は物理削除」という二段階方針の記述あり | **恒久的にアーカイブ退避（30日保持）を採用、物理削除はしない**。起点も元発言時刻ではなく退避時刻（archived_at）に修正済み（ログにはこの起点論点自体が存在しない） |
| ネガティブ記憶・好奇心キュー | ログには明確な言及なし（不明瞭） | Serina独自の企画拡張として、ネガティブ記憶の対等記録・好奇心キュー（open_threads）を3bへ前倒し採用（ログ由来ではなく2026-07-02のマスター企画レビューが出所） |
| 感情ステートのパラメータ数 | 3数値＋自由記述1（ログとSerinaで一致） | 差分なし。intimacy/tension/energy_level + narrative_mood をそのまま採用 |

（ログ内では発火トリガーの最終形（容量×タイムアウトの具体的な閾値）は合意に至っておらず「（ログ内では未確定）」のまま会話が中断している。Serina側で独自に6時間＋生活日方式へ確定させた。）
