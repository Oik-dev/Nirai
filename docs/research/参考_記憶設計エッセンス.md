## 1. 二層記憶：ホットキャッシュ／コールドストア（memory-management より）

- **ホット層**: 毎回システムプロンプトに必ず載せる少量の記憶（目安50〜100行）。「日常会話の9割をこれだけで解読できる」ことを目標にする。
- **コールド層**: 全量DB（Serinaでは SQLite+vector）。ホットで解決しない時だけ検索。
- **昇格・降格ルール**（ここが肝）:
  - 昇格: 頻繁に参照される記憶 → ホット層へ
  - 降格: 使われなくなった記憶 → ホット層から外しコールドのみに
- **Serinaへの適用案**: pinned（呪文）＝ホット層の原型。そこに「参照頻度カウンタによる自動昇格・降格」を足すと、ホット層が生き物のように新陳代謝する。
  - 用語解説 — ホットキャッシュ: 「よく使う物だけ机の上に置き、残りは棚にしまう」こと。8GB VRAM＝机が狭いSerinaに最も効く思想。

## 2. デコーダーリング：呼び名・略語・コードネーム辞書（memory-management より）

- マスターの省略語・あだ名・「いつもの」を解読する専用辞書を持つ。
  - 例: 「トッド」→ フルネーム＋役割、「PSR」→ 正式名称＋文脈、「フェニックス」→ プロジェクト実体
- **別名（エイリアス）を必ず全部記録する**のがコツ。「T」もトッド、「例の移行」もフェニックス。
- **Serinaへの適用案**: 記憶ユニットに `aliases`（別名リスト）フィールドを持たせる、または用語→実体の対応表を独立テーブルに。相棒AIが「あれやっといて」を解読できるかはここで決まる。

## 3. 想起の規律：いつ・どう思い出すか（remembering-conversations より）

**検索トリガー（Coreが Memory検索を発動すべき条件）:**
- 発話に履歴シグナルがある: 「前に」「この間」「言ったよね」「覚えてる？」
- 過去に似た話題・作業をした可能性がある時
- 「知らない」と答える前（推測やシラを切る前に必ず一度検索）

**検索しない条件（無駄打ち防止）:**
- 今の会話内に答えがある時
- そもそも質問の意味を理解する前

**想起フロー:** 検索 → 上位2〜5件だけ読む → 要約統合して応答に使う。
生ログを全部読み込むのに比べ**コンテキスト消費を50〜100分の1に節約**できる（＝ローカル12Bの小さい文脈窓と相性が良い）。

## 4. 揮発／永続の経路分離（deep-agents-memory より・唯一の収穫）

- 「セッション内だけの作業メモ（揮発）」と「セッションを跨いで残す記憶（永続）」を、**保存先の経路で機械的に分ける**設計。
  - 例: `/memories/` 配下に書いたものだけ永続、それ以外は揮発
- **Serinaへの適用案**: 会話中の一時的な文脈（今日の話の流れ）と、長期記憶DBへ昇格させる記憶を明示的に分離。「何を永続化するか」の判断をルール（経路）に落とすと、Coreの実装がシンプルになる。
- ※このSkillの残り9割は LangChain `deepagents` 専用のコード例で、Serina（自前Core＋Ollama）には無関係だった。
