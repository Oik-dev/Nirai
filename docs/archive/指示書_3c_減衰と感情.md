## タスク1: 正典キーワードのバックフィル（新規 `tools/backfill_keywords.py`）

**3cの前提穴埋め**: トリガー想起は `metadata.trigger_keywords` で発火するが、移行v2由来の記憶（pinned 9件を含む858件）はこれを持たない。pinned特例を撤去する前に、**少なくとも pinned 9件**へキーワードを付与する。

- 対象: `pinned = 1` の全記憶（9件）。`--all-facts` オプションで type='fact'/'knowledge' 全件へ拡張可能（既定はpinnedのみ。858件の一括生成は時間がかかるため任意）。
- 生成: 理性エンジン（`reason_model`, keep_alive=0）に記憶本文を渡し、`<keywords>京都,引っ越し,…</keywords>` 形式で3〜8語（**別名・表記ゆれ・言い換えを含む**、3bのデコーダーリング規定と同じ）を生成させる。パースは `reflection_parser.extract_block("keywords", ...)` を流用。
- 書き込み: 既存 `metadata` に `trigger_keywords` をマージ（`store.update(id, metadata=...)`。content不変なので再埋め込みは走らない）。**既に trigger_keywords を持つ記憶はスキップ**（冪等）。
- 出力: 日本語レポート（ID・本文先頭・付与キーワード）を必ず印字（無言破棄禁止の系）。マスターが後から目視で直せるよう `--dry-run` を用意。

## タスク2: 検索設定の刷新（`memory/config.py`）

`SearchConfig` を以下へ改訂（旧 `beta` / `recency_half_life_days` は**削除**。鮮度は関連度への乗算ゲートに一本化）:

```python
@dataclass
class SearchConfig:
    """ハイブリッド検索の係数（3c: フロア付き乗算）"""

    alpha: float = 0.85   # 関連度
    gamma: float = 0.15   # 重要度
    kappa: float = 0.35   # 減衰フロア（0=完全乗算、1=減衰なし）
    vector_candidate_multiplier: int = 5
    # type → 半減期（日）。metadata.half_life_days があれば個別上書き
    half_life_days_by_type: dict = field(default_factory=lambda: {
        "fact": 180.0, "knowledge": 180.0, "relationship": 180.0,
        "promise": 180.0, "belief": 180.0,      # belief は4a用の予約値（現状未使用）
        "diary": 30.0, "event": 30.0,
        "growth_note": 30.0,                     # 4a用の予約値（現状未使用）
    })
    default_half_life_days: float = 30.0
```

- 半減期の持ち方は**「type→H マッピング＋metadata個別上書き」に確定**（列追加はしない。設計書§3cの選択肢を解消）。
- 実装前に `SELECT DISTINCT type FROM memories` で実DBの type 一覧を確認し、漏れている type をマップに追加すること（短期3日の type は現状存在しない想定。将来の一時的関心事用に予約とだけコメント）。

## タスク3: スコア刷新と pinned特例撤去（`memory/store.py`）

**`_recency_score` → `_decay_score` に置換**:

```python
def _decay_score(self, mem: dict, now: datetime) -> float:
    """e^(−ln2·Δt/H)。pinned は減衰しない（decay=1.0）。Δt は last_accessed 起点（再活性化リセット継承）。"""
    if mem.get("pinned"):
        return 1.0
    meta = mem.get("metadata") or {}
    h = float(meta.get("half_life_days") or
              self.search_config.half_life_days_by_type.get(
                  mem["type"], self.search_config.default_half_life_days))
    delta_days = max((now - _parse_iso(mem["last_accessed"])).total_seconds() / 86400.0, 0.0)
    return math.exp(-math.log(2) * delta_days / h)
```

**`_hybrid_score` をフロア付き乗算へ**:
```python
score = α · relevance · (κ + (1−κ) · decay) + γ · importance
```

**`search` の変更3点**:
1. **pinned の候補ユニオン（distance=2.0 で全pinnedを混ぜる処理）を撤去**。pinned もベクトルKNNで戦う（減衰免除のみ特権）。`get_all_pinned` メソッド自体は残す（migrate/検証ツールが使用）。
2. **失効除外**: 候補整形時、`metadata.invalidated_at` が入っている記憶を除外する（Python側でフィルタ。JSON1依存を増やさない）。
3. 戻り値の `recency` キーは `decay` に改名（smoke.py 等の表示があれば追従修正）。

## タスク6: 感情重力パイプライン（`core/reflection.py` `_apply_state`）

3bの「[0,1]クランプのみ」を、設計書§3cの5段パイプラインへ置換:

```
Δt = now − profile[emotion.last_state_update]（日数。キー欠損時は g=1 とし提案値ベースで初期化）
g  = 1 − e^(−Δt / τ)
S0 = 現在値（欠損時はベースライン）
① S1 = S0 + (Baseline − S0) × g                     # 時の力
② S2 = S1 + clamp(提案値 − S0, −0.15, +0.15)         # 言葉の力（提案Δは S0 起点。理性エンジンには現在値=S0 を渡している）
③ intimacy の最終値 ≥ 0.95 のとき tension のみ S3 = S2 + spike（クランプ貫通、[0,1]内）
④ 最終 clamp [0,1]
⑤ emotion.last_state_update = now
```

- 適用順: intimacy → tension → energy_level（③が intimacy 確定後に tension を参照するため）。
- 監査ログの reason には理性エンジンの根拠に加え、`(時の力: S0→S1, 言葉: +Δ, 照れ隠し: +spike)` の内訳を付記する（Opusの再判定材料）。
- パース不能値の破棄・narrative_mood の扱いは3bのまま。
