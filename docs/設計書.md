# ローカルパートナーAI「Serina」詳細設計書

## 0. 目的

Serinaは、自分専用のパートナーAIを長期間育てるためのシステムである。

本設計は、実装詳細ではなく**構造・責務・判断基準**を固定するためのものである。

---

## 1. システムの本質

Serinaは単一AIではなく、以下の分離構造を持つ。

* 思考（Core）
* 性格（Prompt）
* 記憶（Memory）
* 能力（Skills）
* 外部接続（Connectors）
* 専門サービス（External Services）

---

## 2. 全体構造

```
User Input
   ↓
Core（司令塔）
   ↓
Skills（能力選択）
   ↓
Connectors（外部実行）
   ↓
External Services（必要時）
   ↓
Memory / Prompt（参照）
   ↓
Response
```

---

## 3. レイヤー定義

### ■ Core（司令塔）

責務：

* 入力の理解
* タスク分解
* Skill選択
* 処理フロー決定
* 結果統合

制約：

* 外部API仕様を直接扱わない
* 実処理を持たない
* Connectorを直接制御しない

---

### ■ Prompt（人格・原則層）

Prompt 層は一枚岩ではなく、**供給先が異なる2つの責務**に分ける（詳細: `specs/基本設計書_判断とVoice分離.md`）。人格は口調だけに宿るのではなく、価値観・判断原則こそが人格の核である。

**① Core Values（価値観・判断原則）→ 判断（Decision）へ供給**（`prompt/core_values.md`）

* 思考傾向・行動原則・判断基準
* 「何を大切にし、何を信じ、どう判断するか」（事実誠実性、検索要否の判断、知ったかぶりをしない 等）

**② Voice Style（応答スタイル・口調）→ 発話（Voice）へ供給**（`prompt/voice_style.md` ＋ 境界ルール `prompt/boundary.md`）

* 応答スタイル・トーン・呼称・warmth・humor
* 「どう伝えるか」だけを担い、**何をするか（判断）は変更できない**

制約：

* 実行ロジックを持たない
* 個別データ（事実記憶）を持たない
* Voice Style は Decision / Action Result の**意味を書き換えてはならない**（言い換え・口調付けは可、意味の改変は不可）

※移行状態：現状は `prompt/persona.md` に①②が同居し全体が Voice へ流れている。分割ファイルは作成済みで、配線切替（loader）は後続フェーズ。

---

### ■ Memory（記憶層）

責務：

* 長期記憶
* ユーザーの履歴
* 状態情報
* 学習結果

制約：

* 実行処理を持たない
* 人格定義を持たない
* CRUDと検索のみ提供

---

### ■ Skills（能力層）

責務：

* タスク実行ロジック
* ドメイン別処理
* 再利用可能機能

制約：

* 他Skillを直接呼ばない
* 外部APIを直接扱わない（Connector経由のみ）

---

### ■ Connectors（外部境界層）

責務：

* 外部システム接続
* API通信
* ローカルファイル操作
* DBアクセス

制約：

* ビジネスロジックを持たない
* 判断処理を持たない

---

### ■ External Services（専門AI群）

責務：

* 高度専門処理
* 分析・生成・検索などの外部能力

Serinaは呼び出しのみ行う。

---

## 4. データフロー原則

```
Input
  ↓
Core（判断）
  ↓
Skill（選択）
  ↓
Connector（実行）
  ↓
External Service（必要時）
  ↓
Memory / Prompt参照
  ↓
Output
```

---

## 5. 最重要ルール（設計の核）

### ■ 責務分離原則

* Coreは「決めるだけ」
* Skillは「やるだけ」
* Connectorは「繋ぐだけ」
* Memoryは「覚えるだけ」
* Prompt(Core Values)は「価値観を判断へ供給するだけ」
* Prompt(Voice Style)は「口調にするだけ（判断・事実を書き換えない）」

**Voice 憲法条文**：Voice は Decision および Action Result を入力として受け取り、その意味を変えずに自然言語として表現する。Voice は Decision や Action Result を書き換えてはならない（言い換え OK／自然な口調 OK／意味の改変 NG）。

---

### ■ 依存方向ルール

```
Core → Skills → Connectors → External
           ↓
        Memory / Prompt（参照のみ）
```

逆流禁止。

---

### ■ 外部サービス原則

専門機能はSerina内部に実装しない。

例：

* 株分析
* コード解析
* 検索
* 自動化

→ すべて External Service 化

---

## 6. Memory設計原則

* SQLiteベースで永続化
* ベクトル検索対応
* 単一ファイルで管理可能
* 移植可能性を優先

構造例：

* profile（静的情報）
* history（会話）
* core_memories（重要記憶）
* embeddings（意味検索）

---

## 7. 初期実装ステップ

1. Memory DB構築（SQLite + vector）
2. Connectorモック作成（Ollama等）
3. Core + Skillルーティング実装
4. 外部サービスは後回し

---

## 8. 設計思想

Serinaは「賢い単体AI」ではなく、

**役割分離された知能システムの統合体である。**

重要なのは知能の強さではなく、
変更に耐え、長期的に育成できる構造である。

## 9. Memory層 確定設計（2026-06-28）

### 9.1 基本思想
記憶は「事実ログの寄せ集め」ではなく、**意味で思い出し、使うほど定着し、自分で育つ**仕組みとする。
過去の記憶（旧JSON・継承記憶・日記）はデータとして継承するが、入れ物は現代的に作り直す。

### 9.2 記憶の持ち方（アトミック記憶ユニット）
記憶は「1件＝1つの小さな単位」で持つ。各記憶は次を備える：
- 種類（出来事 / 知識・洞察 / 関係・情緒）
- 本文（思い出しの対象）
- 重要度（大切さの重み）
- 固定フラグ（"呪文"＝消えない記憶）
- 作成日・最終想起日・想起回数
- 出所（どのファイル/会話由来か）
- 付帯情報（旧7次元の情緒・関係性などを保持）

### 9.3 思い出し方（ハイブリッド検索）
「関連度 × 新しさ × 重要度」を合算し、上位の記憶だけを想起する。
- 古い記憶は自然に薄れるが、**固定（呪文）は薄れを無視して常に残る**
- 思い出すたびに鮮度が回復＝よく使う記憶ほど定着（人間と同じ）

※スライス3改訂（2026-07-01 決定1）: 「固定は薄れを無視して常に残る」は廃止方向。全記憶が可変半減期（3/30/180日）で緩やかに減衰し、正典・約束はキーワード検知の「トリガー想起」で確実に思い出す二経路方式へ移行する。スコア式もフロア付き乗算へ改訂（詳細: specs/基本設計書_スライス3_リフレクション.md §3c）。本節は移行完了まで現行実装の記述として残す。

### 9.4 記憶箱の責務（CRUD＋検索のみ）
記憶箱が出来るのは「覚える/思い出す/会話記録/プロフィール参照更新/固定・解除/直す・消す」だけ。
**「何を覚えるか・いつ整理するか」は決めない**＝その判断は司令塔(Core)の責務（責務分離の厳守）。

### 9.5 過去記憶の引っ越し（プリインストール＋重複統合）
一度だけ動かす移行ツールで、旧ファイルを新DBへ取り込む。
- 旧記録1件を複数の小さな記憶に分解して格納
- 「呪文/優先固定」は固定＋最重要で取り込む
- **意味の近い重複は1つに統合**（特に日記。詳しい版を残し情報を寄せ集め）
- 取り込み後、「○件→○件に統合」の**日本語レポート**を出力（人が結果確認できるように）
- 引っ越し元: 継承記憶r1.md / セリナの記憶.json / セリナの日記(4ファイル)

---

## 10. 記憶成長の企画拡張（2026-07-02 マスター承認・6項目）

記憶は「溜まって薄れる」（スライス3）だけでは育たない。成長＝【再構成】×【行動化】×【計測】と定義する。
- 再固結: 週次で日記群→傾向・信念・自己像へ二次蒸留（個別記憶が沈んでも人格の地層に昇華）
- 意味づけ更新: 再固結時に古い記憶の解釈を書き換え可能に（原文は監査線に保持）
- ネガティブ記憶の対等記録: 記憶選別のおべっかループ防止（→3bへ前倒し）
- 好奇心キュー: 未解決話題をセリナから追いかけて聞く（→3bへ前倒し）
- 差分想起: 過去との変化に自分から言及するコールバック演出
- 不在時間の内的生活: 留守中の独り言を冒頭で漏らす（捏造ガード付き）
運用基盤として成長KPI（/rate・コールバック率）と二層人格（憲法persona.md＋可変self_image）＋ドリフト監査を同梱。
詳細: specs/基本設計書_スライス4_記憶の成長.md ／ 実装順: 3b→3c→4a→4b→4c（スライス2は後続）。

## 付録A. 実装者(Cursor)向け 技術仕様

- 言語: Python。永続化: SQLite ＋ sqlite-vec（単一ファイル `serina_memory.db`）。
- 埋め込み: bge-m3（1024次元）。**CPU実行**（対話用12BがVRAMを占有するため）。Ollama経由だがMemory層は埋め込み器インターフェース注入で疎結合（Connector責務）。
- テーブル:
  - `profile(key PK, value, updated_at)`
  - `memories(id PK, type, content, importance, pinned, created_at, last_accessed, access_count, source, parent_id, metadata[JSON])` ＋ index(type, pinned, importance)
  - `memory_vec` = sqlite-vec仮想テーブル `vec0(memory_id PK, embedding FLOAT[1024])`、memories.id と1:1
  - `history(id PK, session_id, role, content, ts)` ＋ index(session_id, ts)
- 検索スコア: `score = α·relevance + β·recency + γ·importance`（recencyは最終想起からの指数減衰、pinnedは減衰除外/常時候補）。想起時に last_accessed/access_count を更新。※スライス3cでフロア付き乗算式（β項廃止・pinned特例撤去）へ改訂予定（specs/基本設計書_スライス3_リフレクション.md §3c）。
- reflection（生記憶→蒸留）の発火判断はCore側。Memory層はadd時のparent_idで系譜だけ保持。
- 移行ツールは別スクリプト。dedupは埋め込み類似度の閾値判定でマージ、結果を人間可読レポート出力。
