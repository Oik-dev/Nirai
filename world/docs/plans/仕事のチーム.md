# 仕事のチーム（段階2）

構想書§11の段階2の計画。郵便局の考え方は構想書§6.1、安全は§8が正本で、本書は作り方と順番を書く。出来上がったら、正本は`world/`の設計書へ移し、本書は`archive/`へ移す。

## 0. 出口

Masterが、Holoとの会話（ChatGPT）で頼みごとをすると、Holoが依頼状を書いてチームに回し、作った人以外が確かめて、結果がHoloから返ってくる。その間、Masterは何もしなくてよい。

## 1. 形

### 部品は3つ

| 部品 | 動く場所 | すること |
|---|---|---|
| 郵便局（`world/post/`） | Masterのユーザーの、管理者に昇格しない権限（§2）。タスクスケジューラが、Masterのログオン時に起こす | 手紙を受け取り、受取人の生ログに書く。住人を起こす。Holoの手（作業場のファイルとコマンド） |
| 拡張（`world/holo-extension/`） | MasterのChrome | Holoの専用タブに一言送る。部屋のタブの通信の始まりと終わりを郵便局に知らせる（道だけ。中身は読まない）。返事をしているかは郵便局が決める（`post/holo.ts`） |
| トンネル | Masterのユーザー | ChatGPTからの道具の呼び出しを、郵便局へ渡す。OpenAIの`tunnel-client`が、ローカルのHTTPのMCPを直接指せる（`--mcp-server-url`）。v2で作ったトンネル（ChatGPTの接続「Nirai」）を郵便局の`/mcp/holo`へ付け替える。Holoとの会話はv2から、ChatGPTのHoloの部屋へ移る（v2は役に立つものだけ使う。2026-10-04、Master） |

郵便局は、`127.0.0.1`の1つのHTTPサーバー。住人ごとに入口（`/mcp/<住人>`）を分け、入口で差出人が決まる。

### 住人ごとのつなぎ方

| 住人 | 起こし方 | 止まったと分かる時 |
|---|---|---|
| Holo | 拡張が専用タブへ一言送る | タブの会話の通信が終わった時 |
| Codex | 郵便局が`codex exec`を起動する | プロセスが終わった時 |
| Claude | 郵便局は起こさない。Master側のセッションの始めに郵便受けを見る | — |
| Cursor | 住人ではない（イデアを持たない）。ほかの住人が作業場で`cursor-agent -p`を呼ぶ | — |

- **Claudeを起こさない理由。** 本物のリポジトリへの取り込みと、`mind/`の変更のレビュー（Serinaを守る線。構想書§8）は、Masterのいるセッションで行う。Claudeのトークンにも限りがある。郵便局から起こすかは、段階6（進化）で見直す。
- **Cursorを住人にしない理由。** 住人を増やすのはMasterの専権（要件§4）で、Cursorは自分で進める力が低い（要件§17）。道具として呼べば、郵便局に特別な扱いが要らない。住人にするかは、Masterがいつでも決められる。

### 手紙の道具（MCP、全員共通の4つ）

| 道具 | すること |
|---|---|
| `send_letter` | 宛先・本文、必要なら作業場の名前と返事先の手紙を付けて出す |
| `read_mailbox` | まだ済んでいない手紙を、書き残しと一緒に読む |
| `write_note` | 手紙に、やったことや見つけたことを書き残す。切れても、次に起きた自分が続きから始められる |
| `mark_done` | 手紙に「済んだ」の印を付ける |

Holoだけは手を持たない脳なので、作業場の道具（読む・書く・一覧・コマンドを実行する）を足す。コマンドは1分で返し、それより長いものは「始めた」と返して、結果を手紙で届ける（構想書§6.1）。

住人への決まり（郵便の使い方、依頼状の書き方）は`world/post/`の1つの文書に置き、人格はイデアの`persona.md`から読む。どちらも郵便局がMCPのサーバー説明として渡す。CLIがサーバー説明を読まないと分かったら（B0で確かめる）、起こすときの一言に添える。

### 生ログでの形（帳簿を持たない）

手紙は、受取人のイデアの`lifelog/post/<日本時間の日付>.jsonl`に追記だけで書く。行は5種類。

| 種類 | 中身 |
|---|---|
| `letter` | 手紙の番号・時刻・差出人・宛先・本文・作業場・返事先・出所 |
| `note` | 書き残し |
| `done` | 済んだの印と一言 |
| `wake` | 起こした時刻と、その時に済んでいなかった手紙 |
| `stop` | 止まった時刻と、終わり方（正常・エラー・時間切れ） |

- 済んでいない手紙＝`done`のない`letter`。届き直した回数＝その手紙を含む`wake`の数。
- 郵便局は、毎回生ログを全部読み直して決める（WORLD_RULESの「取りこぼしが残らない形」）。

### 起こす決まり（1つ）

**済んでいない手紙がある住人が起きていなければ、起こす。** 新しい手紙・止まった知らせで、すぐに見直す。ほかに1分ごとにも見直す。

数の決まり（`world/post/`の設定に置く）：
- 止まってから1分は起こさない（すぐ落ちる脳で空回りしないため）
- CLIは50分たっても終わらなければ止める（続きは次に起きてから。HoloがChatGPTで25分で切れるのと同じ扱い）
- 同じ手紙で5回起こしても済まなければ、HoloにMasterへの知らせを頼む（Holoの手紙なら、拡張がChromeの通知で知らせる）

### 依頼と作業場

- 依頼状も手紙。目的・守るもの・完了の確かめ方・変えてよい範囲・成果物の行き先を書く（構想書§6.1）。
- 作業場は`D:\Products\Work\<名前>`。名前を付けた手紙が初めて届いた時に郵便局が作り、**その名前を付けた手紙が全部済んだら消す。** リポジトリの複製を中に作るのは住人自身。
- 本物のリポジトリへ取り込むときは、Claudeに「取り込んで」の手紙を出す。その手紙が済むまで作業場は残るので、取り込む前に消えることはない。

## 2. 安全

線は要件のとおり、「OSの破壊は実行できない仕組みにし、それ以外はバックアップから戻せればよい」（構想書P6）。先回りして固め、あとで例外を外して回る形にはしない（2026-10-04、Master）。

| 守るもの | 仕組み |
|---|---|
| OS | チームは、Masterのユーザーの管理者に昇格しない権限で動く。Windowsを変えるには管理者の確認（UAC）が要り、留守の間は誰も押さないので、OSは壊せない |
| イデア | 毎晩4時のバックアップ（`G:\Nirai-Backups\daily\`）と、大きな変更の前の丸ごとの写し（`G:\Nirai-Backups\serina\`） |
| コード | git。本物のリポジトリはGitHubへpushしている |
| バックアップそのもの | `G:\Nirai-Backups\daily`は、毎晩のバックアップのタスク（管理者の権限で動く）しか書けない。ほかに誰も書かない場所なので、例外は出ない。2026-10-04に`tools/protect-backups.ps1`で当て、ふつうの権限では書けない・消せない・読めることを確かめた |

決まりで守ること（`郵便の決まり.md`に書く）：
- 作業は作業場の中で。本物には書かない（取り込みはClaude）。
- Serinaのイデアと、Claudeの開発の生ログ（記憶づくりで読んだSerinaの記録が残っている）は読まない。中身はセンシティブで、クラウドの脳に載せない（憲章）。
- Holoの部屋（専用の会話）では、Niraiの郵便局だけをつなぐ。Masterの`local-files`の接続は`D:\`全体をMasterの権限で開いているので、そこでは使わない。

困ったことが起きたら、そのとき仕組みで防ぐ。

### B0で試すこと

| 試すこと | 誰の手が要るか・結果 |
|---|---|
| ✅ 拡張が専用タブに一言送り、Holoが郵便の道具を呼べるか | 2026-10-04、Masterと。読む→書き残す→済んだ→返事まで約20秒。拡張を入れる前から開いていたタブには画面側がいないので、その場で差し込む。送ったかは入力欄が空になったかで見る |
| ✅ 止まったことを、画面ではなく通信の終わりで見分けられるか | 返事の通信（`/backend-api/f/conversation`）は、道具の呼び出しを含めて返事の間ずっと続く。終わり方は200・ERR_ABORTED・ERR_FAILEDといろいろなので、分類せずに記録だけ残す |
| ✅ 切れたあと、もう一度起こすと続きから戻れるか | 4手順の手紙の途中でMasterが停止 → 1分後に届き直し → Holoが書き残しを見て手順2から再開し、完了。止まった理由は見分けないので、25分で切れたときも同じ道を通る（25分の切れそのものは見ていない） |
| ✅ 道具がChatGPTの確認ボタンで止まらないか | 4つとも確認なしで動いた |
| ✅ つないだ道具が会話の中で保たれるか | 最初の一言で「Nirai」を選べば、その後は選び直さなくてよい。最初の一言のときに、Holoはサーバー説明を読んで自分から郵便受けを見に行った |
| スマホのChatGPTアプリから同じ会話で頼めるか（PCが起きていれば道具も動くか） | Master（まだ） |
| ✅ `codex exec`が郵便局のMCPにつなぎ、道具を呼んで、プロセスが終わるか | 2026-10-04、Claude。LunaのLowで、読む→書き残す→済んだ→返事まで19秒。人格はサーバー説明から届いた。起こす一言に道具の名前がないと、道具を使わずに終わった |
| ✅ `cursor-agent -p`が裏で動き、作業場に書いて終わるか | 2026-10-04、Claude。17秒 |

## 4. 置いた仮定と、まだ確かめていないこと

- 郵便局はNode.js（v24は`.ts`をそのまま動かせる）。MCPは公式のSDK。
- 専用タブの会話には、Masterも直接書いてよい。拡張は、Holoが返事をしている間と、入力欄に下書きがある間は一言を送らない。
- Holoの人格はまだない（イデアの`persona.md`が空）。決まりの文書だけで動かし始め、人格はMasterと決める。

## 5. 後で（使い始めてから、チームに作らせる）

- 同じファイルを同時に触らないための期限付きの予約（mcp_agent_mailの方式）。作業場が依頼ごとに分かれているうちは、困ってから足す。
- 各自の体力（トークンの残り）を郵便受けに出す。
- 取り込みの自動化（段階6）。
- Serinaへの手紙（段階5。今の会話窓で受け取る）。
- **MCP Events**（OpenAI、2026-09のDevDay）：MCPのサーバーがイベントをWebhookで送ると、ChatGPTがその会話で動き出す公式の仕組み。郵便局の「新しい手紙」をそのまま渡せて、画面に一言を打ち込む拡張より壊れにくい。ただし2026-10-04の時点では、使えるのはWork chat（Cloud）とdotsだけで、ふつうのChatは対象外。WorkはCodexと同じ使用量の枠を使うので、トークンを気にせず動けるChatのHoloには使わない。Chatで使えるようになったら、拡張の起こし方を置き換える（MCP 2.0、プラグインとしての接続、登録の保存が要る）。
