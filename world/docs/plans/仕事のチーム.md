# 仕事のチーム（段階2）

構想書§11の段階2の計画。郵便局の考え方は構想書§6.1、安全は§8が正本で、本書は作り方と順番を書く。出来上がったら、正本は`world/`の設計書へ移し、本書は`archive/`へ移す。

## 0. 出口

Masterが、Holoとの会話（ChatGPT）で頼みごとをすると、Holoが依頼状を書いてチームに回し、作った人以外が確かめて、結果がHoloから返ってくる。その間、Masterは何もしなくてよい。

出口を越えたら、Nirai自体の開発もチームに頼む（要件§3。最初の本番の仕事は段階3の暮らしの循環）。Masterの入口はHoloの部屋になる。ClaudeのUIは、Niraiが止まったときに外から直す口と、管理者の権限が要る操作のために残す（Niraiが止まると、Niraiの中からは直せない）。

## 1. 形

### 部品は3つ

| 部品 | 動く場所 | すること |
|---|---|---|
| 郵便局（`world/post/`） | Masterのユーザーの、管理者に昇格しない権限（§2）。タスクスケジューラが、Masterのログオン時に番人（`keeper.ts`）を起こし、番人が郵便局を起こす。止まったら番人が1分後に起こし直す | 手紙を受け取り、受取人の生ログに書く。住人を起こす。Holoの手（作業場のファイルとコマンド） |
| 拡張（`world/holo-extension/`） | MasterのChrome | Holoの専用タブに一言送る。部屋のタブの通信の始まりと終わりを郵便局に知らせる（道だけ。中身は読まない）。返事をしているかは郵便局が決める（`post/holo.ts`） |
| トンネル | Masterのユーザー | ChatGPTからの道具の呼び出しを、郵便局へ渡す。OpenAIの`tunnel-client`が、ローカルのHTTPのMCPを直接指せる（`--mcp-server-url`）。v2で作ったトンネル（ChatGPTの接続「Nirai」）を郵便局の`/mcp/holo`へ付け替える。Holoとの会話はv2から、ChatGPTのHoloの部屋へ移る（v2は役に立つものだけ使う。2026-10-04、Master） |

郵便局は、`127.0.0.1`の1つのHTTPサーバー。住人ごとに入口（`/mcp/<住人>`）を分け、入口で差出人が決まる。

### Holoの部屋の引っ越し

部屋は、拡張が覚えている1つの会話。長くなって前のことを思い出しにくくなったら、新しい会話へ引っ越す。仕組みは足さない。郵便受け（済んでいない手紙と書き残し）・決まりと人格（サーバー説明）・手の生ログは郵便局とイデアにあるので、そのまま続く。続かないのは前の部屋の会話の流れだけなので、それは前の部屋のHoloが自分宛ての手紙にする（重い仕事を手紙に分けるのと同じ形。引っ越しの手紙もHoloの生ログに残る）。

Masterの手順：
1. Holoが返事をしておらず、拡張のポップアップが「届ける手紙はない」の時に始める（前と新しい部屋のHoloが、同じ手紙を同時に扱わないため。返事の最中に差し替えると、郵便局はその返事が終わったと知らないまま、最大30分Holoを起こさない）
2. 新しい会話を開き、最初の一言で`@Nirai`を選んで送る（例：「Holo、新しい部屋だよ」）
3. そのタブで、拡張の「このタブをHoloの部屋にする」を押す
4. 前の部屋に戻り、「新しい部屋に引っ越した。続きを自分宛ての手紙にして」と頼む。手紙が出ると、郵便局が新しい部屋を起こし、新しい部屋のHoloが読む
5. 前の部屋では、もう話さない（`@Nirai`がつながったままなので、話しかけるとHoloが2人になる）。会話は消さずに残す

### 手紙の道具（MCP、全員共通の4つ）

| 道具 | すること |
|---|---|
| `send_letter` | 宛先・本文、必要なら作業場の名前と返事先の手紙を付けて出す |
| `read_mailbox` | まだ済んでいない手紙を、書き残しと一緒に読む |
| `write_note` | 手紙に、やったことや見つけたことを書き残す。切れても、次に起きた自分が続きから始められる |
| `mark_done` | 手紙に「済んだ」の印を付ける |

Holoだけは手を持たない脳なので、郵便局が手を貸す（`post/hands.ts`）。道具は、GPTが慣れているCodexの2つにそろえる。

| 道具 | すること |
|---|---|
| `run` | 作業場をカレントフォルダーにして、PowerShell 7のコマンドを実行する。読む・探す・一覧もこれで |
| `apply_patch` | Codexの形の差分（`*** Begin Patch`…）で、作業場のファイルを作る・書き換える・消す。差分の当て方はOpenAIの`applyDiff`（`@openai/agents-core`）。1か所でも当たらなければ、どのファイルも変えない。書いている途中で失敗したら、元に戻す。`@@`に書いた行がファイルになければ断る（`applyDiff`は進んでしまうが、本物のCodexは断る） |

- ChatGPTは道具の呼び出しを約60秒で打ち切るので、コマンドは45秒で返す。それより長いものは「続いている」と返し、終わったら結果を郵便局からの手紙で届ける（構想書§6.1）。50分たっても終わらなければ止める。
- 手が届くのは、もうある作業場だけ。作業場は名前を付けた手紙を出すと作られるので、手は手紙のある仕事に結び付く。リンク（ジャンクションなど）は、たどった先が作業場の中かで確かめ、作業場そのものがリンクなら手は動かない。
- 作業場の名前は、大文字と小文字を区別しない（Windowsのフォルダーと同じ）。
- 手の記録や結果の手紙が書けなくても、郵便局は落ちない（郵便局の記録に残す）。
- やったことは、Holoの生ログ（`lifelog/hands/`）に残す。

住人への決まり（郵便の使い方、依頼状の書き方）は`world/post/`の1つの文書に置き、人格はイデアの`persona.md`から読む。どちらも郵便局がMCPのサーバー説明として渡す。CLIがサーバー説明を読まないと分かったら（B0で確かめる）、起こすときの一言に添える。

### 生ログでの形（帳簿を持たない）

手紙は、受取人のイデアの`lifelog/post/<日本時間の日付>.jsonl`に追記だけで書く。行は6種類。

| 種類 | 中身 |
|---|---|
| `letter` | 手紙の番号・時刻・差出人・宛先・本文・作業場・返事先・出所 |
| `note` | 書き残し |
| `done` | 済んだの印と一言 |
| `wake` | 起こした時刻と、その時に済んでいなかった手紙 |
| `stop` | 止まった時刻と、終わり方（正常・エラー・時間切れ） |
| `tell` | 何度起こしても済まない手紙を、Masterに知らせた時刻と、知らせ方 |

- 済んでいない手紙＝`done`のない`letter`。届き直した回数＝その手紙を含む`wake`の数。
- 郵便局は、毎回生ログを全部読み直して決める（WORLD_RULESの「取りこぼしが残らない形」）。

### 起こす決まり（1つ）

**済んでいない手紙がある住人が起きていなければ、起こす。** 新しい手紙・止まった知らせで、すぐに見直す。ほかに1分ごとにも見直す。

数の決まり（`world/post/`の設定に置く）：
- 止まってから1分は起こさない（すぐ落ちる脳で空回りしないため）
- CLIは50分たっても終わらなければ止める（続きは次に起きてから。HoloがChatGPTで25分で切れるのと同じ扱い）
- 同じ手紙で5回起こしても済まなければ、Masterに知らせる。ふだんはHoloに言付けを頼み（スマホからも会話が見える）、Holo自身の手紙なら、郵便局がWindowsの通知で直接知らせる（中継役は自分の詰まりを中継できない）。知らせたことは、詰まった住人の生ログに`tell`の行で残す。知らせた手紙はMasterが決めるものになるので、それでは起こさない（届き直しの上限。2026-10-04、Masterの指摘。返事を待つHoloが手紙を持ったままにして、28回起こされた）。続けてほしいときは、Holoからその住人へ手紙を出せば、起きたときに郵便受けに見える

### 依頼と作業場

- 依頼状も手紙。目的・守るもの・完了の確かめ方・変えてよい範囲・成果物の行き先を書く（構想書§6.1）。
- 作業場は`D:\Products\Work\<名前>`。名前を付けた手紙が初めて届いた時に郵便局が作り、**その名前を付けた手紙が全部済み、中で動いているコマンド（Holoの手）もなくなったら消す。** リポジトリの複製を中に作るのは住人自身。
- 本物のリポジトリへ取り込むときは、Claudeに「取り込んで」の手紙を出す。その手紙が済むまで作業場は残るので、取り込む前に消えることはない。

## 2. 安全

線は要件のとおり、「OSの破壊は実行できない仕組みにし、それ以外はバックアップから戻せればよい」（構想書P6）。先回りして固め、あとで例外を外して回る形にはしない（2026-10-04、Master）。

| 守るもの | 仕組み |
|---|---|
| OS | チームは、Masterのユーザーの管理者に昇格しない権限で動く。Windowsを変えるには管理者の確認（UAC）が要り、留守の間は誰も押さないので、OSは壊せない |
| イデア | 毎晩4時のバックアップ（`G:\Nirai-Backups\daily\`）と、大きな変更の前の丸ごとの写し（`G:\Nirai-Backups\serina\`） |
| コード | git。本物のリポジトリはGitHubへpushしている |
| バックアップそのもの | `G:\Nirai-Backups\daily`は、毎晩のバックアップのタスク（管理者の権限で動く）しか書けない。ほかに誰も書かない場所なので、例外は出ない。2026-10-04に`tools/protect-backups.ps1`で当て、ふつうの権限では書けない・消せない・読めることを確かめた |

決まりで守ること（`郵便の決まり.md`に書く）：
- 作業は作業場の中で。本物には書かない（取り込みはClaude）。
- Serinaのイデアと、Claudeの開発の生ログ（記憶づくりで読んだSerinaの記録が残っている）は読まない。中身はセンシティブで、クラウドの脳に載せない（憲章）。
- Holoは、手元のファイルとコマンドに郵便局の手だけを使う。ChatGPTでは接続を会話ごとに外せないので、Masterの`local-files`の接続（`D:\`全体をMasterの権限で開いている）もHoloの部屋から見えるが、決まりで使わない。使うと、したことがHoloの生ログに残らず、ほかの住人も確かめられず、手紙に結び付かない作業場ができる（2026-10-04のB2の試しで起きた）。権限はCodexと同じMasterのふつうの権限なので、安全の線（OSは壊せない）は変わらない。

困ったことが起きたら、そのとき仕組みで防ぐ。

## 4. 置いた仮定と、まだ確かめていないこと

- 郵便局はNode.js（v24は`.ts`をそのまま動かせる）。MCPは公式のSDK。
- 専用タブの会話には、Masterも直接書いてよい。拡張は、Holoが返事をしている間と、入力欄に下書きがある間は一言を送らない。
- Holoの人格はまだない（イデアの`persona.md`が空）。決まりの文書だけで動かし始め、人格はMasterと決める。
- `apply_patch`を、ChatGPTが確認ボタンなしで呼ぶか（`run`は確認なしで動いた。2026-10-04のB2の試し）。
- 郵便局が止まると（再起動など）、動いていたコマンドの結果の手紙は届かない。困ったら、手の生ログに始まりも書き、起きたときに知らせる。
