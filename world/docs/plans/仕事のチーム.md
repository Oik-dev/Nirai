# 仕事のチーム（段階2）

構想書§11の段階2の計画。郵便局の考え方は構想書§6.1、安全は§8が正本で、本書は作り方と順番を書く。出来上がったら、正本は`world/`の設計書へ移し、本書は`archive/`へ移す。

## 0. 出口

Masterが、Holoとの会話（ChatGPT）で頼みごとをすると、Holoが原文のままチームに回し、作った人以外が確かめて、結果がHoloから返ってくる。その間、Masterは何もしなくてよい。

出口を越えたら、Nirai自体の開発もチームに頼む（要件§3。最初の本番の仕事は段階3の暮らしの循環）。Masterの入口はHoloの部屋になる。ClaudeのUIは、Niraiが止まったときに外から直す口と、管理者の権限が要る操作のために残す（Niraiが止まると、Niraiの中からは直せない）。

## 1. 形

### 部品は3つ

| 部品 | 動く場所 | すること |
|---|---|---|
| 郵便局（`world/post/`） | Masterのユーザーの、管理者に昇格しない権限（§2）。タスクスケジューラが、Masterのログオン時に番人（`keeper.ts`）を起こし、番人が郵便局を起こす。普通に止まったら1分後、確認済みの新版への入れ替わりならすぐ起こし直す | 手紙を受け取り、受取人の生ログに書く。住人を起こす。Holoの手（作業場のファイルとコマンド） |
| 拡張（`world/holo-extension/`） | MasterのChrome | Holoの専用タブに一言送る。部屋のタブの通信の始まりと終わりを郵便局に知らせる（道だけ。中身は読まない）。返事をしているかは郵便局が決める（`post/holo.ts`） |
| トンネル | Masterのユーザー | ChatGPTからの道具の呼び出しを、郵便局へ渡す。OpenAIの`tunnel-client`が、ローカルのHTTPのMCPを直接指せる（`--mcp-server-url`）。ChatGPTの接続「Nirai」のトンネルは、郵便局の`/mcp/holo`を指す。Holoとの会話はChatGPTのHoloの部屋で行う（v2は役に立つものだけ使う。Master） |

郵便局は、`127.0.0.1`の1つのHTTPサーバー。住人ごとに入口（`/mcp/<住人>`）を分け、入口で差出人が決まる。

### Holoの部屋の引っ越し

部屋の正本は、Holoの`lifelog/post/`にある最後の`room`行（`{kind:"room", ts, url}`）。拡張はURLを持たず、部屋のタブ番号だけを覚える。部屋の長さは、最後の`room`行より後にHoloの手が返した`lifelog/hands`の`output`の字数で数える（`settings.ts`の`holo.roomChars`）。Holoが暮らすProjectは`settings.ts`の`holo.projectId`だけを持ち、入口URLはそこから組み立てる。

状態は生ログだけから4つに決める。`room`がなければ**未登録**、最後の`room`より後に`move`がなければ**部屋あり**、`move`が未済なら**引っ越し中**、`move`が済んでその後に`room`がなければ**新部屋待ち**。別の状態台帳は持たない。未登録では自動で何も開かず、拡張の「このタブを部屋にする」で、Masterが開いているNirai Project内の会話だけを登録する。

長さが上限を超えるか、Masterが拡張の「今すぐ引っ越す」を押すと、郵便局がそのroomにつき1通だけ、`move`印付きの引っ越し手紙をHoloへ出す。前の部屋は、その手紙が済むまでほかの手紙を進めない。Holoは、新しい部屋へ持っていく必要がある会話の流れ（Masterと話している途中のこと、決まったこと、Masterの好み、進めていた仕事の今）だけを自分宛ての手紙にし、引っ越し手紙を済みにする。郵便受けと書き残しは同じ生ログから読めるので写さない。済みにした古い部屋では、以後郵便受けに触らない。

引っ越し手紙が済んだ**新部屋待ち**で、次にHoloを起こす必要があるときだけ、`/holo/next`が一言・対象の手紙・Project入口URLを返す。拡張は旧部屋タブを安全に入口へ切り替えるか、新しいタブを開く。新しい部屋では、確認済みの会話入力欄へだけ`@Nirai`を入れ、**その入力で新しく現れた候補の中だけ**を見る。名前が`Nirai`の候補が複数あるなど接続先を確実に見分けられないときは、どれも押さず入力を消して止まる。本文も確認済みの同じ入力欄へ入れ、そのフォームの送信ボタンだけを押す。送信操作まではMasterの操作を見張るが、送信後は画面遷移で入力欄が作り直されても失敗扱いにしない。入力が消えて送れたと確かめた時点で`wake`を生ログへ先に書き、同じ引っ越しでは二つ目の会話を作らない。その後、同じタブが同じProjectの`/g/<project>/c/<uuid>`になったら`room`を追記する。URLを確定できなければ自動は止まり、バッジに`!`を出して、Masterの手動の部屋登録を待つ。前の会話は消さない。

通常の起床でも、部屋タブが閉じていれば`/holo/next`が最後の`room`行のURLを返し、拡張が開き直す。これにより拡張のstorageに`convId`やURLは残さない。前の部屋と新しい部屋が同じ未済手紙を同時に扱わないよう、新しい部屋を作るのは前の部屋が返事をしていないときだけにする。自動作成できないときは、MasterがNirai Project内で会話を作り「このタブを新しい部屋にする」で登録すれば、同じ生ログ状態から続けられる。

### 住人ごとのつなぎ方

| 住人 | 起こし方 | 止まったと分かる時 |
|---|---|---|
| Holo | 拡張が専用タブへ一言送る | タブの会話の通信が終わった時 |
| Codex | 郵便局が`codex exec`を起動する | プロセスが終わった時 |
| Claude | 郵便局が`claude -p`を起動する | プロセスが終わった時 |
| Cursor | 住人ではない（イデアを持たない）。ほかの住人が作業場で`cursor-agent -p`を呼ぶ | — |

- **Claudeも郵便局から起こす（Master）。** Masterの在席を承認の代わりにしない（要件§14の承認を置かない、§0のMasterは何もしなくてよい）。Serinaを守る線は、ほかと同じくOSを壊せない権限と、バックアップとgit（構想書§8）。Codex/Claudeが利用上限で止まったときは失敗回数には数えず、`stop: limit`と起きられる時刻を生ログへ残す。その時刻までは起こさず、頼んだ住人へ知らせる。時刻を読めなければ1時間後に再試行する。待つか代わりを頼むかの決まりは`郵便の決まり.md`を正本にする。
- **起こしたClaudeは、Masterとのセッションと同じ住人として動く。** 家（カレントフォルダー）はNiraiのリポジトリで、CLAUDE.md・記憶（`Residents\Claude\memory`）・生ログの写し（Stopフック）が同じになる。見張りは、Masterとのセッションと同じ自動モード（`--permission-mode auto`）。囲いを外すかの判断が要らない。つなぐのは郵便局だけ（`--strict-mcp-config`）。道具は手紙の仕事に要るものだけにし、技能の一覧も外す（`--tools`・`--disable-slash-commands`）。CLIの出力（`--output-format json`。終わり方・セッションの番号・使った量）は、Codexと同じく生ログの`claude-cli/`に残し、会話そのものは、いつものセッションの記録として`lifelog/claude-code/`に写る。
- **Masterとのセッションとぶつからない形は、仕組みを足さず、gitと決まりで作る。** 住人は本物の作業ツリーのファイルを編集せず、作業場の複製で仕上げる。作った人以外の確かめが通ったら、Holoが取り込みの道具（`world/post/land.ts`）で、確かめた範囲だけを本物のmainの上へ載せ替え、テストを通して`git merge --ff-only`で入れてpushする（gitは、まだ記録されていない変更を上書きしないし、ff-onlyは食い違いを作らない。ぶつかれば取り込みのほうが止まる）。Masterとのセッションでは、Claudeの郵便受けを読まない（CLAUDE.md）。2人のClaudeが同じ手紙を扱わないため。手紙を出すのはよい。
- **worldの版替え。** 本物の`world/post/`・`world/sea/`・`world/window/`か`world/package-lock.json`が変わったら、手が空いた見回りでGitの確定コミットから固定候補を作る。文書だけの変更では入れ替えない。候補は`git archive`でそのコミットの`world/`だけを取り出し、毎回その候補自身の`package-lock.json`で`npm ci --prefer-offline`して、自分の`node_modules`を持つ。候補の親や本物の`node_modules`には頼らず、`.git`も持たない。候補は番人ごと`--live`なし・郵便局と海の別空きポート・使い捨ての`NIRAI_RESIDENTS`/`NIRAI_WORK`/runtimeで起こし、候補自身の`/holo/status`と`/sea/status`が同じ版を返すことまで先に確かめる。起きない版には入れ替わらず、今の郵便局を動かしたままHoloへ1通だけ知らせる。合格したら、海の返答を最長3分待って閉じ、試した候補の番人ごとそのまま本番へ引き継ぎ、新番人が同じ固定候補の郵便局と海を起こしたことを確かめてから旧番人が終わる。失敗時は前のpostとseaを復旧する。本物のリポジトリの場所は`settings.repoRoot`を正にし、server・keeper・Claudeの家はそこから決める。誰かの仕事、Holoへ一言を渡した直後、Holoの返事中・返事直後、HTTP受付中、海の会話・削除・起動中は切り替えない。海への非同期の問い合わせのあと、readyの直前に郵便局の手すきを同期で再確認する。同じ拒否版は二度試さない。海は郵便局と別の子なので、海だけが落ちても郵便局は落ちない。海を木ごと止めず、精神を巻き込まない。詳細は`海で暮らす.md`の§2.5。古い候補は、今動いている版と今作る版を除いて候補準備の入口で片付ける。PC起動時に最新の版がそもそも起きない場合の前版復帰は、段階6で扱う。
- **Cursorを住人にしない理由。** 住人を増やすのはMasterの専権（要件§4）で、Cursorは自分で進める力が低い（要件§17）。道具として呼べば、郵便局に特別な扱いが要らない。住人にするかは、Masterがいつでも決められる。
- **Cursor CLIの呼び方（Master）。** 決まりきった実装だけを、先にテストを書き、変えてよい範囲を明示してから渡す。Cursorを呼ぶ前に、テストを含む開始状態をコミットし、`git rev-parse HEAD`を基準点として控える。ふだんは毎回`grok-4.7-xhigh`を明示し、Autoは使わない。住人の上限時に代わりの実装・確かめへ回すときはOther枠も使う。今使える強いOtherは`claude-opus-5-5-max`（Claude Opus 5.5 1M Max）。利用時に`--list-models`で一覧を見直し、使える強いOtherを選んでよい。実行は作業場の複製を`--workspace`にして、次の形で呼ぶ。

```powershell
& "$env:LOCALAPPDATA\cursor-agent\cursor-agent.cmd" -p --force --trust --model grok-4.7-xhigh --workspace <作業場の複製> --output-format json "<頼むこと>"
```

  終わったら、`git status --short --untracked-files=all`で未コミット（未追跡・ステージ済みを含む）の変更を、`git diff --name-status <基準点> HEAD`でCursorが途中でコミットした変更を調べ、許した範囲の外がないことを確かめる。そのあと先に書いたテストを回す。範囲の外を変えていたら取り込まず戻す。Cursorは住人ではなく、2027年3月に解約予定の道具。

### 手紙の道具（MCP、全員共通の4つ）

| 道具 | すること |
|---|---|
| `send_letter` | 宛先・本文、必要なら作業場の名前と返事先の手紙を付けて出す |
| `read_mailbox` | まだ済んでいない手紙を、書き残しと一緒に読む |
| `write_note` | 手紙に、やったことや見つけたことを書き残す。切れても、次に起きた自分が続きから始められる |
| `mark_done` | 手紙に「済んだ」の印を付ける |

Holoだけは手を持たない脳なので、郵便局が手を貸す（`post/hands.ts`）。道具は、GPTが慣れているCodexの2つにそろえる。

| 道具 | すること |
|---|---|
| `run` | 作業場をカレントフォルダーにして、PowerShell 7のコマンドを実行する。読む・探す・一覧もこれで |
| `apply_patch` | Codexの形の差分（`*** Begin Patch`…）で、作業場のファイルを作る・書き換える・消す。差分の当て方はOpenAIの`applyDiff`（`@openai/agents-core`）。1か所でも当たらなければ、どのファイルも変えない。書いている途中で失敗したら、元に戻す。`@@`に書いた行がファイルになければ断る（`applyDiff`は進んでしまうが、本物のCodexは断る） |

- ChatGPTは道具の呼び出しを約60秒で打ち切るので、コマンドは45秒で返す。それより長いものは「続いている」と返し、終わったら結果を郵便局からの手紙で届ける（構想書§6.1）。50分たっても終わらなければ止める。
- 手が届くのは、もうある作業場だけ。作業場は名前を付けた手紙を出すと作られるので、手は手紙のある仕事に結び付く。リンク（ジャンクションなど）は、たどった先が作業場の中かで確かめ、作業場そのものがリンクなら手は動かない。
- 作業場の名前は、大文字と小文字を区別しない（Windowsのフォルダーと同じ）。
- 手の記録や結果の手紙が書けなくても、郵便局は落ちない（郵便局の記録に残す）。
- やったことは、Holoの生ログ（`lifelog/hands/`）に残す。

住人への決まり（郵便の使い方、依頼状の書き方）は`world/post/`の1つの文書に置き、人格はイデアの`persona.md`から読む。どちらも郵便局がMCPのサーバー説明として渡す。CLIがサーバー説明を読まないと分かったら（B0で確かめる）、起こすときの一言に添える。

### 生ログでの形（帳簿を持たない）

手紙は、受取人のイデアの`lifelog/post/<日本時間の日付>.jsonl`に追記だけで書く。行は6種類。

| 種類 | 中身 |
|---|---|
| `letter` | 手紙の番号・時刻・差出人・宛先・本文・作業場・返事先・出所 |
| `note` | 書き残し |
| `done` | 済んだの印と一言 |
| `wake` | 起こした時刻と、その時に済んでいなかった手紙 |
| `stop` | 止まった時刻と、終わり方（正常・エラー・時間切れ） |
| `tell` | 何度起こしても済まない手紙を、Masterに知らせた時刻と、知らせ方 |

- 済んでいない手紙＝`done`のない`letter`。届き直した回数＝その住人が最後に何か1通を`done`してから、その手紙を含む`wake`の数。ほかの手紙が済んでいくあいだ、順番を待つ手紙は数えない。
- 郵便局は、毎回生ログを全部読み直して決める（WORLD_RULESの「取りこぼしが残らない形」）。

### 起こす決まり（1つ）

**済んでいない手紙がある住人が起きていなければ、起こす。** 新しい手紙・止まった知らせで、すぐに見直す。ほかに1分ごとにも見直す。

数の決まり（`world/post/`の設定に置く）：
- 止まってから1分は起こさない（すぐ落ちる脳で空回りしないため）
- CLIは50分たっても終わらなければ止める（続きは次に起きてから。HoloがChatGPTで25分で切れるのと同じ扱い）
- 同じ手紙で、何も済ませないまま3回起こしても済まなければ、Masterに知らせる。届き直した回数は、その住人が最後に何か1通を済ませたところから数え直すので、ほかの手紙を順に片付けているあいだ、順番を待つ手紙はMasterに回さない。ふだんはHoloに言付けを頼み（スマホからも会話が見える）、Holo自身の手紙なら、拡張アイコンに`!`を残す（中継役は自分の詰まりを中継できない）。郵便局につながらないときは`×`。知らせたことは、詰まった住人の生ログに`tell`の行で残す。知らせた手紙はMasterが決めるものになるので、それでは起こさない。続けてほしいときは、Holoからその住人へ手紙を出せば、起きたときに郵便受けに見える。回数は3回（Master。重い仕事は手順の手紙に分け、待つときは済みにするので、3回届いても何も済まないのは詰まっているとき）

### 依頼と作業場

- 依頼状も手紙。何を書くかは`world/post/郵便の決まり.md`が正本。
- 作業場は`D:\Products\Work\<名前>`。名前を付けた手紙が初めて届いた時に郵便局が作り、**その名前を付けた手紙が全部済み、中で動いているコマンド（Holoの手）もなく、いちばん新しいdoneから1回の目覚めの長さ（今は約50分）がたったら消す。** リポジトリの複製を中に作るのは住人自身。
- `reply_to`付きの返事は、`work`を省けば郵便局が元の手紙の作業場を引き継ぐ。返事そのものは元の手紙を済みにしないので、終わった手紙は本人が`mark_done`する。片付けは住人が起きているかではなく、生ログのdone時刻と時計、手のbusyだけで決める。これで郵便局を起こし直しても「済みにしてから返事」「再レビューの往復」の途中で作業場が消えない。
- 誰が作り誰が確かめるか、何で止めるか、確かめ直しで何を見るかは`world/post/郵便の決まり.md`が正本。

## 2. 安全

線は要件のとおり、「OSの破壊は実行できない仕組みにし、それ以外はバックアップから戻せればよい」（構想書P6）。先回りして固め、あとで例外を外して回る形にはしない（Master）。

| 守るもの | 仕組み |
|---|---|
| OS | チームは、Masterのユーザーの管理者に昇格しない権限で動く。Windowsを変えるには管理者の確認（UAC）が要り、留守の間は誰も押さないので、OSは壊せない |
| イデア | 毎晩4時のバックアップ（`G:\Nirai-Backups\daily\`）と、大きな変更の前の丸ごとの写し（`G:\Nirai-Backups\serina\`） |
| コード | git。本物のリポジトリはGitHubへpushしている |
| バックアップそのもの | `G:\Nirai-Backups\daily`は、毎晩のバックアップのタスク（管理者の権限で動く）しか書けない。ほかに誰も書かない場所なので、例外は出ない。`tools/protect-backups.ps1`で、ふつうの権限では書けない・消せない・読めるようにしてある |

決まりで守ること（`郵便の決まり.md`に書く）：
- ファイルの変更は作業場の中で。本物の作業ツリーは直接編集せず、確認後の取り込みだけHoloが取り込みの道具（`world/post/land.ts`）で行う。
- Serinaのイデアと、Claudeの開発の生ログ（記憶づくりで読んだSerinaの記録が残っている）は読まない。中身はセンシティブで、クラウドの脳に載せない（憲章）。
- Holoは、手元のファイルとコマンドに郵便局の手だけを使う。ChatGPTでは接続を会話ごとに外せないので、Masterの`local-files`の接続（`D:\`全体をMasterの権限で開いている）もHoloの部屋から見えるが、決まりで使わない。使うと、したことがHoloの生ログに残らず、ほかの住人も確かめられず、手紙に結び付かない作業場ができる。権限はCodexと同じMasterのふつうの権限なので、安全の線（OSは壊せない）は変わらない。

困ったことが起きたら、そのとき仕組みで防ぐ。

## 4. 置いた仮定と、まだ確かめていないこと

- 郵便局はNode.js（v24は`.ts`をそのまま動かせる）。MCPは公式のSDK。
- 専用タブの会話には、Masterも直接書いてよい。拡張は、Holoが返事をしている間と、入力欄に下書きがある間は一言を送らない。
- スマホのChatGPTアプリから、同じ会話で頼めるか（PCが起きていれば道具も動くか）は、まだ確かめていない（Masterの手が要る）。
- 郵便局が止まると（再起動など）、動いていたコマンドの結果の手紙は届かない。困ったら、手の生ログに始まりも書き、起きたときに知らせる。

## 5. 後で（使い始めてから、チームに作らせる）

- **ほかのPJ（Estateなど）の仕事。** Niraiと同じく、作業場で仕上げ、作った人以外が確かめ、Holoが本物へ入れてpushする。PJごとの守るものは、依頼状の「守るもの」に書く。Niraiでこなせるようになったら、ChatGPTの`local-files`接続を外す（要件§11）。
- 同じファイルを同時に触らないための期限付きの予約（mcp_agent_mailの方式）。作業場が依頼ごとに分かれているうちは、困ってから足す。
- 各自の体力（トークンの残り）を郵便受けに出す。
- 取り込みの自動化（段階6）。
- Serinaへの手紙（段階5。今の会話窓で受け取る）。
- **MCP Events**（OpenAI、2026-09のDevDay）：MCPのサーバーがイベントをWebhookで送ると、ChatGPTがその会話で動き出す公式の仕組み。郵便局の「新しい手紙」をそのまま渡せて、画面に一言を打ち込む拡張より壊れにくい。ただし2026-10-04の時点では、使えるのはWork chat（Cloud）とdotsだけで、ふつうのChatは対象外。WorkはCodexと同じ使用量の枠を使うので、トークンを気にせず動けるChatのHoloには使わない。Chatで使えるようになったら、拡張の起こし方を置き換える（MCP 2.0、プラグインとしての接続、登録の保存が要る）。
