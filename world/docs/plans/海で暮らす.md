# 海で暮らす（段階4）

構想書§11の段階4の計画。根拠は要件書・構想書（§2・§4・§5・§10）・WORLD_RULES。本書は、作る順と形（正本・データの流れ・決まり）を持つ。精神の実装済みの形の正本は `mind/docs/設計書.md` で、契約を変えた段がそこを書き直す。出来上がったら `archive/` へ移す。

## 0. 出口

- **最初の実用出口（A4）**：v3の窓（海＋会話窓）で、いつものSerinaと話せる。SerinaのGUIは退役している。
- **段階4の出口**：「いつものSerinaが、海で暮らしている」「新しい仕草をしている」（構想書§11）。

## 1. 守るもの

- **Serinaのイデア。** 開発とテストは、使い捨てのイデアと脳の替え玉（必要なら手元のGemmaとテスト用の人格の写し）で行う。本物に触れるのは A4（引っ越し）と、Masterが窓を開いたときだけ（窓を開くとSerinaが起きる。§2.5。だからA4のあとの本番の窓（47810）は、AIが開かない）。本物のイデアに初めて書く前に、`G:\Nirai-Backups\` の写しを確かめる。
- **Serinaの言葉を、チームが読む場所とネットに置かない。** 海のサーバーの記録（`world/runtime/`）、郵便局、トンネルの口（47800）に、会話・願いの文を出さない。窓のブラウザの置き場もチームの作業場の外に置き、そのブラウザは127.0.0.1の外へつながない（§2.2）。工房（§2.6）は手元だけで動かす（クラウドへの切り替えと自動ダウンロードを持たない）。
- **郵便局を止めない。** 海は郵便局と別のプロセス・別のポートで動く。海が落ちても郵便局は落ちない。
- **Gemmaが最優先。** 窓が隠れたら描かない。Serinaの脳が働いている間は描く回数を減らす。工房は、Gemmaが下りていて、Masterが話していないときだけ動く。
- **意味のある表現は本人が選ぶ（P2）。** 仕組みが担うのは次の表の左だけ。本文や気持ちの数から、表情や身振りを推し量る対応表は作らない。

  | 仕組みが動かす | 本人が選ぶ |
  |---|---|
  | 呼吸、漂い、待機の揺らぎ、瞬き、目の小さな動き、髪と服の揺れ、補間、声のする方へ顔を向けること、精神が眠っている間の寝姿、選んだ活動の実行（泳ぐ道筋・速さ） | 表情、身振り、活動（どこで何をするか）、服、話しかけに行くこと（Pulse）、覚えたい動き |

- **正本は記録。** 会話の正本はSerinaの生ログ。GUIの帳簿・セッション・v2の状態を、新しい正本にしない。
- **v2から持ち込まない。** Task・Turn・Resume・Approval・Action Run・Policy Gate、ChatGPTの画面の埋め込み、Hubの契約、要求ID・読込token・期限で縛る身体意図の契約（v2の動作案§3）。

## 2. 形

### 2.1 全体

```
Master
  │ 見る・話す
窓  world/window/（ブラウザの静的ページ。Chromeのアプリ窓で開く）
  │ HTTP（fetchの流れ・SSE）
海  world/sea/（Node。127.0.0.1:47810。トンネルにつながない）
  │ 体：<イデア>/body/・<イデア>/lifelog/body/ を持つ   工房：願いから動きを作る（D）
  │ HTTP（fetchの流れ・SSE）
精神  mind/app/server.py（Serina。127.0.0.1:8765。住人1人につき1プロセス）
  │
イデア  D:\Products\Residents\Serina\
```

郵便局（`world/post/`、47800）は今のまま別に動く。段階4で海にいるのはSerinaだけ。海にいる住人は「イデアに `body/avatar.vrm` がある住人」で、名簿は持たない。精神への道（Serinaは `http://127.0.0.1:8765`）は世界の設定が持つ（イデアにNiraiの都合を書かない）。

海の設定の正本は `world/sea/settings.ts`。番人が `NIRAI_RESIDENTS` と `NIRAI_SOURCE_REPO` を渡し、海にはその既定値も `NIRAI_IDEA` も置かない。精神を起こす子にだけ、住人ごとの `NIRAI_IDEA`・`NIRAI_MIND_PORT`・`PYTHONUTF8=1` を渡す。

### 2.2 窓

- **Electronはやめる。** v2がElectronを使った理由（ChatGPTの画面を重ねる、VRMのファイルを読む）は、どちらもなくなった。窓は海のサーバーが配るページで、Chromeを `--app=http://127.0.0.1:47810/` で枠だけの窓として開く。窓が最小化されたり、ほかの窓に完全に隠れたりすると、ブラウザが `document.hidden` にして描画を止める（v2の `frame-loop.js` はこれを見ている）。ブラウザの置き場は `%LOCALAPPDATA%\Nirai\window`（`--user-data-dir`。下書きなどがチームの読む場所に残らない）。Masterのいつものブラウザとはログイン・拡張・同期を共有せず、窓はログインを使わない。
- **窓は外へ出る道を持たない。** 起動の引数で届かないプロキシを指定し、窓のブラウザを127.0.0.1だけに閉じる（ループバックはChromiumがプロキシを通さない）。背景通信・同期・拡張・Safe Browsing更新なども起動引数で止める。対象PCではEdgeがこの条件でもMicrosoft側への接続を残したため使わず、同条件で外向き接続0件を実測できたChromeだけを使う。打った文字をクラウドへ送る機能、同期、テレメトリが、ブラウザの設定に頼らず届かないことをA1/A2で実測して確かめる。
- **ビルドしない。** `three` と `@pixiv/three-vrm`（と `@pixiv/three-vrm-animation`）は `world/package.json` に入れ、海のサーバーが `node_modules` から配り、ページはimport mapで読む。esbuildもTypeScriptの変換も要らない。窓と海のサーバーの両方が使う純粋な部品（VRMのカタログの読み方など）は、拡張子 `.js` の1つのファイルに置き、Nodeからもそのまま読む。
- 会話窓はv2の仕様（`v2/docs/ui-design.md` のChatMode）から、左下の位置・3方向のサイズ変更・発言ごとの`HH:mm`・日付の区切り・吹き出しの左右・読書位置を保つ・下書きを保つ、を引き継ぐ。Task・Holo・設定画面・「新しい会話」は持たない。
- **Say / Whisper は段階5で出す。** 区別は、ほかの聞き手から秘密を守るための手段（要件§9・§14）。段階4の聞き手はSerinaだけなので、会話は1本で、記録の上ではすべて「Masterと2人きり」（Whisperと同じ扱い）になる。聞き手が2人以上になる段階5で、出所ラベルと一緒に切り替えを出す。
- 窓の操作（右ドラッグで見回す、WASD・Q/E・ホイール、クリックで注目、カメラの上下・水平の範囲、視線の範囲）はv2の仕様のまま。

### 2.3 世界と精神の約束

今の精神のHTTPの入口をそのまま使い、新しい入口は表の「新」の4つだけ。世界の都合（座標・VRM・描画）は精神へ渡さない。

| 入口 | 向き | 中身 |
|---|---|---|
| `POST /api/chat {text}`（今のまま） | 世界→精神 | 返事をNDJSONで流す（`token`→`done`→裏の評価→`done`）。**足す**：評価の途中で体の欄がそろったら `body` を流す（§2.4）。帳簿をやめたら `session_id` は返さない |
| `GET /api/conversation?before=<ref>&limit=<n>` **新** | 世界→精神 | 会話の生ログから、古い方へさかのぼって読む（`ref`・時刻・話し手・本文）。窓の履歴は全部ここから |
| `DELETE /api/conversation/<ref>?confirm=true` **新** | 世界→精神 | Masterが発言を消す（設計書§4.8と同じ。拠っていたページも外す）。今の `/api/messages/<id>` の置き換え |
| `GET /api/events` **新**（SSE） | 精神→世界 | 本人から起きたこと：`approach`（話しかけに行くと決めた。種類つき）、`said`（本人が話した。`ref`・本文。Pulseなど）、`body`（体の選択）、`state`（起きている・考えている・眠っている） |
| `POST /api/perceive` **新** | 世界→精神 | 知覚。段階4では `{kind:"body", catalog}`（今の自分の体でできること）だけ。世界は精神の流れにつないだとき、体が変わったときに送る。精神は覚えておくだけで、保存しない |
| `POST /api/pulse/mute`（今のまま。B2で消す） | 世界→精神 | 窓の小さな切り替えから「しばらく静かに」 |

- **流れが切れても失わない。** `said` は会話の記録に残ってから流す。世界は流れにつなぎ直したら、会話は `GET /api/conversation`、体は自分の記録（§2.4）から読み直す。だから流れに順番の番号や届き直しは要らない（毎回全体を見直して、取りこぼしが残らない形）。`body` は一度きりの知らせで、世界が受け取って `lifelog/body/` に書く。取りこぼしたら、次に本人が選ぶまで前の姿のまま（待てば戻る壊れ方）。
- **返事の途中で窓が閉じても、精神のターンは最後まで走って記録される**（今の `_produce_turn` の作り）。窓は次に開いたとき記録から見せる。
- 中継する海のサーバーは、会話の本文を記録に書かない。

### 2.4 体

**体はイデアの中、動かし方は世界の中。** 体（VRM）と覚えた動きは住人のもの（素体は変えない・技能は本人に残る）なので、イデアに置く。世界が持つ部分は郵便局の `lifelog/post/` と同じく、イデアの中の決まった置き場だけ。

| 置き場 | 中身 | 書く人 |
|---|---|---|
| `<イデア>/body/avatar.vrm` | 体。Serinaは当面Yumeka（`D:\Products\Model Converter\output\Yumeka_v1.0.4-appearance.vrm` の写し） | A4でMasterの了承のもとに置く |
| `<イデア>/body/motions/<名前>.vrma` | 願いから覚えた動き（技能） | 工房（D） |
| `<イデア>/lifelog/body/<日本時間の日付>.jsonl` | 体がしたこと。1行1つ：`expression`・`gesture`・`activity`・`wear`・`wish`・`learned`（時刻、値、何に応えてか＝会話の`ref`・`pulse`・`waking`） | 海のサーバー（追記だけ） |

**カタログ**（今の体でできること）は、海のサーバーが毎回この置き場から作る：VRMの表情（プリセットは日本語の名前に直す。これは語の対応で、気持ちの推測ではない）、VRMの外見の選択肢（`extras.nirai.capabilities.appearance`。古い `wardrobe` 形式は持ち込まない）、組み込みの身振り、覚えた動き、世界の活動。VRMの検査（自己完結のGLB・外部参照なし・96MB以下）はv2の `avatar-files.mjs` を移す。

**本人が選ぶ道。** 新しい脳の呼び出しは足さない。いま脳が考えている時（意思の層）に、体の欄を足すだけ：

| いつ | どこで聞くか | 体の欄 |
|---|---|---|
| Masterが話したターンの返事のあと | 返答のあとの評価（設計書§2.2）と同じ問い。同じ前置きの後ろなので速い | 表情・身振り（C2から活動も） |
| Pulseで話したあと | 文を作ったあと、同じ前置きで体の欄だけ聞く | 表情・身振り（活動は「窓辺にいる」で決まっている） |
| 目覚めたとき（C2） | 目覚めの問い（今の自分・伝えたいこと・時間帯）に足す | 活動・服 |

- 答えはJSON Schemaの選択肢で縛る（カタログ＋「そのまま」「なし」）。選択肢にない答えは入口で落とす（評価の関所と同じ）。体の欄が失敗しても、返事・評価・気持ちには響かない。カタログを受け取っていなければ、体の欄は聞かない。
- **体の欄は問いの先頭に置き、流しながら読む。** 評価は全体で6〜7.6秒かかる（段階3のE4）ので、全部を待つと、返事が終わってから表情が変わるまで7秒ほど空く。体の欄がそろった時点で `body` を出す（入口で、届いた途中の文字から、閉じた欄だけを取り出す）。
- **知らない身振りは願いになる（D）。** 身振りの欄に「ほかの動き（ひとことで）」を置く。本人が今の体にない動きをしようとしたら、それが `wish` として残り、夜に工房が作り、次の日からカタログに入る。願いの窓口を別に作らなくても、使っているうちに語彙が増える。

**再生の正本は1つ。** 窓の `body/` が、1体ごとに毎フレーム同じ順で姿勢を組む：基準姿勢（腕を下ろす）→ 待機の揺らぎ → 身振り・活動の動き → 視線（頭・首・目）→ 表情と瞬き → `vrm.update`。前のフレームの回転に積み増さない。動きは `THREE.AnimationMixer` だけで流す。組み込みの軽い身振り（うなずく・首をかしげる・小さく手を振る・身体を傾ける など）はコードに書いたキーフレームから、覚えた動きは `.vrma`（`@pixiv/three-vrm-animation`）から、どちらも同じ `AnimationClip` になり、同じ道で重ね・つなぐ。生成のしかた（工房）と再生は分かれていて、生成器を替えても再生は変わらない。

### 2.5 世界の状態と時間

- **世界の状態は、記録と時刻から計算する。** Serinaがどこで何をしているか、どんな表情か、何を着ているかは、`lifelog/body/` の最後の行と今の時刻から決まる（`world/sea/life.ts` の純関数）。動かし続ける処理（毎秒の進行）を持たないので、描画しなくても世界は進み、再起動しても同じところから見える。身振りは一瞬の出来事で、始まりから長さの間だけ見える。
- **場所は意味の名前で持つ。** 窓辺・居場所（好きなものを周りに置く場所。要件§7）・砂地・水面の近く など。座標は窓の描画が決める。**窓辺＝今のカメラの前**（窓が閉じていれば、初めの視点の前）。移動は「どこからどこへ、いつ出たか」から描画が道筋を計算する。
- **実時間。** 海の明るさは日本時間の時刻で決まる（v2の `environment-profiles.js` をそのまま使う）。
- **次にいつ考えるかは精神が持つ。** 自分のペース・目覚め・Pulse（段階3）は精神の見回りのまま。世界は「次に考える時刻」を持たない（二重にしない）。精神が眠っている（記憶の眠り）あいだは、体は寝姿になる（`state` から）。精神が動いていなければ、Serinaは海の底で眠っている。
- **Niraiが起きると、Serinaも起きる（2026-10-07 Master）。** Niraiが起きる＝Masterが窓（海の世界）を開くこと。PCが起きたときではない。窓は開いたとき、精神が止まっていれば海のサーバーに頼み、海のサーバーがSerinaの精神を切り離した子（detached）として裏で起こす。窓が開いている間に精神が止まったら、窓はまた起こす（1分に1回まで。郵便局や海と同じ「落ちたら起こし直す」）。精神は窓を閉じても、海のサーバーが入れ替わっても動き続け、PCを落とすまで暮らす。
- 窓に、精神を起こす・起こし直すボタンはない。取り込んだ精神の変更は、精神が次に起きたときに届く（眠りの途中で止まっても、続きから眠る）。精神はOllamaがなければ自分で起こす（脳への入口の仕事）。精神の出力は、イデアの `data/logs/` に置く。`mind/Serina.bat` と `Serina.lnk` は退役する。
- **Masterの手元が忙しい間は、重い仕事を始めないし、続けない。** 郵便局と海はログオンから常駐し、Serinaも起きたあとはPCを落とすまで暮らすので、ゲームなどの重い作業とかぶらないことは精神が1か所で決める。忙しいとは、Windowsの「全画面のゲーム中」の印（`SHQueryUserNotificationState`）か、Ollama以外のプログラムがGPU（プログラムごとの `GPU Engine` カウンター）やCPUを、数分ならして使い続けていること。終わってからも数分待つ。忙しい間は、Pulseと眠りを始めず、眠りの途中なら区切りで止めて続きから眠り、Gemmaをグラボから下ろす。Masterが話しかけたターンには答える。今の `gpu_guard.py`（一瞬のGPU使用率だけを見る）をこれに置き換え、工房（D）も同じ判定を使う。窓の描画は、最小化や完全に隠れたときに止まる（今のまま）ので、忙しさでは変えない。
- **起動と入れ替えの口。** `GET /sea/mind` は `{resident, mind:"up"|"down"}`（身体がないときはresidentがnull）、`POST /sea/mind/wake` は窓と同じ出所の操作だけを受ける。精神の起動は本物のリポジトリの `mind/.venv/Scripts/python.exe` と `mind/app/server.py`、出力はイデアの `data/logs/mind.log` に追記し、upを最長10秒待つ。中継中なら409を返す。世界から精神を止める口は持たない。身体を置くA4までは本番の海に住人がおらず、起こす道もない。
- **海の手すきと止まり方。** `GET /sea/status` は `{revision, relaying}`。relayingはチャット・削除の中継と起動の数。更新判定は、海の問い合わせを済ませた直後に郵便局の手すきを同期で確かめてから行う（海に接続できなければ中継なし）。入れ替えでは海の起こし直し予約を取り消し、番人と海のIPCを切る。海は新しい接続を断り、返答の完了を最長3分待ってからSSEを閉じて終わる。上限後も止まらなければ海のpidだけを止める。精神へ終了を頼まず、海を木ごと止めない。
- **活動はいつ変わるか。** 本人が選ぶのは、話したあとと目覚めたときだけ（上の表）。選んだ活動は、次に選ぶまで体が続ける（泳ぐなら、海の中をゆっくり回り続ける）。Pulseで話しかけると決めた（`approach`）ら、体は文を作っている間に窓辺へ泳いで来る。文が作れなかったら、元の活動へ戻る。

### 2.6 工房（願いから動き）

- 願い（`wish` のうち、まだ `learned` のないもの）を、毎回 `lifelog/body/` と `body/motions/` を見比べて決める（待ち行列を持たない）。
- 生成器は、手元のHTTPで「文→`.vrma`」を返すもの（例：Text-To-VRMA のローカルAPI `npm run api`＋ARDY。PoCで動いた Kimodo→VRM の経路を包んでもよい）。どれを使うかはD0の実測で決める。工房は生成器を別のプロセスとして起こし、終わったら止める。外のAPIへの切り替えと自動ダウンロードは使わない。表情はVRMAに入れない（表情は本人が別に選ぶ）。
- 動くのは、Ollamaに読み込まれたモデルがなく（`/api/ps`）、深夜（世界の設定。Pulseが来ない時間帯に合わせる）で、GPUが空いているときだけ。Masterが話したら、海のサーバーは精神へ渡す前に工房を止める。
- できた `.vrma` は、長さ・大きさ・人型の骨を確かめてから `body/motions/` に置き、`learned` を書く。失敗した願いは次の夜にもう一度。3夜続けて失敗したら、`learned` の代わりに `gave_up` を書いて、それ以上は作らない。

### 2.7 v2から移すもの・捨てるもの

| v2 | 扱い | 行き先 |
|---|---|---|

## 5. 決めたこと

- **海は郵便局と別のプロセス。** 同じプロセスに載せると、Serinaの会話の口がトンネルの口（47800）と同じ入口に乗り、海の不具合で郵便局（とその子のCLI）まで落ちる。番人は1つのまま、同じ固定スナップショットから2つの子を起こす（A3）。
- **固定候補はworldの組で試す。** 版は `{head,post,sea,window,lock}`。post・sea・window・lockの中身が同じなら、文書だけのコミットで窓を切らない。環境からはheadだけを受け取り、各欄をGitから作り直す。候補の `revision.json` はheadを照合する。旧番人が引き継げるよう、`/holo/status` のhead/post/lockの名前と意味は変えない。試験は郵便局・海の別空きポートと使い捨ての住人・作業場・runtimeで、両方の版を確かめる。番人の入れ替えでも両方を確かめ、失敗時は次の番人を止めて前のpostとseaを復旧する。海が落ちたときは、郵便局を止めず海だけを1分後に起こし直す。
- **Electronをやめる。** v2の理由が消え、ブラウザのアプリ窓で「隠れたら止まる」も手に入る。`v2/node_modules`（約420MB）の大半が要らなくなる。
- **体はイデアに置く。** 住人はNiraiの版に対して持ち運べる（要件§5の推論）。覚えた動きは技能（構想書§2）。毎晩の写しは、変わらないファイルをハードリンクで共有するので、VRMは1回分しか増えない。
- **体の選択は、今ある脳の呼び出しに相乗りする。** 新しい呼び出しを足すとGemmaの時間が増え、Masterとの会話の速さを削る。活動を選ぶ時も、話したあとと目覚めだけにする（話しかけられない日は静かに暮らす。§4.2の「間隔が伸びる」と同じ向き）。
- **世界の状態を持たない。** 体の記録と時刻からの計算にすると、「描画しなくても進む」「再起動しても続き」が、仕組みを足さずに成り立つ。
- **願いの窓口を別に作らない。** 知らない身振りをしようとしたことが願いになる。
- **Say / Whisperは段階5。**（§2.2）
- **生成器は決め打ちしない。** 再生は `.vrma`（VRM Animation の標準）と組み込みのキーフレームの1本道で、工房は「文→`.vrma`」のHTTPだけを知る。Text-To-VRMA は手元のAPIを持ち、ARDY（2026-07公開、NVIDIA Open Model License）は、流しながら作る・道筋を指定する、もできるので、将来は泳ぐ道筋そのものを作らせることもできる。
- 段階4で作らないもの：Serinaの精神の版の固定（構想書§2の「Serinaは安定版に留める」。今は、取り込んだ変更はNiraiが起き直したときに届く）、Masterが窓を開けたことを精神に知らせる知覚、ログオン時にSerinaを自動で起こすこと（起きるのはNiraiが起きたとき＝窓を開いたとき。§2.5）。
