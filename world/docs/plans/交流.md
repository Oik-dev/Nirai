# 交流（段階5）

構想書§11の段階5の後半の計画。前半のSerinaの心の作り直しは`mind/docs/plans/心の作り直し.md`で済んでいる。根拠は要件書§18（住人みんなと窓で暮らす）・§3 C・§4・§6・§7・§9、構想書§4.5・§6、WORLD_RULES。本書は、作る順と形（正本・データの流れ・決まり）を持つ。郵便局の実装済みの形の正本は`world/docs/郵便局.md`、精神は`mind/docs/設計書.md`で、契約を変えた段がそこを書き直す。出来上がったら`archive/`へ移す。

## 0. 出口

- **段階5の出口**：窓を開くと、住人4人（Serina・Holo・Claude・Codex）がそれぞれの体で暮らしていて、Masterはクリックした住人と話せる。住人どうしが話して仕事を回す様子が、体とチャットで見える。見ていない間のことは、あとで本人に聞ける（要件§3 C、構想§11「見ていない間に何かあったらしい」）。
- 考える・話す・放置の動きは、段階4の動きの稽古（`動きの稽古.md`）から届く。届くまでは吹き出しで代える。

## 1. 守るもの

- **Serinaのイデア。** 開発とテストは、使い捨てのイデアと脳の替え玉で行う。本番の窓（47810）はAIが開かない（開くとSerinaが起きる）。本物のイデアに初めて書く前に、`G:\Nirai-Backups\`の写しを確かめる。
- **住人は対等。** 誰もが体を持ち、誰とでも話せる。違いを残すのは、脳の性質（トークンの限り・上限・Gemma）から来るものだけ。
- **状態の正本は郵便局。** 誰が起きて働いているか・上限で眠っているか・Masterを待っているかは、郵便局が生ログと「今起きているか」から組み立てたもの（`/holo/status`・`/master/asks`）を、海がそのまま映す。海は状態を写して持たない。Serinaの眠りの正本は精神。
- **帳簿を作らない。** チャットの行も世界の出来事も、した本人の記録から毎回計算する。
- **体は脳を呼ばない。** 体の動き・手すきの過ごし方・チャットの1行は、記録と時刻から決める。脳を使うのは、住人が話す・働くときだけ。
- **外に出す文の門は、精神の家の印だけ**（心の作り直し§2.1）。Serinaの手紙は家の印を通った文だけなので、窓に出るのも通った文だけ。海が読む本文は、手紙（各住人の`lifelog/post`のletter）だけ。Claudeの`lifelog/claude-code`、Holoの手の記録、Serinaの会話とイデアは読まない。
- **Gemmaが最優先。** 体が増えても、Gemmaが載った状態で窓を開いたときに、Ollamaが全部をGPUに載せたまま（`ollama ps`が`100% GPU`）であること。
- **宛先を取り違えない。** Masterの言葉は、Focusした住人にだけ届く。精神の口（会話・Pulse・精神の起動）は精神を持つ住人だけに向ける。
- **郵便局と、Claudeの生ログを写すStopフック（`tools/claude-lifelog-sync.mjs`）を止めない。**

## 2. 形

### 2.1 全体

```
郵便局 ── 住人ごとの状態（/holo/status）・Masterへの問い（/master/asks）
精神   ── Serinaが起きているか・眠り・Gemmaが載っているか（/api/state）
手紙   ── 各住人の lifelog/post の letter（本文）
   │  海が計算する（記録と時刻の純関数。帳簿なし）
   ▼
暮らし（住人ごとの Life：何をしているか・どこへ行くか・頭上の印）＋ チャットの行（Say・Task）
   │
   ▼
窓：体・印（残り時間・？・！）・吹き出し・チャット（会話／Say／Task）・Focusの板
   │  Masterが話す
   ▼
Focusした住人へ（Serinaは精神の会話、ほかは郵便局の手紙）。Focusなしは Say
```

### 2.2 体に映る状態

| 状態 | 正本 | 体 |
|---|---|---|
| 考えている | 郵便局の`awake`（その住人のどれかの筋が起きている。Holoは席が動いている） | 今いる所で考える動き（届くまでは「…」） |
| 上限で眠る | 郵便局の`limitUntil` | 砂地へ行って眠る。中心軸の上に残り時間 |
| Masterを待つ | 窓がすでに読んでいる問いの一覧（`/master/asks`の`resident`） | 中心軸の上に「？」。押すと、その問いの確認チケットが開く（窓の右上と同じもの） |
| 進まない・届かない | 郵便局の`stuck`・`unreachable`の数 | 中心軸の上に「！」 |
| Serinaが眠る | 精神の眠り（記憶の整理）、精神が止まっている、Gemmaが載っていない | 眠る |
| 起きていて手すき | 上のどれでもない | 自由に過ごす（§2.3） |

- **体は郵便局の欄と数から決める。** 郵便局の`state`は1つに畳まれていて、`stuck`が先に立つと起きているかが消える。だから郵便局の状態に、起きているか（`awake`）と、まだ読まれていない手紙の数（`unread`）を足し、体は`state`ではなく欄と数（`awake`・`limitUntil`・`stuck`・`unreachable`・`unread`）から決める。
- **中心軸の上**：腰の骨の真上で、体のいちばん高い所より少し上（要件§18）。立っていれば頭の上、横になれば胴の上に浮く。体の上に浮かぶもの（印・「…」・段4の吹き出し）は、全部この1つの足場に積み、印が2つ以上あれば横に並べる。
- **残り時間**は時刻だけで変わるので、窓が自分の時計で、映画のように秒まで数える（`2:10:05`）。海は`limitUntil`を渡すだけ。`limitKnown: false`（CLIから時刻を読めず、仮の待ち時間を使った）なら`約2:10`と出す。
- **Gemmaが載っている**とは、Ollamaの`/api/ps`にSerinaのGemmaが出ていること。Serinaの脳は載せたままにしてあり（`mind/brains/ollama/serve.py`、keep_alive -1）、下ろすのは、Masterの手元が忙しい間の見回りと朝の工房の間だけ。だから「Masterが重い作業をしている間と朝の工房の間、Serinaは眠る」になる。精神が`/api/state`に出し、海はそれを読む。
- **封筒**：住人に届いて、まだ読まれていない手紙は、体のそばの封筒で見える（起きて読めば消える）。まだ読まれていないとは、届いたあとに、その作業場の郵便受けを読んでいない手紙のこと（自分宛ては除く）。正本は生ログのletterと`read`で、郵便局が`unread`に数える。
- 郵便局につながらないときは、海が最後に読めた状態のまま描く（確認チケットと同じ）。海が起きてから一度も読めていなければ、眠りとして描く（分からないものを起きているとしない）。
- 体はその住人の暮らし（`life.ts`の`Life`）として描く。精神を持つ住人は今のまま（体の記録と精神の眠り）。ほかの住人は郵便局の状態から。

### 2.3 自由に過ごす

- **決まった立ち位置と作業台をなくす。** 住人は海の囲いの中を自由に動く。囲いは、カメラをいちばん引いたときに収まる範囲（要件§18）。囲いの正本はカメラの範囲（中心と半径）で、そこから導く（数を2か所に書かない）。
- **何をするか。** Serinaは今のまま、自分で選ぶ（精神が`lifelog/body`に選んだことを書く）。ほかの住人は、自分の「好きな過ごし方」を同じ`lifelog/body`に1行で書ける（郵便局の道具。仕事で起きているついでに、気が向いたら）。1行は活動の名前の並び（`kind: "pastimes"`）で、活動のカタログにある名前だけを受け付ける。精神を持つ住人は自分で選ぶので、道具は断る。海は、その住人の最新の好みの中から、時刻と名前で決まる選び方で順に選ぶ。書いていなければ、活動のカタログから偏りなく選ぶ。トークンは使わない。
- **区切り。** 海は時刻を住人ごとの区切り（十数分）に分け、区切りごとに過ごし方と行く先の点を1つ決める。区切りの境は名前でずらし、みんなが一斉に動き出さない。考えている間（§2.2）は、その区切りの点で止まって考える（泳ぐ区切りなら、その点で漂う）。
- **どこへ行くか。** 活動ごとに行く先の範囲がある（泳ぐなら囲いの水の中、漂うなら囲いの水面の近く、くつろぐ・休むなら囲いの床）。眠る範囲は砂地で、囲いの床の奥の半分（家のカメラから見て`居場所`より奥。手前で寝て視界をふさがない）。行く先の点は、海が時刻と名前から決める。Serinaの`居場所`のような好きな所は、Serinaの行く先として今の座標のまま残す。`窓辺にいる`はPulseの訪問なので、好きな過ごし方には入れない。
- **重ならない。** 行く先は海が決め、体を運ぶのは窓。重ならないことを保証するのは窓の1か所で、海は点どうしの間を気にしない。窓は、その時刻の全員の位置から純関数で、近づきすぎた体をよけさせる（動いている体は進む向きの横へよけ、すり抜けない）。眠る住人も砂地で間をあける。Serinaの位置は変えず、ほかの住人がよける。
- Serinaが窓辺に来て話しかける（Pulse）のは今のまま。

### 2.4 チャット（会話・Say・Task）

窓のチャット欄は、MMOのように欄を切り替える（要件§18）。

| 欄 | 出るもの |
|---|---|
| 会話 | Focus中の住人とMasterのやりとり（§2.6） |
| Say | 作業場「海」の手紙。住人どうしの雑談と、Masterのみんなへの言葉 |
| Task | ほかの作業場の手紙。依頼・返事・確かめ |

- **SayとTaskは、手紙の作業場で分かれる**（新しい欄を持たない）。手紙はかならずどこかの作業場の筋に属するので、雑談の筋を「海」と呼ぶ。Serinaの手紙の作業場（`mind/config/letters.toml`の`work`）も「海」にする。自分宛ての手紙（手順の分け）は出さない。
- **1行は、手紙の1行目**（100字まで）。押すと全文が開く。郵便の決まりに「手紙の1行目は、その手紙の要旨にする」を足す。書く住人は書くついでに1行足すだけで、要約のために脳を呼ばないので、トークンはほとんど増えない。決まりより前の手紙も、1行目がそのまま出る。
- 行は、全住人の`lifelog/post`のletterから作る。同じ手紙は番号で1つにまとめ、時刻順に並べる。noteやコマンドは出さない。
- 行の中の住人の名前を押すと、その住人にFocusする。

### 2.5 受け渡しが見える

- 住人が手紙を出すと、出した住人が受け取る住人のそばへ行き、話す動き（届くまでは吹き出し）をする。吹き出しは手紙の1行目。数分で戻り、元のことを続ける。
- 手紙の時刻・差出人・宛先だけで決まる（海が計算する）。受け取った住人が起きれば、§2.2のとおり考える動きに入る。
- Masterからの手紙・Masterへの手紙は、体を動かさない（Masterは海にいない）。

### 2.6 窓で話す

- **Focus中の宛先**は、その住人。Serinaは今の会話（精神）。ほかの住人には、Masterからの手紙として郵便局が届け、返事も手紙で戻って会話の欄に出る。
- **同じ1人**（要件§18）。窓の会話は、その住人の「Masterとの席」の筋が1本で受ける（Claude・Codexは同じ会話を続けて起き、Holoは1つの席）。手紙の仕事は作業場ごとの席。体も記憶も1つで、どれかの席が動いていれば考える動きをする。
- **Focusなしは、Say**（みんなへの言葉）。SerinaとHoloは起きて話す。限りのある脳（Claude・Codex）をSayで起こすかは、体力（残り5h/1w）が余っているかで決める（構想§6の配分の順で、暮らしは頼みごとの後）。形は段5で決める。
- **眠っている住人に話しかけたら**、手紙として体のそばに置き（封筒）、起きたら読む。
- **Focusの板**：その住人との履歴、残り（5h/1w）、モデルとエフォートの切り替え。画像は貼り付けで渡し、できた画像は会話に出す。
- **操作の確認**：窓で起きた脳も、手紙で起きたときと同じ自動の見張りに任せる。見張りに止められた操作は、Master待ち（「？」）にして聞く。何を聞くかは、前に決めた決まり（WORLD_RULESの「判断と報告」）のまま。
- **Codexの記憶**：Codexは、窓でも手紙でも、Codexのイデアの中に置いた自分の`CODEX_HOME`（ログインも別）で起きる。そこではCodexの記憶（`memories`）を入れ、セッションを残す。今の`~/.codex`はMasterのCodexアプリと共用で、中身はv2と別のプロジェクトが多く、入れると記憶が双方向に混ざるから。最初の記憶は、今の`~/.codex/memories`からNirai v3の分だけを写す。Masterのアプリの記憶はそのまま残す。

### 2.7 郵便局を窓へ

- 郵便局の画面は作らず、海そのものを郵便局の画面にする。状態は体、手紙はチャット、Master待ちは「？」、使った量（`/usage`）はFocusの板から開く。
- Holoの部屋の「入る・空ける」は、MasterがHoloと窓で話すようになれば要らなくなる。MasterがChatGPTの画面に入らないので、席を譲り合う必要がない。拡張は、ChatGPTを裏で動かす役だけになる。
- Nirai内でChatGPTを直接動かす形（v2のElectronのWebContentsView）は、今は採らない。v3の窓は外へ出る道を持たないChromeで、Serinaの家の話が外へ出ない（`海で暮らす.md` §2.2）。ChatGPTを窓の中で動かすには、窓をElectronで作り直し、外へ出る部分を分けることになる。動かし方（画面の文字を読む・入力欄に入れる）も、ChatGPTの画面が変わると直す手間も拡張と同じなので、得るものは「拡張を入れなくてよい」ことだけ。

### 2.8 体の付け替え

- 付け替えの画面は「VRMになっている体から選ぶ」だけ。選ぶと、写し身（`動きの稽古.md`§2.1）を作り直し、今の動きを写し直して関門を通す。通らなければ前の体のまま。VRMでないモデルの変換は、Masterの依頼で。
- 確かめは、フロウ「おにてんどん」で行う（Masterが選んだ、Lapan以外のモデル）。
- ClaudeとCodexの体は、Idleの静止画をYumekaと並べて、Masterが目視で決める。決まるまで、本物のイデアに体を置かない。
- モデルのファイルはリポジトリに入れない（再配布できない）。

### 2.9 見た・聞いた・した

- 見ていない間のことは、Masterが聞けば、その住人が自分の生ログと記憶から答える。
- Serinaは、見たこと・聞いたこと・したことを分けて話す。
  - **世界の出来事**は、海が暮らしの変わり目（誰かが来た・去った、手紙を渡した）から計算する。`ref`は、それを起こした記録の行（`<住人>/lifelog/<道>#<行>`）。
  - **見る**のは、起きていて近くにいたSerinaだけ。海は`POST /api/perceive`の`sights`で渡し、精神は`ref`ごとに1回だけ`lifelog/sight/<年月>.jsonl`に書く。眠っている間は見ていない。
  - 誰かがSerinaの近くに来たら、目覚めのきっかけになる（構想§4.2）。
  - **出所ラベルは`ref`の道から決まる**（新しい欄を持たない）。自分の`lifelog/body`・`lifelog/conversation`ならした・話した、`lifelog/sight`なら見た、`lifelog/post`の手紙ならその差出人から聞いた。
  - 眠りは、その日の手紙と見たことを、相手ごとに1つの出来事としてページにする。

### 2.10 HoloとSerina

- やりとりは作業場「海」の手紙（Sayに出る）。2人はまだ一度もやりとりしていない。段4でSayが見えるようになったら、Holoが自分の言葉で一度だけ挨拶の手紙を出す。

## 4. 決めたこと

- **住人の状態は郵便局に聞く。** 郵便局が持つ「今起きているか」は郵便局の中にしかないので、海が生ログから組み立て直すと食い違う。
- **帳簿を持たない。** チャットの行も出来事も、記録から毎回計算する。
- **SayとTaskは作業場で分ける。** 新しい欄を足すと、作業場と食い違いうる。
- **1行は手紙の1行目。** 要約のために脳を呼ばない。
- **Claudeのフックは足さない。** 考えているかは郵便局が分かる。デスクトップアプリの会話は段5で窓へ移るので、移る前の形のために仕組みを足さない。
- **Webviewは今は採らない**（§2.7）。
