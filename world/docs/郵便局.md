# 郵便局

郵便局（`world/post/`）の形。郵便局の考え方は構想書§6.1、安全の線は§8。住人への決まり（郵便の使い方、依頼状の書き方、誰が作り誰が確かめるか、何で止めるか）は`world/post/郵便の決まり.md`が正本で、本書には書かない。

Masterの入口はHoloの部屋（ChatGPT）。ClaudeのUIは、Niraiが止まったときに外から直す口と、管理者の権限が要る操作のために残す（Niraiが止まると、Niraiの中からは直せない）。

## 1. 部品は3つ

| 部品 | 動く場所 | すること |
|---|---|---|
| 郵便局（`world/post/`） | Masterのユーザーの、管理者に昇格しない権限（§8）。タスクスケジューラ「Nirai Post」が、Masterのログオン時に番人（`keeper.ts`）を起こし、番人が`--live`で郵便局と海を子として起こす。普通に止まったら1分後、確認済みの新版への入れ替わり（§7）ならすぐ起こし直す。記録は`world/runtime/post.log` | 手紙を受け取り、受取人の生ログに書く。住人を起こす。Holoの手（作業場のファイルとコマンド）。Holoへのトンネルを起こす |
| 拡張（`world/holo-extension/`） | MasterのChrome | 受付と作業場それぞれのHolo専用タブへ一言を送り、通信の始まり・終わりを部屋の筋付きで郵便局へ知らせる。中身は読まない |
| トンネル | Masterのユーザー | ChatGPTからの道具の呼び出しを、郵便局へ渡す。OpenAIの`tunnel-client`が、ローカルのHTTPのMCPを直接指す（`--mcp-server-url`）。ChatGPTの接続「Nirai」のトンネルは、郵便局の`/mcp/holo`を指す |

郵便局は、`127.0.0.1:47800`の1つのHTTPサーバー。住人ごとに入口を分け、受付は`/mcp/<住人>`、Codex/Claudeの作業場は`/mcp/<住人>/<URLエンコードした作業場>`を使う。Holoの入口は1つの`/mcp/holo`で、すべての道具に必須の`room`（`受付`または作業場名）を付けて筋を分ける。試すときは`--live`を付けず、使い捨ての置き場と別のポートで動かす（`NIRAI_RESIDENTS`・`NIRAI_WORK`・`NIRAI_PORT`）。

## 2. 住人ごとのつなぎ方

| 住人 | 起こし方 | 止まったと分かる時 |
|---|---|---|
| Holo | 拡張が受付または作業場の専用タブへ一言送る | その部屋の会話通信が終わった時 |
| Codex | 郵便局が`codex exec`を起動する | プロセスが終わった時 |
| Claude | 郵便局が`claude -p`を起動する | プロセスが終わった時 |
| Cursor | 住人ではない（イデアを持たない）。ほかの住人が作業場で`cursor-agent -p`を呼ぶ | — |

- **Claudeも郵便局から起こす（Master）。** Masterの在席を承認の代わりにしない（要件§14の承認を置かない）。Serinaを守る線は、ほかと同じくOSを壊せない権限と、バックアップとgit（構想書§8）。
- **利用上限は眠り。** Codex/Claudeが利用上限で止まったときは失敗回数には数えず、`stop: limit`と起きられる時刻を生ログへ残す。その時刻までは起こさず、頼んだ住人へ知らせる。時刻を読めなければ1時間後に再試行する。待つか代わりを頼むかは`郵便の決まり.md`。
- **CLIの筋は作業場ごと。** ClaudeとCodexは別々の作業場でそれぞれ最大2プロセスまで同時に起こす。作業場なしは受付筋。MCPの入口から読めるのはその筋の手紙だけで、ほかの筋の`note`と`done`は断る。返事でない手紙の`work`省略時は呼んだ筋を引き継ぐ。上限による眠りは住人全体に効く。
- **Holoも作業場ごとに別の部屋。** 受付の会話だけはMasterが初回登録し、作業場は初めて起こすときに自動作成する。同時に起こす部屋の上限は`settings.maxConcurrent.Holo`に従う。別の部屋への`mark_done`・`write_note`・`reply_to`は受け付けず、`work`省略の新しい手紙は呼び出し元の部屋を継ぐ。
- **起こしたClaudeは、Masterとのセッションと同じ住人として動く。** 家（カレントフォルダー）は`settings.repoRoot`のリポジトリで、CLAUDE.md・記憶（`Residents\Claude\memory`）・生ログの写し（Stopフック）が同じになる。見張りは、Masterとのセッションと同じ自動モード（`--permission-mode auto`）。つなぐのは郵便局だけ（`--strict-mcp-config`）。道具は手紙の仕事に要るものだけにし、技能の一覧も外す（`--tools`・`--disable-slash-commands`）。CLIの出力（`--output-format json`。終わり方・セッションの番号・使った量）は、Codexと同じく生ログの`claude-cli/`に残し、会話そのものは、いつものセッションの記録として`lifelog/claude-code/`に写る。
- **Masterとのセッションとぶつからない形は、仕組みを足さず、gitと決まりで作る。** 住人は本物の作業ツリーのファイルを編集せず、作業場の複製で仕上げる。取り込みはHoloが`world/post/land.ts`で行う（確かめた範囲だけを本物のmainの上へ載せ替え、テストを通して`git merge --ff-only`で入れてpushする）。gitは、まだ記録されていない変更を上書きしないし、ff-onlyは食い違いを作らないので、ぶつかれば取り込みのほうが止まる。Masterとのセッションでは、Claudeの郵便受けを読まない（CLAUDE.md。2人のClaudeが同じ手紙を扱わないため）。
- **Cursorを住人にしない理由。** 住人を増やすのはMasterの専権（要件§4）で、Cursorは自分で進める力が低い（要件§17）。道具として呼べば、郵便局に特別な扱いが要らない。住人にするかは、Masterがいつでも決められる。Cursorは2027年3月に解約予定。
- **Cursor CLIの呼び方（Master）。** Cursorを呼ぶ前に、テストを含む開始状態をコミットし、`git rev-parse HEAD`を基準点として控える。ふだんは毎回`grok-4.7-xhigh`を明示し、Autoは使わない。住人の上限時に代わりの実装・確かめへ回すときはOther枠も使う（`--list-models`で一覧を見直し、使える強いものを選ぶ）。実行は作業場の複製を`--workspace`にして、次の形で呼ぶ。

  ```powershell
  & "$env:LOCALAPPDATA\cursor-agent\cursor-agent.cmd" -p --force --trust --model grok-4.7-xhigh --workspace <作業場の複製> --output-format json "<頼むこと>"
  ```

  終わったら、`git status --short --untracked-files=all`で未コミット（未追跡・ステージ済みを含む）の変更を、`git diff --name-status <基準点> HEAD`でCursorが途中でコミットした変更を調べ、許した範囲の外がないことを確かめる。そのあと先に書いたテストを回す。範囲の外を変えていたら取り込まず戻す。

## 3. 道具

### 手紙の道具（MCP、全員共通の4つ）

| 道具 | すること |
|---|---|
| `send_letter` | 宛先・本文、必要なら作業場の名前と返事先の手紙を付けて出す |
| `read_mailbox` | まだ済んでいない手紙を、書き残しと一緒に読む |
| `write_note` | 手紙に、やったことや見つけたことを書き残す。切れても、次に起きた自分が続きから始められる |
| `mark_done` | 手紙に「済んだ」の印を付ける |

Holoの上記4つと`run`・`apply_patch`・`look`には、呼び出し元の部屋を示す`room`が必須。受付は`room:"受付"`、作業場の部屋は`room:"作業場名"`。実行対象の`work`と呼び出し元の`room`は別であり、手の生ログには`room`も刻む。

住人への決まり（`world/post/郵便の決まり.md`）と、イデアの`persona.md`の人格は、郵便局がMCPのサーバー説明として渡す。Claude Codeはサーバー説明を2,048字で切るので、起こしたClaudeには同じ全文を起こすたびにファイルへ書き、`--append-system-prompt-file`でsystemにも足す（`cli.ts`の`claudeCommand`）。ChatGPTは接続を更新したときの道具と説明を覚えたままなので、道具（`world/post/mcp.ts`）か決まりを変えたら、Masterが接続「Nirai」をRefreshする（頼む手順は`郵便の決まり.md`）。

### Holoの手

Holoだけは手を持たない脳なので、郵便局が手を貸す（`post/hands.ts`）。道具は、GPTが慣れているCodexの2つにそろえる。

| 道具 | すること |
|---|---|
| `run` | 作業場をカレントフォルダーにして、PowerShell 7のコマンドを実行する。読む・探す・一覧もこれで |
| `apply_patch` | Codexの形の差分（`*** Begin Patch`…）で、作業場のファイルを作る・書き換える・消す。差分の当て方はOpenAIの`applyDiff`（`@openai/agents-core`）。1か所でも当たらなければ、どのファイルも変えない。書いている途中で失敗したら、元に戻す。`@@`に書いた行がファイルになければ断る（`applyDiff`は進んでしまうが、本物のCodexは断る） |

- ChatGPTは道具の呼び出しを約60秒で打ち切るので、コマンドは45秒で返す。それより長いものは「続いている」と返し、終わったら結果を郵便局からの手紙で届ける。50分たっても終わらなければ止める。
- 手が届くのは、もうある作業場だけ。作業場は名前を付けた手紙を出すと作られるので、手は手紙のある仕事に結び付く。リンク（ジャンクションなど）は、たどった先が作業場の中かで確かめ、作業場そのものがリンクなら手は動かない。
- 作業場の名前は、大文字と小文字を区別しない（Windowsのフォルダーと同じ）。
- 手の記録や結果の手紙が書けなくても、郵便局は落ちない（郵便局の記録に残す）。
- やったことは、Holoの生ログ（`lifelog/hands/`）に残す。
- Holoがほかの接続（Masterの`local-files`など）を使わないのは、したことがHoloの生ログに残らず、ほかの住人も確かめられず、手紙に結び付かない作業場ができるため。ChatGPTでは接続を会話ごとに外せないので、決まりで使わない。権限はCodexと同じMasterのふつうの権限なので、安全の線（OSは壊せない）は変わらない。

## 4. 生ログでの形（帳簿を持たない）

手紙は、受取人のイデアの`lifelog/post/<日本時間の日付>.jsonl`に追記だけで書く。行の種類は`letters.ts`が正本。

| 種類 | 中身 |
|---|---|
| `letter` | 手紙の番号・時刻・差出人・宛先・本文・作業場・返事先・出所 |
| `note` | 書き残し |
| `done` | 済んだの印と一言 |
| `read` | 郵便受けを実際に読めた時刻と筋（任意の`work`）。MCPの`read_mailbox`が記録する |
| `wake` | 起こした時刻、その時に済んでいなかった手紙、CLIの作業場（任意） |
| `stop` | 止まった時刻、終わり方（正常・エラー・時間切れ・上限）、CLIの作業場（任意） |
| `tell` | 何度起こしても済まない手紙を、Masterに知らせた時刻と、知らせ方 |
| `room` | Holoの部屋の登録。`work`なしは受付、ありはその作業場の部屋（§6）。引っ越しは`move`印付き`letter` |

- 済んでいない手紙＝`done`のない`letter`。届き直した回数＝その筋で最後にどれかの手紙に`note`か`done`を書いてから、その手紙を含む`wake`のうち、次の`wake`か`stop`までに`read`があった回数（上限で止まった回は除く）。進行中の`read`は回数表示に入るが、Masterへの滞留通知を確定するのは、終了が確定した非上限の目覚め3回に達したときだけ。ほかの手紙を進めているあいだ、順番を待つ手紙は滞留に数えない。`tell`が効くのは、最後の`note`か`done`より後の滞留だけ。進捗が書かれたら以前の`tell`は効かなくなり、また3回読んでも進まなければ新しい`tell`を1回だけ出す。不通からの回復に使う`read`の事実は、終了が上限でも残す。
- 郵便局は、毎回生ログを全部読み直して決める（WORLD_RULESの「取りこぼしが残らない形」）。
- 段1のCLIは、`work`ごとの行を取り出してから進捗・休み・届き直しを数える。他の筋の`note`や`done`では数を戻さない。古い`work`なしの`wake`・`stop`は受付筋の行として読む。CLIの生出力は`<日付>.<筋のファイル鍵>.jsonl`（受付は`<日付>.reception.jsonl`）へ分ける。ファイル鍵は作業場名を小文字に正規化し、UTF-8の十六進が160文字以下ならそのまま、超える場合は`sha256-`に64桁のハッシュを続ける。Claudeの指示書も同じ鍵を使う。Codex使用量は日付と鍵で集計し、ハッシュ鍵の場合は生ログのwakeからその筋を確定する。確定できない場合は他の仕事へ推測配分しない。古い日付だけの記録も読む。

## 5. 起こす決まり（1つ）

**済んでいない手紙がある筋が起きていなければ、起こす。** 筋は住人と作業場の組。上限を超える場合は、その住人の最も古い未済手紙を持つ筋から起こす。Holoも受付と作業場の部屋ごとに起床・休み・通信を分け、上限は`settings.maxConcurrent.Holo`に従う。新しい手紙・止まった知らせで、すぐに見直す。ほかに1分ごとにも見直す。

数の決まり（`world/post/settings.ts`）：
- 止まってから1分は起こさない（すぐ落ちる脳で空回りしないため）。
- CLIは50分たっても終わらなければ止める（続きは次に起きてから。HoloがChatGPTで25分で切れるのと同じ扱い）。
- 郵便受けを読んでも進捗のない目覚めが3回に達した手紙は、差出人が自分でも他人でもMasterへ1回だけ滞留を知らせる。Holoの作業場の部屋と他住人の筋は受付Holoへ言付ける。受付自身だけは拡張アイコンの`!`で知らせ、言付けを連鎖させない。本文には筋・手紙番号・差出人・届き直し回数・最後の進捗日時・最後のnoteを含める。知らせたことは生ログの`tell`に残し、その滞留中はその依頼での自動起床を止める。同じ筋で`note`か`done`を書けば起床でき、新しい手紙が来ても起こされる。
- 最後の3つの目覚めが続けて郵便受けを読めなかった筋は「不通」とする。滞留の`tell`や言付けは出さず、前回の`wake`/`stop`から15分以上あけて再起床する。1回読めれば不通は解け、通常の間隔に戻る。状態に`unreachable`を出し、拡張アイコンは`!`で見せる。
- Holoの手のコマンドが動いている部屋は起こさず、結果の手紙が届いたら起こす。実行する作業場と返事を届ける部屋は異なることがあるので、返事先の筋で判断する。
- 郵便局につながらないときの拡張の印は`×`。

### 依頼と作業場

- 作業場は`D:\Products\Work\<名前>`。名前を付けた手紙が初めて届いた時に郵便局が作り、**その名前を付けた手紙が全部済み、中で動いているコマンド（Holoの手）もなく、いちばん新しいdoneから1回の目覚めの長さ（今は約50分）がたったら消す。** リポジトリの複製を中に作るのは住人自身。
- `reply_to`付きの返事は、`work`を省けば郵便局が元の手紙の作業場を引き継ぐ。返事そのものは元の手紙を済みにしないので、終わった手紙は本人が`mark_done`する。片付けは住人が起きているかではなく、生ログのdone時刻と時計、手のbusyだけで決める。これで郵便局を起こし直しても「済みにしてから返事」「確かめ直しの往復」の途中で作業場が消えない。

## 6. Holoの部屋の引っ越し

部屋の正本は、Holoの`lifelog/post/`にある、各筋の最後の`room`行（`{kind:"room", ts, url, work?}`）。`work`なしは受付、ありはその作業場。拡張はURLを持たず、`work→tabId`だけを覚える。部屋の長さは、その`room`行の時刻より後に同じ`room`からHoloの手が返した`lifelog/hands`の`output`の字数で数える（`settings.ts`の`holo.roomChars`）。Holoが暮らすProjectは`settings.ts`の`holo.projectId`だけを持ち、入口URLはそこから組み立てる。

状態は筋ごとの生ログだけから4つに決める。`room`がなければ**未登録**、最後の`room`より後に`move`がなければ**部屋あり**、`move`が未済なら**引っ越し中**、`move`が済んでその後に`room`がなければ**新部屋待ち**。受付が未登録なら自動起床しない。受付だけはMasterが拡張の「このタブを部屋にする」で登録する。作業場は未登録でも、初回の郵便の一言を送るときに新部屋を用意し、`room`行を記録する。部屋が片付いた作業場は同じ名前なら同じ最後の会話を再利用する。

長さが上限を超えるか、Masterが拡張の「今すぐ引っ越す」を押すと、郵便局がそのroomにつき1通だけ、`move`印付きの引っ越し手紙をHoloへ出す。Holoがその手紙ですることは`郵便の決まり.md`。

引っ越し手紙が済んだ**新部屋待ち**で、次にHoloを起こす必要があるときだけ、`/holo/next`が一言・対象の手紙・Project入口URLを返す。拡張は旧部屋タブを安全に入口へ切り替えるか、新しいタブを開く。新しい部屋では、確認済みの会話入力欄へだけ`@Nirai`を入れ、**その入力で新しく現れた候補の中だけ**を見る。名前が`Nirai`の候補が複数あるなど接続先を確実に見分けられないときは、どれも押さず入力を消して止まる。本文も確認済みの同じ入力欄へ入れ、そのフォームの送信ボタンだけを押す。送信操作まではMasterの操作を見張るが、送信後は画面遷移で入力欄が作り直されても失敗扱いにしない。入力が消えて送れたと確かめた時点で`wake`を生ログへ先に書き、同じ引っ越しでは二つ目の会話を作らない。その後、同じタブが同じProjectの`/g/<project>/c/<uuid>`になったら`room`を追記する。URLを確定できなければ自動は止まり、バッジに`!`を出して、Masterの手動の部屋登録（「このタブを新しい部屋にする」）を待つ。前の会話は消さない。

通常の起床でも、部屋タブが閉じていれば`/holo/next`が最後の`room`行のURLを返し、拡張が開き直す。だから拡張のstorageに`convId`やURLは残さない。前の部屋と新しい部屋が同じ未済手紙を同時に扱わないよう、新しい部屋を作るのは前の部屋が返事をしていないときだけにする。

`/holo/next`は1回に1部屋の`work`付きの一言を返し、部屋へは「ここは『作業場』の部屋」と伝えて`read_mailbox`の`room`指定を促す。拡張はその筋のタブだけへ送る。`net`と`room`の筋はそのタブの`work`で決めるが、`sent`では`work`を送らず、郵便局が対象の手紙の`work`から筋を決める。知らない手紙や、筋が異なる手紙の混在は拒否する。これにより古い拡張が`work`を送らなくても、作業場宛の`wake`が受付に紛れず、URL未確定の部屋を繰り返し作らない。作業場が片付いたら、そのタブを閉じるが会話は消さない。拡張のボタンは開いているタブが登録済みの部屋ならその部屋を操作し、違えば受付の登録をする。

専用タブの会話には、Masterも直接書いてよい。拡張は、Holoが返事をしている間と、入力欄に下書きがある間は一言を送らない。

Masterが話しかけた返事のあと10分間は、同じ部屋へ郵便の一言を送らない。郵便の一言への返事のあとには従来の1分間の休みを使う。Masterの番は起床だけに影響し、版の入れ替わりの手すき判定には影響しない。

## 7. 版の入れ替わり

郵便局・海・窓・Holo拡張のコードが変わったら、番人が確かめた版へ自分で入れ替わる。本物のリポジトリの場所は`settings.repoRoot`を正にし、server・keeper・Claudeの家はそこから決める。

- **版。** `{head,post,sea,window,lock,extension}`。headは環境から受け取り、各欄（`world/post/`・`world/sea/`・`world/window/`・`world/package-lock.json`・`world/holo-extension/`の中身）はGitから作り直す。post・sea・window・lock・extensionの中身が同じなら、文書だけのコミットでは入れ替わらない（窓も切らない）。拡張だけが変わっても番人は入れ替わり、`/holo/status`の`revision.extension`に新版が現れる。旧番人が引き継げるよう、`/holo/status`のhead/post/lockの名前と意味は変えない。
- **拡張の追従。** 拡張は`poll()`の頭、`/holo/next`で新たな一言を受け取る前に`/holo/status`の`revision.extension`を確かめる。初回に見た値は`chrome.storage.session`へ記録し、同じ版ならそのまま進む。違う版なら`chrome.runtime.reload()`で自身を読み直す。sessionは拡張の読み直しで消え、service workerの再起動では維持される。郵便局の入れ替わりは住人全員が手すきのときだけなので、一言を送ったあとに読み直して返事の`net`を落とすことはしない。
- **候補を作る。** 新版を見つけたら新しい起床を保留し（手紙は受け付ける）、Gitの確定コミットから固定候補を作る。候補は`git archive`でそのコミットの`world/`だけを取り出し、その候補自身の`package-lock.json`で`npm ci --prefer-offline`して、自分の`node_modules`を持つ。候補の親や本物の`node_modules`には頼らず、`.git`も持たない。候補の`revision.json`はheadを照合する。古い候補は、今動いている版と今作る版を除いて、候補準備の入口で片付ける。
- **試す。** 候補は本番が忙しい間にも、番人ごと`--live`なし・郵便局と海の別の空きポート・使い捨ての`NIRAI_RESIDENTS`/`NIRAI_WORK`/runtimeで起こし、候補自身の`/holo/status`と`/sea/status`が同じ版を返すことまで確かめる。起きない版には入れ替わらず、今の郵便局を動かしたままHoloへ1通だけ知らせ、起床を再開する。同じ拒否版は二度試さない。試したあとで本物のHEADがさらに進んでも、試した候補以外は起こさない。
- **手すき。** Codex/Claudeのすべての筋とHoloのすべての部屋が停止し、返事直後の休みも終わり、HTTP受付中でも海の中継中（`/sea/status`の`relaying`）でもないときだけ入れ替わる。海への問い合わせ（非同期）を済ませた直後、readyの直前に郵便局の手すきを同期で確かめ直す。海に接続できなければ中継なしとみなす。
- **入れ替わる。** 合格して全員の手が空いたら、海の起こし直し予約を取り消し、番人と海のIPCを切る。海は新しい接続を断り、返答の完了を最長3分待ってからSSEを閉じて終わる。上限後も止まらなければ海のpidだけを止める。精神へ終了を頼まず、海を木ごと止めない（精神を巻き込まない）。試した候補の番人をそのまま本番へ引き継ぎ、新番人が同じ固定候補の郵便局と海を起こしたことを確かめてから旧番人が終わる。失敗したら次の番人を止め、前のpostとseaを戻す。
- **海だけが落ちたとき。** 海は郵便局と別の子なので、郵便局は落ちない。海だけを1分後に起こし直す。
- PC起動時に最新の版がそもそも起きない場合の前版復帰は、段階6で扱う。

## 8. 安全

線は要件のとおり、「OSの破壊は実行できない仕組みにし、それ以外はバックアップから戻せればよい」（構想書P6）。先回りして固め、あとで例外を外して回る形にはしない（Master）。困ったことが起きたら、そのとき仕組みで防ぐ。

| 守るもの | 仕組み |
|---|---|
| OS | チームは、Masterのユーザーの管理者に昇格しない権限で動く。Windowsを変えるには管理者の確認（UAC）が要り、留守の間は誰も押さないので、OSは壊せない |
| イデア | 毎晩4時のバックアップ（`G:\Nirai-Backups\daily\`）と、大きな変更の前の丸ごとの写し（`G:\Nirai-Backups\serina\`） |
| コード | git。本物のリポジトリはGitHubへpushしている |
| バックアップそのもの | `G:\Nirai-Backups\daily`は、毎晩のバックアップのタスク（管理者の権限で動く）しか書けない。ほかに誰も書かない場所なので、例外は出ない。`tools/protect-backups.ps1`で、ふつうの権限では書けない・消せない・読めるようにしてある |

決まりで守ること（作業場の中でだけ変える、Serinaのイデアと開発の生ログを読まない、Holoは郵便局の手だけを使う）は`郵便の決まり.md`。

## 9. 置いた仮定と、まだ確かめていないこと

- 郵便局はNode.js（v24は`.ts`をそのまま動かせる）。MCPは公式のSDK。
- スマホのChatGPTアプリから、同じ会話で頼めるか（PCが起きていれば道具も動くか）は、まだ確かめていない（Masterの手が要る）。
- 郵便局が止まると（再起動など）、動いていたコマンドの結果の手紙は届かない。困ったら、手の生ログに始まりも書き、起きたときに知らせる。
