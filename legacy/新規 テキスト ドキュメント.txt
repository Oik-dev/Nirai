リフレクションの実行（ブロック2で詳述）。
出力結果（日記、ファクト、ステート）を長期記憶ストアへ正常にコミット完了する。

1.2 物理削除とメンテナンス
デバッグ期は、予期せぬパース失敗によるデータ消失を防ぐため、物理削除ではなく退避（Archive）を原則とする。
容量圧迫を防ぐため、以下の手動メンテナンスコマンドを提供する。
code
Bash
python manage.py purge-archive --older-than 30d
（30日以上前の退避アーカイブのみをDBから完全物理削除する）
1.3 最適化への議論の残し（※セッション1で詰める点）
「一律6時間経過」のみに頼ると、深夜の長時間の連続会話によるコンテキスト肥大化に対応できない。
追加の動的トリガー案:
未整理の履歴が「30ターン（または規定トークン数）」を超えたら、会話の途中でも裏で「部分リフレクション」を非同期実行して圧縮。
ユーザーからの入力が一定時間（例: 2時間）途絶えたタイミング、または「おやすみ」等のセッション終了ワードを検知したタイミングでの発火。
🗂 【ブロック2】 リフレクションのデータ形式とパーシング
2.1 蒸留エンジン（モデル仕様）
推奨モデル: ローカルの軽量な無検閲（Abliterated/脱検閲）Instructモデル（例：Qwen2.5-Instruct系 7Bクラス）。
理由: 親密な会話やセンシティブな話題がログに含まれていても、モデル側の安全ガイドラインによる「お説教」や「要約の拒絶」を防ぎ、中立な書記として正確なファクトと感情を抽出させるため。
2.2 出力フォーマット（XMLタグ形式）
12B以下のモデルでの構文エラーを防ぐため、JSONではなく、以下の構造化XMLタグを出力させる。
code
Xml
<diary>
(前回の会話における出来事、セリナ自身が感じた心の揺れ、マスターの様子の情緒的な要約。
※「何時何分に関数を実装した」等の細かなコマンドや日常の挨拶は無視し、「深夜まで複雑なバグの解決に奔走し、マスターは非常に疲れていたが、解決してホッとしていた」といった情緒文脈に圧縮して記録する)
</diary>

<new_facts>
- (新しく判明したマスターやセリナ自身に関する普遍的な事実。例：好物、予定、家族構成、ピーナッツアレルギー、嫌いな話題など)
</new_facts>

<state_update>
intimacy: (0.0〜1.0)
tension: (0.0〜1.0)
energy_level: (0.0〜1.0)
</state_update>
2.3 Python側のパーシング処理
JSONのように厳密な閉じ括弧のチェックを行わず、以下の正規表現（RegEx）を用いた前方一致による抽出（フォールバック）を実装する。
万が一、モデルが途中でトークン制限に達して </state_update> などの閉じタグを出力しきれなかった場合でも、タグの開始位置から前方にあるテキストを最大限救い出してパースする。
💾 【ブロック3】 二本立て記憶（情緒日記 vs 固定ファクト）と検索（RAG）
3.1 二本立て（ツートラック）構造
Track A：エピソード日記（ナラティブ/流れ）
役割: 「その日の空気感」「関係性の変化」「マスターの全体的な状態（疲労度など）」。
保存: ベクトルDBまたは日付順DBへ。
想起: 会話開始時、直近数日分の日記をシステムプロンプトに差し込む（例：「昨日は深夜まで大変そうでしたね」を自然に言えるようにする）。
Track B：ファクトブック（名詞/設定）
役割: アレルギー、住所、仕事、家族など、要約によって薄めてはいけない「固有名詞や事実（静的なプロファイル）」。
保存: シンプルなキー・バリュー形式（KVストアまたは静的ドキュメント）。
処理: 新しい事実が検出されたときだけ、その項目を直接追加・上書きする。

🧪 【ブロック5】 自動テストと検証手法
5.1 必須の自動アサーション項目
時間偽装トリガーテスト:
モックデータを使用し、セッションの最終タイムスタンプを「現在から7時間前」に偽装。
起動時判定関数を呼び出し、正しくリフレクションが True（実行対象）と判定されるかをテストする。
XMLパースおよびフォールバックテスト:
故意に </diary> や </state_update> などの閉じタグが欠落した破損XML（モック）をインプットする。
パーサーがクラッシュせず、前方一致正規表現によって日記テキストやステート数値を正確に救い出せるかをテストする。
状態遷移クランプ＆重力テスト:
AIが極端なステート値（例：親密さを前回の 0.5 から 0.9 へ急上昇させるなど）を提案してきた際、プログラムによるクランプフィルター（変動幅

履歴テーブル物理削除/退避テスト:
